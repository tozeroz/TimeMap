# 证据冲突：原版留言板表情行到底是 7 个还是 6 个？（未解决，待新只读 dump）

> 时间：2026-09-21 17:41（Asia/Shanghai）
> 起因：审核建议"回到原版只读观察去数表情入口数量"，我用现有两种证据去核，结果**互相矛盾**。

## 一、两份证据

### 证据 A：UI 控件树 dump（**强证据**）

来自 `docs/test/original-baseline/supplements/message-board.json`：

```
"id/rvEmojiList + id/fl_emoji_root ×7  表情行（**恰好 7 个**）"
"fact":     "表情行恰好 7 个表情"
"evidence": "id/rvEmojiList 下 id/fl_emoji_root 出现 7 次（间距 112px）"
```

强度：**strong**（控件 id + 计数 + 间距，属语义级证据）。

### 证据 B：截图 + 视觉读取（**弱证据**）

`docs/test/original-baseline/screens/message-board/normal.png`（51933 字节，仓库里唯一的该页产物），
用视觉模型读数：

> 1. 😂  2. 👑  3. 💛  4. 👀  5. 😱  6. +1（不是普通 emoji，更像"+1"快捷按钮）
> **如果只算 emoji 是 5 个；把最后的"+1"按钮也算作这一行图标则共 6 个。**
> 这一行看起来**没有被截断**：右侧还有明显留白，没有露出半个表情或滚动提示。

强度：**weak / auxiliary**（截图读数会受分辨率、缩放、图标字体差异影响；
且视觉模型可能数错或误判"未截断"）。

## 二、冲突点（不只是数量，还有字符）

| 项 | 证据 A（dump） | 证据 B（截图） |
|---|---|---|
| 数量 | 7 | 6（其中 5 个是 emoji、1 个是 "+1"） |
| 第 3 个 | 未记录字符 | **💛**（而我们的 mock 写的是 **❤️**） |
| 是否被截断 | 不适用 | 判断为"未截断" |

## 三、我的处置：**不选边，也不改动现有实现**

1. **不改** `boardEmojis` 的 7 —— 上一轮我按证据 A（dump，strong）改成 7。
   现在有了冲突，**既不升级为确定、也不回退到 6**，保持 7 并标注"存在冲突"。
   （回退会掩盖问题；升级会过度声明。）
2. **不声称字符一致** —— 这一点在代码注释里已经写明："具体字符没有证据"。
   现在更进一步：连**数量**都有冲突，所以注释要更新为"数量存在证据冲突"。
3. **记录冲突本身** —— 两份证据不一致时，正确做法是补证据，不是挑一个信。

## 四、为什么这可能不是"谁对谁错"，而是观测条件不同

几个合理假设（都需要新证据才能区分，**现在不下结论**）：

- `fl_emoji_root` 可能既用于表情项、也用于某个容器/末位"+1"按钮，
  于是 dump 计到 7 而可见项是 6
- 截图可能是**某个版本/某个状态**（例如未登录、或话题为空）下的渲染
- 截图分辨率下 💛 与 ❤️ 难以区分，第 3 项可能是误读
- 第 7 项可能在**屏幕外**（横向可滚动的表情行），而视觉模型判断"未截断"本身也可能出错

## 五、解决路径（下一步，只读）

**做一次新的只读观察，直接 dump 该页控件树，并保存原始 xml 到仓库**（现有 baseline 只有摘要，
原始 dump 没入库 —— 这正是"证据不可复核"的根源）。

断言口径：
- `id/rvEmojiList` 下**直接子节点**里 `fl_emoji_root` 的个数与**每个节点的 bounds**
  （bounds 能同时回答"几个"和"是否在屏幕外"）
- 每个节点的 `content-desc` / `text`（回答"具体是哪几个字符"）
- 若某字段为空，就如实记 `NOT_CAPTURED`，**不推断**

**本次观察前必须先确认**：是否需要在未登录状态下导航（避免误触写操作）。
当前登录状态与页面可达性都要先记录，否则又是一次"条件不明的观测"。
