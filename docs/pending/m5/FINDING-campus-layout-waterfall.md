## 二、决定性证据：**读 bounds，不读控件名**

该页所有 `view_image_container` 的 bounds（设备 px，屏宽 1080）：

| 位置 | bounds | 宽 × 高 |
|---|---|---|
| 右列 | `x=[571,1042] y=[270,769]` | 471 × **499** |
| 左列 | `x=[41,506]   y=[285,905]` | 465 × **620** |
| 右列 | `x=[589,1024] y=[863,1445]` | 435 × **582** |
| 左列 | `x=[55,492]   y=[1007,1447]` | 437 × **440** |
| 左列 | `x=[18,529]   y=[1533,1920]` | 511 × **387** |
| 右列 | `x=[561,1052] y=[1560,1920]` | 491 × **360** |

关键几何特征：
```
① 只有**两个** x 区间：左 ≈ [18..55, 492..529]，右 ≈ [561..589, 1024..1052]
   → 双列
② 高度**各不相等**：499 / 620 / 582 / 440 / 387 / 360
   → 不是等高网格（等高网格是 collage/宫格的判据）
③ y 位置**交错**：左列 y=285/1007/1533，右列 y=270/863/1560
   → 两列各自推进、互不对齐 = **瀑布流（masonry）**的典型形态
```

`view_image_container` 外还各有一层 `view_image_bg`（底色）与 `view_image_stroke`（描边），
三层 bounds 几乎重合（如 `[41,506][285,905]` / `[41,506][285,905]` / `[41,506][285,905]`）——
说明每张卡片 = 背景 + 描边 + 内容三层叠加，**不是拼贴的自由摆位**。

## 三、结论

```
ORIGINAL_CAMPUS_PLAZA_LAYOUT: **两列瀑布流（two-column waterfall / masonry）**
  判据: 双列固定 x 区间 + 高度不等 + y 交错（见上表）
OURS:                        column-count:2 瀑布流
→ **一致。A-D-LIST §2 里"原版是拼贴照片墙、我方是瀑布流"这条差异【不成立】。**
```

## 四、根因：**第 4 次栽在同一个坑上**

`A-D-LIST` 之所以判成"拼贴照片墙"，唯一依据是**控件名** `collageView`。

而本项目此前已**三次**因"把标识符名当行为契约"而得出错误结论：

| 次数 | 误判 | 依据的名字 | 实际 |
|---|---|---|---|
| 1 | C1 以为关闭按钮有某行为 | `ivClose` | 名字 ≠ 行为 |
| 2 | C2 以为有评论总数语义 | `tvTotalComment` | 名字 ≠ 行为 |
| 3 | C4 曾据 id 名判"表情是图片"又反悔 | `emotion_image` | 名字 ≠ 绑定关系 |
| **4（本次）** | **判成"拼贴照片墙"** | **`collageView`** | **实际是两列瀑布流** |

→ 现实是：`collageView` 只是**外层容器**的类名（它的 bounds 是 `[0,1080][0,1920]`，**全屏**），
   真正的排布在它内部，**必须靠 bounds 才能判**。

**纪律（第 4 次重申，建议升级为硬规则）**：
```
❌ 不得用 resource-id / 控件类名推断**布局、数量、层级或行为**
✅ 布局类结论必须给出**几何证据**（bounds/尺寸/坐标）
   —— 与既有纪律 "引用了 raw_evidence ≠ 读了 raw_evidence" 是同一族的两次教训
```
