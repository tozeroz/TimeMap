> 时间：2026-09-21 20:52｜方法：对已入库的原版截图做视觉读图（**线索级**证据，但足以支撑"预期"）

## 一、发现：`10-message.png` **不是**会话列表，而是「更多同学」推荐页

对 `docs/test/original-baseline/screens/original-sweep/10-message.png` 读图，结果：

```
会话条目数：**0 个**
页面内容：  顶部系统邀请类文案「分享我的校园卡」「邀请同学一起加入 Campus!」「邀请同学」
            + 7 个推荐条目，形如：

              （共 7 个，最后一个「禾桉涵」被底部截断）
未读红点 / 时间戳：**没有**
```

**即：这一页是"邀请同学/更多同学推荐"，没有会话条目、也没有任何消息预览。**

## 二、这纠正了一个误读风险

`docs/test/comparison.md:90` 写的是：

> 聊天列表 | 原版截图 + vision 逐字 | ✅ 「分享我的校园卡」「邀请同学一起加入 Campus!」
> 「邀请同学」+「更多同学」列表（昵称/相同学校/学院-专业/年级）一致

**这段描述其实与读图结果一致** —— 它列的就是**邀请文案 + 更多同学列表**。
但**文件名 `10-message.png` 会让人以为它是"带消息预览的会话列表"**。

→ **纠正**：该图应理解为"**消息/邀请页（含更多同学推荐）**"，
   **不能**用它支持任何关于"会话列表条目/消息预览"的结论。

## 三、对在飞的观察任务的预判（重要）

由上述两点可推：

```
原版账号**没有**任何"已有真实消息的会话"的证据 ——
   · 唯一见过的"消息"类是 10-message.png（实为邀请/推荐页，0 个会话条目）
   · 11-chat.png 是**空**单聊页（无气泡）
因此：子代理 659cfcd8 很可能**找不到非空会话**
     → 结果大概率是 **BLOCKED_BY_POLICY**（造消息＝写操作＝禁止）
```

**这不是坏结果**：用户的硬约束要求"凡是必须做写操作才能拿到证据的场景，
一律记为 BLOCKED_BY_POLICY，不得执行、不得绕道，并如实写进报告与 Gate 判定"。
**BLOCKED_BY_POLICY 是合规的终态，不是失败。**

## 四、若真落到 BLOCKED_BY_POLICY，`CHAT_MESSAGE_SENDER_PRESENTATION` 应如何收口

按 A/D 账本预先定的裁定规则：

```
原版区分左右 → 偏差成立，接线级修复（senderId + .bubble--me 都已存在）
原版不区分   → 撤销该偏差
**控件树不足以判定 / 无法取证 → 保持 UNRESOLVED**
```

→ 若因原版无会话而无法取证，则该偏差应记为：

```
CHAT_MESSAGE_SENDER_PRESENTATION: UNRESOLVED
  reason: BLOCKED_BY_POLICY（原版账号无可观察的非空会话；
          造消息需写操作，用户硬约束禁止）
  implementation_impact: FREEZE（不得据此修改我们的实现）
```

**关键**：**不得**因为"观察不到"就把它当作"不是偏差"而撤销 ——
撤销需要"原版不区分"的**正面证据**，而"看不到"不是那种证据。
这与 C4 的处理口径一致（C4 也是 UNRESOLVED + FREEZE，而非撤销）。
