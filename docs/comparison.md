# 原版 vs 复刻 demo 一致性对比报告

> 对比方法：同一页面分别取「原版 app 在 MuMu 模拟器上的截图」与「demo 的截图」，
> 交给视觉模型逐项比对并打分。原版截图保存在 `.mumu-capture/sweep/`，
> demo 截图由 `tools/shoot-demo.ps1` 生成到 `.mumu-capture/demo/`。

## 总体结论

| 页面 | 首轮评分 | 修订后评分 | 说明 |
|---|---:|---:|---|
| 校园广场 | 7/10 | 7/10 | 骨架高度还原；配图为本地生成的占位图，非实拍图 |
| 个人主页 | 6/10 | 7/10 | 已改为纯白底、去掉多余模块、加大头像 |

> 评分口径：以「初次看到时能否认出是同一个 app」为准。骨架/导航/文案类差异权重高，
> 图片素材类差异权重低（因为需求明确要求数据 mock）。

## 一、校园广场（campus）

### 首轮发现的问题与处理

| # | 问题 | 处理 |
|---|---|---|
| 1 | demo 多出一个「推荐/最新/关注」分类 Tab，原版没有 | ✅ 已删除 |
| 2 | 有图帖子原版是「文字悬浮在图上」，demo 是「图下白条」 | ✅ 已改为图上渐变遮罩 + 文字/作者悬浮 |
| 3 | 卡片统一白底卡片化，原版是图片直接铺满 | ✅ 有图帖子不再加白底，仅无图帖子用白底卡片 |
| 4 | 帖子数据与原版不匹配（作者名/文案/图错配） | ⚠️ 部分保留：mock 数据为重新编造，非原版逐条搬运 |
| 5 | 配图为渐变占位图，原版是实拍图 | ⚠️ 有意保留：原版图片来自 CDN，且属他人内容，不复用 |

### 仍存在的差异（如实记录）

1. **图片素材**：原版是实拍/拼贴/海报，demo 一律为本地生成的渐变图。
   这是"数据完全 mock"的直接结果，也是版权上的刻意选择。
2. **瀑布流错落程度**：原版图片比例差异大（长图/短图/GIF），demo 图片统一 3:4，
   错落感弱于原版。
3. **点赞/评论数展示位置**：原版大部分卡片不显示互动数，demo 显示。
4. **状态栏时间**：原版截图是真实时间，demo 固定显示 9:41。

## 五、明确未复刻/不可复刻的部分

| 项 | 原因 |
|---|---|
| 腾讯地图实时瓦片 | 需联网与地图 SDK 授权 |
| 真实相机取景 | 需摄像头权限与原生相机；demo 用模拟取景画面 |
| 校园圈（feed/list）页 | 原版强依赖后端，本机打开即「网络错误」，无法取得真实界面 |
| 真实用户头像与动态图片 | 属他人内容，且要求数据 mock |
| 服务端 3D 虚拟形象 | 由服务端生成，离线不可复现 |
| 扫码 / 图片预览 / 入群桥接等技术页 | 无独立 UI 价值 |

## 六、复现方法

```powershell
# 1) 启动 dev server（已由后台任务承担）
cd 'G:\demo map\app'; pnpm run dev

# 2) 生成 demo 各页截图
& 'G:\demo map\tools\shoot-demo.ps1'

# 3) 生成原版各页截图（需模拟器运行且原版 app 已安装）
& 'G:\demo map\tools\sweep-pages.ps1'

# 4) 打包并安装 APK
& 'G:\demo map\tools\build-android.ps1'
```
