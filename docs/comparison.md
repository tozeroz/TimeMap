# 原版 vs 复刻 demo 一致性对比报告

> 对比方法：同一页面分别取「原版 app 在 MuMu 模拟器上的截图」与「demo 的截图」，
> 交给视觉模型逐项比对并打分。原版截图保存在 `.mumu-capture/sweep/`，
> demo 截图由 `tools/shoot-demo.ps1` 生成到 `.mumu-capture/demo/`。

## 总体结论

| 页面 | 首轮 | 修订后 | 说明 |
|---|---:|---:|---|
| 校园广场 | 7/10 → 6/10 | **7/10** | 骨架、导航、瀑布流还原；配图为本地生成的抽象图，非实拍 |
| 个人主页 | 6/10 | **7/10** | 已改为纯白底、去掉多余模块、加大头像、图标加白底阴影 |
| 地图页 | — | **7/10** | 结构与文案一致；底图不可能离线复刻 |
| 其余 19 个页面 | — | 结构对齐 | 走查通过，未逐张打分 |

> 评分口径：以「初次看到时能否认出是同一个 app」为准。骨架/导航/文案类差异权重高，
> 图片素材类差异权重低（需求明确要求数据 mock、且不联网）。
> 三次评分波动 ±1 属正常，关键看**差异项是否收敛**。

### 第 2 轮：6/10，发现新问题

| # | 问题 | 处理 |
|---|---|---|
| 1 | 视觉模型把配图上的文字读成「分类标签」 | ✅ 占位图不再写字，改为抽象渐变+光斑 |

### 第 3 轮：7/10，差异项已收敛

仍存在的差异（**属于设计取舍，不再继续迭代**）：

1. **配图素材**：原版是实拍照片 / 拼图 / 截图；demo 一律是本地生成的抽象渐变图。
   这是「数据完全 mock + 纯本地不联网 + 不复用他人图片」三条要求共同决定的，无法消除。
2. **作者信息位置**：原版部分卡片把头像昵称放在卡片外上方；demo 统一用图片顶部的半透明胶囊。
3. **蒙层与点赞样式**：原版是黑底/透明底混用，demo 统一为底部深色渐变。

## 六、设备端验收（真机，非浏览器）

浏览器截图用于快速迭代；**最终验收在真实 APK 上做**，方法与结果见
[`docs/device-walkthrough.md`](./device-walkthrough.md)。

- 手段：通过 `adb forward` + Chrome DevTools Protocol 连进 APK 的 WebView，
  执行真实 DOM 点击并断言路由/DOM，避免模拟器旋转导致的坐标换算误差。
- 结果：17 项交互步骤全部通过；22 个页面在设备上逐页截图（`.mumu-capture/device/`）。
- 过程中发现并修复 3 个只在真机上才暴露的问题：
  1. 应用被渲染成屏幕中间一条竖条（手机壳样式在 1920 宽视口被误触发）→ 竖屏锁定 + `pointer: fine` 约束
  2. 双状态栏（系统状态栏 + 应用自绘模拟状态栏）→ 原生壳下不渲染模拟状态栏
  3. PowerShell `$pid` 只读变量导致调试通道建错

## 七、复现验证的方法

```powershell
# 1) dev server（后台任务）
cd 'G:\demo map\app'; pnpm run dev

# 2) demo 全路由截图（22 个页面）
& 'G:\demo map\tools\shoot-demo.ps1'

# 3) 原版全路由截图（需模拟器运行且原版 app 已安装）
& 'G:\demo map\tools\sweep-pages.ps1'

# 4) 打包 + 安装 APK
& 'G:\demo map\tools\build-android.ps1'
```

### 踩过的坑（避免重犯）

1. **Vite dev server 会提供过期的文件转换缓存**：改完源码后某些路由可能仍渲染旧代码
   （症状：新页面白屏、或新路由不生效）。验证时给请求加 `?probe=<时间戳>` 可确认，
   或直接重启 dev server。**构建产物（dist/APK）不受影响。**
2. 截图文件名不能带路由 query 里的 `?` `&`，脚本里要清洗。
3. 深色页面（扫码/图片预览）必须覆盖状态栏与顶栏配色，
   否则 `.topbar--plain .iconbtn` 的白色底托 + 白色图标 = 图标看不见。
