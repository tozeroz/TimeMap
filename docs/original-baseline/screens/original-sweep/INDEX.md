## 三、⚠️ 一条已知不可靠的旧结论（入库**不等于**它成立）

`docs/comparison.md:87` 曾写：

> 留言板 … **表情行 `😂👑❤️👀😱+1` … 全部一致**

**这条已被证明不可靠**，理由有二（详见 `docs/m5/FINDING-board-emojis.md`、`docs/m5/C4-EVIDENCE-CONFLICT.md`）：

1. **控件树里根本没有 emoji 字符文本**（`text` 仅 4 条中文，`content-desc` 全空）→ dump 无法读出字符
2. **两次视觉读数不一致**（第 2 项一次 🤩、一次 👑）→ 截图读数属**弱证据**

**且它有前科**：我据一条**不可复算**的记录把实现从 6 个表情改成了 7 个，
后来用可复核 dump 复算才发现原版是 **6** 个。

→ **因此：`05-board.png` 这张图不能用来支持任何关于"表情行字符"的结论。**
   现行冻结口径是 `ORIGINAL_EMOJI_CHARACTERS: NOT_CAPTURED`，
   视觉候选 `😂 / 🤩? / 💛? / 👀 / 😱 / +1` 标为 **WEAK**。

## 四、使用这些图时的纪律

1. **截图是"线索"级证据，不是"证据"级** —— 它的强度低于控件树 dump
   （dump 给出 id/bounds/文字，截图只给像素）
2. 引用某张图时，**必须同时说明它支持到什么程度**（例如"11-chat.png 只支持输入框文案，
   不支持气泡排布"）
3. **凡"数量/字符/行为"类结论，不得仅凭截图** —— 那需要 dump 或可复算产物
4. 若将来要用截图支持新结论，应把**结论、图、以及"为什么只能支持到这一步"一起写**
   （本文件就是范例）
