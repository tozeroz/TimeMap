### 为什么单列这一节

本项目的教训反复指向同一件事：**"看起来完成"与"已验证"之间的缝隙**才是问题藏身处。
- 改 CSS 后没重装就以为生效过（后来补验才发现需要重装）
- 断言写错却间歇性通过（flaky）
- 部署旧产物却以为验的是新代码（三次）

G1 正是这一类：**我为了让脚本更合规而改了它，但没验证改完之后它还能工作**。
把它显式列出来，是为了不让它变成"完成度看起来 100%、实际有洞"的那一类。
