## 二、我此前错在哪

我在登记 deviation 时写的是：

> 原版底部 tab 是 **4 项**（校园广场 / <账号昵称> / 校园 / 地图），我们只有 3 项

**这个结论是这样得出的**：我在 dump 里看到 4 个像 tab 名字的文字，就认定它们是 4 个底部 tab。
**我没有检查它们的 bounds。**

而实际上：
- `校园广场` 是**顶部栏目/页面标题**（视觉读图 `01-trident.png` 也印证：
  顶部大字 "Campus"，其下是「校园广场」**带下拉箭头**，像栏目选择器）
- 底部**只有 3 个文字 tab**：自定义名称6 / 校园 / 地图

**→ 原版底部 tab 数 = 3，与我们的 3 个一致。**
**"4 vs 3"这条 deviation 不成立，应撤销。**

## 三、这是同一错误类型的**第四次**

| # | 我犯的错 | 性质 |
|---|---|---|
| 1 | 把 `ivClose` 当成"关闭按钮"（实为容器内图标） | 照 `resource-id` 名字推断 |
| 2 | 把 `tvTotalComment` 当成"总数"（实为标题） | 照 `resource-id` 名字推断 |
| 3 | 把 `emotion_image` 当成"位图素材"（未证明） | 照 `resource-id` 名字推断 |
| **4** | **把 4 个文字当成 4 个底部 tab（实为 3+1 顶部标签）** | **只数节点、不看坐标** |

**共同点**：**用"名字/数量"代替"结构"**。
本次的新变体是：**数量也是一种"名字级"的浅层特征** ——
数到 4 个 tab 名字，就以为有 4 个 tab，而**位置（bounds）才是区分"顶部标签"与"底部 tab"的关键**。

→ 应并入纪律：**凡涉及"有几个 / 在哪一类"的结论，必须看 bounds / 层级，不能只数名字。**

## 四、更正后的实际情况（并派生一条**新的** deviation 候选）

```
原版底部导航：3 个文字 tab（自定义名称6 / 校园 / 地图）
             + 右侧一个**黑色圆形 + 按钮**（发布入口，非 tab；视觉读图 01-trident.png 见到）
原版 校园广场：**顶部栏目**（「Campus」大字 + 其下「校园广场」带下拉箭头），
             内容为**两列瀑布流拼贴**，每张卡片带头像 + 作者昵称
             （昵称样本：蒸柿煮柿呆 / 云云 / an moss×2 / 肆季 / Iemy(或 lemy)）
             帖子文字样本：「草头娃娃，听说浇水能长草，让我来试试～」
```

**因此：**
1. **撤销**原 deviation 的"底部 tab 4 vs 3"部分

   它现在有**两张独立证据**支持（dump 的 `collageView`/`view_user_tag` + 截图的两列瀑布流与昵称标签）
