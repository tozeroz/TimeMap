# M5 留言板设备端验证状态

M5 留言板设备端：四次注入尝试结论明确——React 受控 state 无法被合成输入更新（下一步改用"点表情"）

【决定性数据（查 Nginx 访问日志）】
四次尝试，每次点击「留言」都发出 POST，且**每次都回 400 bad_body（响应体 20 字节）**：
  16:49:50  400   （原生 setter + input 事件）
  16:50:30  400   （Input.insertText）
  16:50:58  400   （insertText，复跑）
  16:52:32  400   （逐字符 keyDown/char/keyUp）
其中最后一轮**输入框的 value 与期望完全一致**，POST 仍是 400 ——
即 DOM 值对了，但 React 的受控 state 没有更新（受控输入会在下次渲染时回退 DOM 值，
我读 value 的时机恰在回退之前，所以看起来是对的）。

【结论】
- **产品无责**：服务端对"空正文"回 400 是**正确行为**（与 verify-board-notes.sh 的 B4 组一致），
  且四次都能收到请求（点击链路是通的）。
- 瓶颈在**我们的合成输入手段**：四种方式都无法让 React 19 在这个 Capacitor WebView 里
  接受合成文本。这是测试 harness 的限制，不是产品缺陷。

【下一步（有明确依据的方案，不是再试一次）】
**用"点表情"产生正文**：表情按钮的 onClick 是 **React 自己调用**的
`setDraft(prev => prev + emoji)` —— 只要用真实触摸点一下表情，
state 里就有了真实文本，**完全不依赖任何注入**。
然后再点「留言」→ 应该得到 201 与便签。
这个方案的好处：既绕开 harness 限制，又**没有为了让测试通过而改动产品代码**
（给输入框加 test-only 入口那种做法是产品为测试让路，方向反了）。

【纪律记录（第五次）】
"输入框 value 正确但 POST 400" 这个组合是**关键区分信号**：
它把"UI 显示"与"组件状态"分开了，也把"产品拒绝空正文"与"产品写不进去"分开了。
只看界面会得出"输入框正常"，只看 400 会得出"接口有问题"，两者都不对。
