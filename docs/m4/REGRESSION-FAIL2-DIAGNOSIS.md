M4 Final regression 的 FAIL 2 定位：详情页加了图片区把评论列表下推，测试点击落空

【现象（单独跑 scripts/m3/device-slice1.mjs composer 的完整输出）】
  FAIL 回复弹层没有「回复 @昵称」标题（实际: anmoss 9月1日 · 北京交通大学 而我不再觉得… 回复 2 2）
  FAIL 回复输入框占位是 'null'
  SLICE1_COMPOSER_RESULT FAIL

即：用例点了"回复"按钮，但**回复弹层没有出现**，页面仍停在详情页
（页面文字未变，最后还能看到点赞/评论计数「回复 2 2」）。

【根因判断（高置信，但尚未用日志/截图最终确认）】
M4 给帖子详情页新增了图片区（`.feed__media`）—— **它把评论列表整体往下推**。
composer 用例通过 `getBoundingClientRect()` 取"第一个回复按钮"的中心点再合成触摸事件；
页面变长后该按钮可能落到**视口之外**，于是合成触摸点落在可视区之外，点击自然无效。
所以弹层没打开、后续断言（弹层标题、输入框占位）全部连锁失败。

【性质判断】
- **不是产品缺陷**：回复功能本身没坏（详情页正常渲染、评论与回复都在）。
- 也不是"因为加了图片所以功能坏了" —— 而是**测试没有把目标滚进视口**。
- 但**触发条件是 M4 的产品改动**（页面变长），所以它属于"改动暴露了既有的测试脆弱性"。
- 分类：GATE_DEFECT（测试侧），不是 PRODUCT_DEFECT。

【修法（下一步）】
device 驱动在点击前**先把目标滚动进视口**（`el.scrollIntoView({block:'center'})` 并等待一帧），
再取中心点合成触摸。这条应当**在所有 device 驱动里统一**——
本项目已经因为"用坐标点元素"踩过多次坑（tab 栏、回复按钮、发布按钮），
统一加一个 `tapSelector`（滚动 → 定位 → 点击 → 校验副作用）比逐个修更可靠。

【为什么先不改产品】
1. 产品行为本身正确（图片区在详情页是应该有的，原版详情也有图）；
2. 若为了迁就测试而调整页面结构，等于让产品为测试让路 —— 方向反了；
3. 先把"测试必须滚动进视口"这条加上，再看 composer 是否恢复。

FAIL 1（迁移数硬编码 5）已改为派生断言（applied == expected 且 > 0）。
