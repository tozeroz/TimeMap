# 地图地点抽屉与简介页实施记录

日期：2026-11-03　分支：zhenzhen（未提交）
依据：`.agents/tasks/place-sheet-ui/spec.md`、`design.md`（第三版）、`design-review.md`（第三轮）。

## 路由

| 地址 | 说明 |
| --- | --- |
| `#/map?placeId=<id>&sheet=preview\|expanded` | 地图上打开地点抽屉。打开时推入一条带 `tmSheet` 标记的历史，档位变化和切换地点用 replaceState |
| `#/place-intro?id=<id>` | 新增的地点简介页；`&photo=cover\|<n>` 表示照片查看器打开 |
| `#/publish?placeId=<id>&from=sheet` | 进入发布页并预选该地点；关闭后回到原抽屉 |
| `#/poidetail?id=<id>` | 保留，与抽屉共用数据和分区组件；没有历史时返回地图预览 |

## 有意变更

- 抽屉的地点内容默认「最新」，`#/poidetail` 仍默认「近期热门」。
- 抽屉中的帖子分左右两列，按原始顺序交替排列；旧页面保持 CSS 多列。

## 按评审意见的处理

- **HIGH（标记高度）**：不再假设标记高 100px，改用适配器实测 `.rm__card` 与 `.rm__pin` 的实际范围（`getMarkerExtent`）。露出区域放不下整个标记时，保证图钉底端距抽屉至少 24px。
- **手势拦截**：第一次出现有方向的移动时锁定「是否拦截」；最终判给正文时立即停止拦截。
- **简介页 photo 参数**：带 photo 参数加载页面时去掉该参数，并记下被去掉的 route 对象，不会打开一个没有历史条目的查看器。
- **usePlaceDetail 重置时序**：sort 和 filter 按地点原子保存，在渲染期间派生，只有一个请求 effect。
- **演示素材**：来源以「演示素材」开头的照片不作为封面或缩略图。
- **Leaflet 精确对齐**：先 `stop()`，再注册 `moveend`，然后 `setView`；对不到 1px 的偏移用 `reset` 对齐（普通 setView 会忽略这种偏移）。

## 与参考图的差异

- 地图使用真实的 Leaflet 底图和照片卡片标记，不是插画地图。标记较密时，选中地点会与周围标记重叠。
- 帖子卡片沿用现有 `PostRow`，没有作者头像和「⋯」菜单（接口没有对应字段和操作）。
- 简介页封面下多一行「标题 · 年代 · 来源」，因为 spec 要求不能省略来源。
- 目前每个地点最多只有一张照片，它会成为封面，所以「相关照片」区都显示「暂无相关照片」。
- 展开态的地图露出区约 147px（0.82H）。照片型标记约 122px 高，放不下时卡片顶部最多被裁 7px，图钉和名称仍可见。

## 未测与已知限制

- 腾讯 GL 和高德 1.4 适配器已按设计实现，但本机没有 Key，未测试。
- Android WebView 实机手势未测，包括「展开态顶部先轻压再上滑」。Playwright 通过 CDP 派发的触摸没有平台 touch slop。
- 以下项目未专门测试：减少动效、横屏单档、大字号、键盘 Tab 自动展开、定位授权弹窗延后弹出、帖子分类筛选后搜索选中。
- `#/poidetail` 的「没有历史」仍按 `history.length > 1` 判断（评审 F9 的 a 方案，已知限制）。
