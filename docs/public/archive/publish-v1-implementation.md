# 发布流程与贴纸首版实现

日期：2026-10-12。依据《BJTU TimeMap帖子发布流程及照片抠图方案设计》V0.1的首版范围。

## 完成的小任务

- 发布页统一为单图编辑，支持纯文字、纯图片、图文，必选预设地标；前后端按去除首尾空白后的 Unicode 码点计数，最多500字。
- 四个一级页使用同一发布页；地点详情带入地点；发布成功返回地图，突出代表新帖约10秒，提供查看同一帖子入口。
- 拍照/相册菜单，更换、删除；取消换图保留当前图片和贴纸。沿用原有选图压缩：最长边1280像素，JPEG质量0.72。图片读取失败明确提示。
- 主动抠图、透明预览、确认采用、恢复原图、白色描边。主体裁至透明区域边界，居中展示，描边写入透明PNG，不写入预览背景。描边切换不会再次调用供应商。
- 图片版本隔离，换图、删除、取消处理后旧请求不覆盖当前图片。
- IndexedDB保存正文、原照片数据、地标和贴纸模式标记；按设备和账号隔离，多草稿列表；新建不覆盖旧草稿。恢复后手动生成贴纸。
- 上传失败/发帖失败保留内容；成功上传的图片复用；同一次上传与发帖重试沿用请求标识。结果不确定时暂时锁定修改，重试同一次提交；该提交信息随显式保存的草稿持久化。
- 原照片地图显示点赞数；贴纸不显示点赞数。纯文字代表帖显示地标附近文字气泡，支持开关；关闭弹幕时新帖成功提示仍可见。当前地图仍按地点聚合，展示该地标最新代表帖，尚未改成所有帖子同时铺满地图。

## 修改入口

草稿：`app/src/data/publishDrafts.ts`；相机/相册：`app/src/native/camera.ts`；透明裁剪与描边：`app/src/native/sticker.ts`。

## 启用真实抠图

后端根据百度官方智能抠图接口实现自动多主体、RGBA返回。凭证只放后端环境配置：

```dotenv
BAIDU_CUTOUT_API_KEY=
BAIDU_CUTOUT_SECRET_KEY=
CUTOUT_MAX_CALLS=0
```

缺少凭证或次数上限为0时返回明确的“尚未开通”，原图发布可继续使用。未购买服务、未消费调用额度。

账户开通并核对实际价格、额度后，可将次数上限设为批准的测试次数，例如24次。上限按数据库中累计保留的尝试记录计算，含失败尝试；清理原图不会补回额度。每账号每分钟最多3次。供应商费用以其控制台为准，此次数限制不是供应商账单上限或自动付费授权。

调用链：上传原图 → 后端鉴权与校验 → 持久预留调用次数 → 百度 → 后端保存透明结果 → 前端预览及描边 → 确认采用 → 通过已有媒体接口上传最终PNG → 创建帖子。

相同处理请求重试读取已有结果；处理中的请求不会再次调用供应商。处理请求超过两分钟仍未完成时，查询会将其标记失败。取消客户端处理不保证供应商免计费。

官方契约：[百度智能抠图文档](https://ai.baidu.com/ai-doc/IMAGEPROCESS/rm8zl3koj)。

## 验证与交付边界

- 前端生产构建通过；后端类型检查、构建和构建加载冒烟通过。
- 在`server`目录执行`node tests/run-publish-v1.mjs`：14项后端检查，使用隔离数据库替身，未连接生产数据库。
- `node tools/checks/publish-v1-browser.mjs`：真实桌面Chromium模拟手机视口，拦截后端响应，验证草稿、内容校验、单图、上传复用、防重复重试、贴纸采用、描边、取消换图、地图成功反馈。
- 浏览器测试需要Playwright。可通过`PLAYWRIGHT_MODULE_PATH`和`PLAYWRIGHT_EXECUTABLE_PATH`指定本机安装位置。脚本启动临时本地预览，测试结束关闭浏览器和预览进程。
- 图片：`docs/test/publish-flow-mobile.png`，使用生成的红色方块验证透明贴纸状态，不代表真实抠图质量。
- 仓库现有全目录lint会扫描依赖并产生大量无关诊断；已单独检查修改的发布和地图源文件。保留部分React建议告警，不将其写成全仓lint通过。

本次尚未部署网页、更新线上数据库或打包安装APK。部署后端时需执行新增迁移，网页和APK需各自发布新构建。百度真实调用效果/耗时、Android相机与相册、苹果手机浏览器兼容性仍需实机验证。图片叠加文字、手动修边、多图和完整贴纸草稿恢复不在本次首版范围。
