更新日期：2026-11-05。维护角色：地图前后端负责人（待认领）。状态：已完成本地数据、接口与地图首版，远程未执行写入或发布。具体结果与限制见[本地实施与验证记录](../../test/地图分级与地点数据本地实施记录-2026-11-05.md)。

## 1. 目标与确定的规则

执行顺序为：全量数据核对 → 本地数据与接口 → 完整地点基础验证 → 地图分级与页面改造 → 本地验收 → 远程协调上线。布局样式可与本地数据工作并行准备，业务显示规则以真实数据验证。

- 目标具体地点为 26 个，五类依次为教学楼 7、食堂 4、运动场 2、休闲场所 4、校园地标 9。
- 留园按用户最新确认移除，不进入本轮地图及新帖选择集合；若旧库存在则保留历史关联。
- 保留三级具体地点，不加第四级。学活食堂、银杏大道改为三级，分配 **6／11／9**，累计候选 **6／17／26**。
- 校园总入口独立于 26 点，复用已有“北京交通大学”学校节点；用于介绍和进入校园地图，禁止作为新帖地点。
- 使用新增 `displayTier` 数字字段，兼容已有 `displayLevel=school/area/place`；类别、结构角色、展示级别分开维护。
- 搜索与分类可以突破默认级别，仍须遵守范围、有效性、权限和碰撞规则。

详细配置以[分级实现方案](地图地标显示层级实现方案.md)为唯一分级表，视觉与交互以[页面复刻说明](地图页面复刻说明.md)为准，地点原始信息见[分类资料](../BJTUTimeMap_校园地点分类资料.md)。

## 2. 当前基线与待确认项

已完成[线上公开数据核对](../../test/地点数据核对-2026-11-05.md)：两个接口均返回 13 个已启用节点，其中 10 个有坐标；目标 26 点中可匹配 7 个，19 个未出现在公开列表。线上有坐标记录与目标资料均未发现完全重复的坐标组合，但资料中存在不足 50 米的相邻点。

已通过 includeDisabled=1 补查 16 条启用及停用记录；仍未取得数据库只读连接及迁移执行历史。“19 个未出现在公开列表”不能直接当作“需要新增 19 条”。

| 待确认项 | 处理方式 | 影响范围 |
| --- | --- | --- |
| 已移除的留园 | 移出清单与地图，旧记录不删除关联内容 | 不再阻塞本轮 26 点验证 |
| 南门坐标差约 6.4 米 | 核对真实入口落点并记录采用依据；未定前保留线上值 | 阻止该点坐标覆盖，不阻止保留 ID 的其他更新 |
| 思源碑、第二食堂 | 两者各有直接关联帖子；核对是否保留额外入口，不能自动替换为目标地点 | 历史节点处置、地图纳管范围与最终全库计数 |
| 停用节点与迁移历史 | 取得服务器认可的只读访问，检查完整 places、schema_migrations 和外键关联 | 正式确定新增／更新清单及远程迁移 |
| 旧版分类兼容 | 盘点当前前端、APK 与管理端使用的分类值，定义旧接口输出与输入兼容 | 分类切换和发布顺序 |

不需要等待以上所有信息才能开始代码准备；涉及未确认记录的写入保留为待办，不能用校园中心或随意坐标补齐后宣称全部验证通过。

## 3. 阶段一：完成全量地点核对

**工作内容**

1. 对数据库执行只读查询，获取所有已启用、停用地点的 ID、名称、类别、坐标、结构角色、父级、排序，以及关联帖子／照片／活动数量；不导出用户个人资料或帖子正文。
2. 检查重复 ID／同名、经纬度完全相同、单维坐标缺失、超范围／零坐标；对距离小于 50 米的组合列为显示风险，不自动判为重复实体。
3. 将 26 个目标与实际记录逐项建立映射；逸夫楼优先复用“逸夫教学楼”的现有 ID，其他地点按核实结果匹配，避免仅靠相似名称改写实体。
4. 查明旧 031 导入脚本是否执行；它包含被排除雕像、旧类别和留园园林资料，不能直接用于本次导入。

**交付物**：更新核对报告；建立机器可读的地点配置清单，记录目标名称、现有／新增 ID、目标分类、tier、坐标及核实状态、更新动作、原始值。

**完成条件**：每个目标都有明确动作“复用更新／新增／待确认”；历史额外节点单独记录处置策略，没有因缺少数据而推测 ID 的情况。未确认项可继续保留，但正式导入前必须解决。

## 4. 阶段二：本地补齐结构、数据和接口

**工作内容**

1. 准备隔离本地数据库及必要地点关联数据，确保开发后端指向本地；启动测试不得自动连接远程执行迁移。
2. 在下一个可用迁移版本增加 `display_tier` 与发帖资格配置，注册到迁移入口；不改写已经执行的迁移。先允许历史未纳管节点 tier=null，避免强迫线上活动或外校区进入三级。
3. 按确认后的 ID 清单更新／补齐目标节点，保留已有外键和帖子归属；不默认启用曾被管理员停用的记录。校园总入口复用已有 school 节点。
4. 明确管理的目标集合与真实校园归属。单纯 parent 指向学校并不代表纳入本轮 26 点，历史额外节点不能未经确认混入验收集合；范围策略必须可在服务端执行。
5. 新增规范类别，同时处理旧单分类接口及旧客户端兼容。旧“地标”与新类别不是一对一关系，兼容投影需逐类定义，不能仅重命名常量。
6. 扩展 `/api/map/places` 的完整 DTO 和多分类查询；保留单分类兼容，明确截断。发布列表过滤资格，服务端新建／编辑帖子也必须拒绝校园总入口等非发帖节点。
7. 准备可预览差异、事务执行和重复运行不产生副作用的数据脚本：重复运行不新增重复 ID，不重置人工停用状态，不擅自搬迁内容，不覆盖未经批准的坐标修正；发现运行前基线与审核清单不一致时停止该次导入。

**交付物**：版本化结构迁移、配置清单与数据脚本、dry-run 差异输出、兼容接口与前端类型定义、回退说明。文件名按仓库实际版本确定，不在计划中占用迁移编号。

**完成条件**：在本地重复运行结果稳定；已确认数据正确；旧 ID 与关联内容不变；新旧分类请求行为明确；校园入口不能发帖。留园已经移除，完整目标集合以 26 点验收。

## 5. 阶段三：验证完整地点基础能力

这一步先验证数据可用，避免与缩放隐藏混在一起排错。

1. 首页接入完整地图数据源，区分地点接口失败和帖子预览失败，无帖子地点也能形成标记。
2. 在仅限本地开发的诊断视图中列出目标地点、ID、坐标、分类和 tier，允许查看全部目标候选；不把“全部常显”的诊断开关作为产品默认行为发布。
3. 在同一 provider／坐标系下检查真实落点，逐个验证名称搜索、点击进入地点抽屉、返回保留视角。
4. 核对目标集合 26 个、类别 7／4／2／4／9、tier 6／11／9；校园节点和历史额外节点另计，不要求全库只有 27 条。

**交付物**：地点清单核验结果、落点问题表、基础交互验证记录。

**完成条件**：26 个目标都能正确定位、搜索并打开详情，未解决坐标问题为零；不以“全部标签同时无遮挡”作为此阶段要求。

## 6. 阶段四：实现分级、避让与页面复刻

**工作内容按依赖顺序执行**

1. 拆开 SDK 实例初始化与 marker 更新，补视图订阅和边界能力；分级变化不得重建地图或重置中心。
2. 普通模式实现校园入口／全校／局部／近景四种逻辑视图，具体地点累计候选 6／17／26。学生活动中心二级、学活食堂三级；校史馆二级、银杏大道三级。
3. 实现多选筛选和搜索焦点突破。食堂筛选可纳入四个食堂，包括三级学活食堂；关闭临时焦点后恢复已应用的类别与缩放规则。
4. 实现稳定排序、标签避让、地点去重聚合与最大缩放成员列表；学校节点、帖子数和聚合地点数不混算。
5. 独立限制照片／贴纸与文字弹幕数量，再按参考图改造头部、面板、工具、卡片和校园介绍抽屉。静态布局可提前准备，最终联调需依赖完整数据。

**交付物**：本地可运行页面、provider 配置、分级与聚合实现、参考图展开态和各逻辑视图截图。

**完成条件**：全校概览主地点清楚，局部不挤满标签，近景目标可达；搜索／筛选可突破且正确恢复；照片隐藏不影响地点可达；真实版权和比例尺无遮挡。

## 7. 阶段五：本地回归与发布准备

| 检查 | 通过标准 |
| --- | --- |
| 数据脚本 | 首次运行正确，重复运行无重复记录；异常能事务回退；保留历史外键和人工状态 |
| 接口 | 新旧分类兼容、多分类并集、完整 tier、停用／非发帖节点限制与截断处理正确 |
| 分级 | 候选集合逐级累加为 6／17／26；学活食堂与银杏大道普通中景不出现 |
| 搜索与筛选 | 四食堂可成为筛选候选，三级目标可定位；焦点清除后恢复规则 |
| 碰撞与预览 | 聚合成员不重复、数字正确、最大缩放可展开；图片预算独立且不压住工具 |
| 生命周期 | 缩放和数据刷新不重建地图，返回恢复视角，SDK 降级不丢筛选 |
| 页面 | 320／390／430px 和桌面布局、展开面板、安全区、减少动效可用 |
| 发布 | 校园入口在前端不可选，伪造 ID 提交也被服务端拒绝；旧具体地点帖子仍可浏览 |

补充有意义的候选选择、聚合去重、迁移幂等和服务端资格测试；按改动范围执行前后端类型检查与构建。真实 SDK 交互另做设备验证，不用单元测试代替实际投影与手势检查。

**交付物**：验收报告、可部署构建、迁移 dry-run、远程数据变更清单、备份和回退步骤。完成这些准备后才能进入远程写入阶段。

## 8. 阶段六：协调远程上线

这部分是未来上线流程，本次仅编写计划，不执行远程写入或发布。

1. 重新只读核对线上基线，防止本地准备期间出现人工改名、停用、坐标修正或新关联数据；有差异先刷新迁移清单。
2. 备份数据库和当前服务／前端构建，确认备份可读取，记录版本与备份位置。
3. 先上线兼容旧结构与旧分类调用的后端能力，再按兼容窗口执行新增列、放宽约束等结构准备。若后端启动会自动迁移，必须事先审查启动行为，不能误以为“部署代码”不含数据库写入。
4. 按已审阅的增量清单事务更新地点。旧客户端仍在线时，须由版本化接口或兼容输出继续满足旧分类；不能在没有兼容路径时直接切换数据库值。
5. 只读核对写入结果、关联计数和校园发帖限制，然后发布／启用新前端。保留必要的旧接口兼容，收紧约束安排在使用方迁移完成之后。
6. 验证线上普通概览、两级放大、分类、搜索、详情与旧内容访问；避免为了冒烟验证创建无关公开帖子。
7. 失败先关闭新策略／回退前端，保留兼容后端；依据实际写入差异决定是否回退数据。不能在新类别仍存在时恢复旧 CHECK，也不能回滚整个数据库而覆盖上线后用户新产生的内容。

**完成条件**：远程目标配置和本地验收一致，旧内容关联不变，新旧客户端可按兼容约定使用，线上基本交互通过，回退路径可执行。

## 9. 当前可立即推进的工作

现在可准备 ID 映射草案、迁移与接口代码、本地隔离环境及前端静态布局；取得全量只读核对结果后定稿新增／更新清单。南门坐标覆盖和历史额外节点的策略确认前，相关写入不能用猜测值代替。

本轮文档调整已经完成分级规则变更；执行状态应在后续实现与验收时更新，不将计划中的脚本或功能视作已经交付。
