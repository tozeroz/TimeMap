# 地图帖子展示 UI 优化与实现说明

版本：v0.3 首版实现说明  
更新日期：2026-10-28  
范围：地图底图、地点标记、帖子叠放预览、缩放层级与展开交互。本文用于指导 UI 和功能实现，已落地范围及待验证项见第 13 节。

> 2026-10-28 后续 UI 调整（优先于下文首版入口规则）：用户确认帖子数量改为普通文字，使用 `span.rm__count`，取消点击、键盘焦点、展开语义及按钮背景；数量未知显示“帖子数未知”。帖子预览通过上方叠层打开，叠层被收起或无帖子时，数量文字不再提供入口。地点图标／名称仍进入地点详情。另外，底图 CSS 弱化滤镜已取消，保留地图服务自身样式。

## 1. 目标与已确认决策

优化当前地图中的地点和帖子展示，使用户既能看清地点，也能发现附近的内容。以用户提供的参考图片为视觉依据，借鉴其布局和信息层级，具体尺寸需结合实际手机视口验证。

已确认：

1. 底图采用浅色风格，底图文字颜色较浅，突出应用自己的地点和帖子。
2. 地点主标记改为横向排列：左侧图标，右侧地点名称。
3. 拉远地图时，仍显示的地点可以展示该地点的帖子总数。
4. 地点标记上方可以叠放多条帖子预览，支持图片、贴纸、文字帖。
5. 地点按“学校→区域→建筑／具体地点”划分展示层级，并允许逐个地点调整。
6. 叠放预览优先展示热门帖子。
7. 点击帖子叠放区域，先展开该地点的帖子预览，再选择一条进入详情。
8. 手机端使用底部半屏面板展开帖子，面板内纵向浏览，上方地图继续支持操作。
9. 点击地点图标／名称进入地点详情；点击帖子数量／叠层打开帖子预览，叠层收起后仍保留帖子入口。
10. 首版热门规则：优先最近 30 天内的帖子，按点赞量排序；不足时使用更早的帖子补齐。

本版将 2026-10-28 审阅建议纳入实现规则；具体视觉规格和缩放阈值仍需预览确认。

术语：本文“缩小／拉远”表示地图缩放级别降低、可见地理范围扩大；“放大／拉近”表示可见范围缩小。

## 2. 当前实现与改动方向

| 项目 | 当前代码行为 | 本次目标 |
| --- | --- | --- |
| 地点标记 | 名称在上、分类图标在下 | 图标在左、名称在右 |
| 地点与帖子关系 | 一个地点生成一个标记，附带一条代表帖 | 保留地点为组织单位，扩展为多条帖子叠放预览 |
| 代表帖选择 | 从当前帖子集合取该地点第一条匹配内容 | 使用明确的热门排序和数量上限 |
| 帖子卡片位置 | 位于地点图标右上方 | 位于地点主标记上方，形成一个视觉组 |
| 帖子点击 | 直接进入代表帖 | 先展开地点帖子预览，再选择具体帖子 |
| 帖子计数 | 地点列表已有 postCount，标记尚未使用 | 在规定缩放状态下展示计数 |
| 缩放显示 | 尚无统一的业务层级和碰撞规则 | 层级筛选、密度控制和内容降级共同决定展示 |

## 3. 底图视觉

- 道路、建筑轮廓和地名采用低饱和浅色，保证基本辨路能力。
- 应用地点名称使用明显深于底图文字的颜色；帖子预览处于更高视觉层级。
- 浅色处理只影响底图，不降低地点标记、帖子卡片和定位点的透明度。
- 优先通过地图服务支持的样式配置调整；不同地图实现需逐一验证。栅格瓦片中的文字无法通过普通 CSS 单独换色，需选择合适瓦片样式或使用经过验证的底图专属降级处理。
- 不在整个地图容器上叠加会同时淡化业务内容的白色蒙层。
- 应用地点名、帖子数量、预览正文保持清晰。普通大小的应用文字以实际合成背景上至少 4.5:1 的对比度为目标，必要时增加局部浅色衬底；分别在道路、绿地、建筑背景上检查。底图弱化不能连带降低业务文字的辨识度。

## 4. 地点标记样式

结构示意（用于表达相对位置，不代表最终图标素材）：

```text
       [图片帖 A]
          [贴纸帖 B]
        [文字帖 C]

    [分类图标] 北京交通大学
               128 条帖子
```

图标、名称和计数组成地点主标记，其中图标／名称是地点详情入口，计数和帖子叠放区域是帖子预览入口。各入口使用独立按钮，不嵌套按钮，不互相覆盖点击范围。

建议初始规格，尚待视觉确认：

| 元素 | 建议值／规则 |
| --- | --- |
| 分类图标 | 24–32 CSS px；同类地点使用统一风格的资源 |
| 地点名称 | 14–16 CSS px，深色、中等字重 |
| 图标与名称间距 | 4–6 CSS px |
| 计数 | 12 CSS px，次级深灰色，对齐名称左侧 |
| 名称长度 | 常态最多一行，超长省略；展开面板提供完整名称 |
| 交互区域 | 地点入口、计数入口和叠放入口分别提供足够触控面积，初始以至少 44×44 CSS px 为 Web 项目目标；Android WebView 中另行实测触控舒适度，CSS px 不直接视为原生 dp／pt |
| 相邻入口 | 尽量保留至少 8 CSS px 的可辨间隔；不可用互相覆盖的透明点击区补足面积 |
| 地理锚点 | 固定在地点图标中心附近；卡片数量和名称长度变化不改变真实落点 |

图标使用现有分类资源作为起点，是否重绘待确认。参考图中的学校图标用于表达风格和布局，不直接决定所有地点的素材。

未选中时使用轻阴影或细文字描边，增强复杂底图上的辨识度。选中时提高该组的层叠优先级，增加轻量描边或强调色反馈，避免持续闪烁。

## 5. 帖子数量

- 拉远状态中，只要地点通过层级和避让筛选且计数可用，就在名称下展示“128 条帖子”。
- 建议在近景也保留计数，确保同一地点的信息一致；是否只在远景显示待确认。
- 计数代表该地点归属范围内、当前用户有权查看的帖子总数，不是叠放卡片张数，也不是已经加载的列表长度。
- 学校和区域标记的计数需要明确的下级归属关系，由服务端汇总并按帖子 ID 去重。不得将几个相邻地点直接当成同一个区域，或根据名称猜测学校归属。
- 学校级、区域级的汇总卡片必须和计数采用相同归属范围。
- 确认无帖子时可显示“0 条帖子”，同时不展示帖子叠层；计数未知时暂不展示数字，不以 0 代替。
- 帖子数量是可点击的预览入口。叠层因避让被收起时，该入口仍可用；点击“0 条帖子”打开空状态面板。计数未知且没有可用叠层时，在原计数入口位置显示“查看帖子”，打开面板查询，不伪造数字。
- 初稿使用精确整数，不额外引入“1.2万”等缩写；大数量格式后续再定。

## 6. 地图缩放与地点层级

### 6.1 层级配置

地点类别与显示层级分开维护：例如“食堂”是类别，显示层级可以是“建筑／具体地点”。

| 显示层级 | 典型对象 | 展示意图 |
| --- | --- | --- |
| 学校 | 学校、校区主标记 | 拉远后识别整体位置和内容总量 |
| 区域 | 教学区、生活区、体育区 | 中景识别区域和内容分布 |
| 建筑／具体地点 | 图书馆、食堂、教学楼、球场 | 近景查看具体位置和帖子 |

建议配置字段：`displayLevel`（显示层级）、`minDisplayZoom`（单点起始缩放覆盖值）、`displayPriority`（同层级避让优先级）、`parentPlaceId`（经维护确认的上级归属）。这些是拟新增字段，现有地点列表接口尚未提供。

规则优先级：地点单独配置覆盖层级默认配置，再执行视口筛选和碰撞避让。单独调低出现阈值并不意味着允许该标记覆盖其他标记。

归属结构允许跳过区域层，例如建筑直接归属学校。不得为了满足三层结构虚构区域。

### 6.2 建议缩放分段

下表是首轮调试起点，**尚未确认为最终阈值**。以当前默认缩放约 16 和栅格地图最大缩放 18 为背景，按实际可见范围校准各地图实现，不能假定相同数字具有完全相同的视觉效果。

| 逻辑视图 | 初始参考 zoom | 地点展示 | 帖子展示 |
| --- | --- | --- | --- |
| 远景 | 小于 15 | 学校级优先，隐藏区域和具体地点 | 有空间的学校标记可显示精简叠层和总数 |
| 中景 | 15 至小于 17 | 区域级出现；学校级按避让规则保留 | 有空间的标记展示热门帖叠层，其他仅名称和计数 |
| 近景 | 17 及以上 | 建筑／具体地点出现 | 优先展示具体地点的热门帖叠层 |

放大时先保留既有地点再渐进增加细节；缩小时先隐藏低层级内容。学校、区域、建筑并非需要全部同时展示，父级标记可为具体地点让位。

层级回退：当前视口内没有符合默认层级的候选地点时，允许补充下一层已有真实坐标的地点，按配置优先级和避让规则逐步显示。回退只能放宽层级默认阈值，不能覆盖地点单独设置的起始缩放阈值，也不能重新显示禁用地点。不承诺在无数据、加载失败或所有地点均被单独阈值限制时显示标记。

### 6.3 碰撞与密度

层级控制负责筛选候选地点，屏幕空间避让负责决定最终显示。建议规则：

1. 根据当前视口和缩放确定候选地点。
2. 按已选中地点、配置优先级、当前视图适合的层级、距离视口中心依次排序；同优先级以稳定 ID 排序，避免随机抖动。
3. 计算地点文字、计数、帖子叠层以及点击区域的屏幕占用范围。
4. 空间冲突时先收起低优先级地点的帖子叠层，保留地点名称和计数；仍然冲突时隐藏低优先级的整组地点。
5. 不通过挪动地理坐标解决碰撞；叠层可在限定范围内微调偏移，但需保持与地点的明确关联。
6. 靠近顶部搜索栏、底部导航和视口边缘时，收起叠层或调整卡片组偏移，避免遮挡操作和裁切关键内容。
7. 同一视野轻微平移时，在优先级和避让条件允许的情况下优先保留已显示地点；不得每次按中心距离重排就让标记频繁交换。平移／缩放手势进行中不触发地点或帖子点击，结束后的合成点击也需抑制。

初版建议用屏幕像素避让控制密度，不额外增加“把不相关地点合并成一个数字圆点”的交互。地点隐藏属于展示决策，不改变其归属和计数。

缩放过程中保持地理锚点跟随地图；缩放结束后统一计算展示状态，可使用短延迟和切换缓冲，避免在临界缩放值附近反复闪现。隐藏标记必须同时移除点击能力及键盘／读屏焦点入口。卡片加载前预留稳定尺寸，图片、字体或内容尺寸变化后重新检查避让，不改变地理锚点。

## 7. 热门帖子叠放预览

### 7.1 内容选择

首版热门规则已确认，采用服务端请求时刻为基准的最近 30×24 小时发布窗口；窗口内按点赞量降序、发布时间降序、帖子 ID 升序稳定排序。评论量暂不参与排序。

- 建议每个地点最多展示 3 条，按热门排序取前几条；1 条不制造假叠层，2 条叠放 2 张，3 条及以上最多显示 3 张。
- 建议由服务端对完整可见帖子集合排序和截取，避免仅从客户端已加载的一页中计算“热门”。
- 先取窗口内帖子，不足所需数量时，按相同排序规则从窗口以前的帖子补齐；近期帖子始终排在补齐的旧帖之前。使用服务端时间判断窗口，边界时刻计入近期集合。
- 被删除、不可见或归属不符的帖子不进入候选；地图预览只提供必要摘要和缩略图。
- 地图停留期间保持顺序稳定；刷新或重新进入时更新，避免浏览中突然换卡片。
- 首版不增加手动置顶覆盖热门排序；如果后续有运营需求，另行定义置顶优先级。

同屏去重：学校、区域和具体地点同时显示时，同一帖子 ID 在地图叠层中最多出现一次。先确定地点主标记的可见集合，再按从具体地点到区域、学校的顺序分配预览；同层按展示优先级、地点 ID 稳定分配。仅有空间实际展示叠层的地点占用帖子 ID，上级从其余热门候选中补齐，补不齐时减少卡片数，不制造假叠层。服务端应支持补充候选或排除已展示 ID，不能只返回固定 3 条后假定总能补齐。

同屏去重只影响地图叠层，不扣减各层级总数，也不从展开面板的完整列表中剔除帖子。某张叠层被避让收起后可将帖子释放给上级；一次布局中统一提交，避免反复分配引起闪烁。

### 7.2 视觉形式

- 整组位于地点名称上方，和下方地点形成明显关联，预留间距，不遮挡名称和数量。
- 图片帖采用带白色细边、轻阴影的照片卡片；建议宽 72–96 CSS px，按固定预览比例裁切。
- 贴纸帖保留透明背景，图片使用 contain，避免裁掉贴纸主体。
- 文字帖使用便签样式，建议最多展示两行摘要；完整内容在展开预览中查看。
- 卡片可轻微错位和旋转形成参考图中的叠放效果，初始角度建议控制在 ±6° 内。最上方卡片优先表达排名最高的内容。
- 照片、贴纸和文字根据真实帖子类型展示，不为了凑参考图效果伪造内容。
- 紧凑状态建议展示 1–2 张，宽松状态最多 3 张。卡片视觉大小保持稳定，不随着地图连续缩放无限变大或变小。
- 初稿建议不在叠层中增加头像、评论数和点赞徽标，减少噪声；这些信息在展开预览显示。最终取舍待视觉确认。

## 8. 点击与展开

已确认：点击叠层先展开地点帖子预览，然后选择具体帖子。

### 8.1 入口与面板

1. 点击叠层任意可见卡片，都展开其归属地点的帖子预览，避免重叠的小点击区分别导航。
2. 手机端使用底部半屏面板，初始约占可用内容高度的 50%，标题显示完整地点名和总数；内容纵向滚动，并按第 7.1 节排序分页加载。该高度为初始实现值，需在小屏、大字体和横屏下校准。
3. 地图仍保留，选中地点高亮；如被面板遮住，可平移到可见区域，不主动改变用户缩放级别。
4. 点击面板中的具体帖子，进入对应帖子详情。
5. 从详情返回时恢复展开面板、列表位置、选中地点和离开地图时的地图视图。关闭面板时按第 8.2 节规则处理地图位置。
6. 同时只展开一个地点。面板打开时点击另一个地点叠层，替换面板内容并更新选中状态。

点击地点图标／名称继续进入现有地点详情；点击数量／叠层进入同一个帖子预览面板。面板打开时点击其他地点名称仍进入该地点详情，返回后恢复离开前状态。

面板不添加阻断上方地图的全屏遮罩；地图可以拖动、缩放和切换地点。点击地图空白处保持面板打开，避免拖动结束误关闭。提供明确关闭按钮；Android 系统返回和 Web Escape 在面板打开时先关闭面板。从帖子详情返回则先回到预览面板。

首版固定半屏高度，面板内只处理列表纵向滚动，不要求拖动面板调整高度或滑动关闭。后续如果加入拖动，仍需保留按钮替代操作；不得抢占地图平移、列表滚动或系统返回手势。

### 8.2 地图位置恢复

- 打开面板时记录地图中心、缩放和本次系统平移；面板本身不触发自动缩放。
- 用户没有主动移动地图时，关闭面板仅撤销系统为避让面板产生的平移。
- 用户打开面板后主动拖动、缩放，或点击定位／回到校区等视图控制，则保留最近视图，关闭面板不再跳回旧中心。
- 面板内切换地点产生的自动平移仍属于系统动作，不能误判为用户拖动；没有用户视图操作时，以首次打开面板前的视图作为恢复基准。
- 用户主动移动导致选中地点离开视口时，不强行拉回；面板保留当前地点内容，直到用户切换或关闭。

### 8.3 焦点与可访问性

- 面板是可与地图共同操作的非模态区域，具有明确标题；不锁住整页焦点，也不声明为阻断背景的模态对话框。
- 打开时将焦点移到面板标题或首个有效控件；关闭时返回触发入口，入口已隐藏时转移到地图的可用控制按钮。
- 地点入口读出地点名；数量和叠层入口读出“地点名、帖子数（已知时）、展开帖子”，并暴露展开状态。装饰性分类图标不重复朗读地名。
- 提供可见键盘焦点，面板及固定导航不遮挡当前焦点；加载、空状态和请求失败提供可读的状态反馈。
- 点击后及时提供按压反馈；过渡遵循减少动态效果设置，不以颜色或动画作为唯一状态提示。

## 9. 异常状态

| 状态 | 预期反馈 |
| --- | --- |
| 地点无帖子 | 显示地点标记，不显示叠层；允许进入地点详情 |
| 热门帖正在加载 | 保留地点标记；预览区域使用稳定占位，加载后不改变地理锚点 |
| 图片失败 | 当前卡片使用文字摘要或类型占位，不影响地点和其余卡片 |
| 展开内容请求失败 | 面板保留地点名并提供重试 |
| 帖子已删除或失去可见权限 | 从预览移除，必要时重新补位，并更新计数 |
| 缺少经纬度 | 不在地图编造落点 |
| 地图切换实现 | 遵守同一业务展示规则，单独校准缩放和坐标投影 |
| 离线自绘地图 | 维持现有无权威标记的降级策略，待投影经过校准后另行设计 |

## 10. 实现拆分与代码入口

本节记录实现模块的职责划分，首版落地情况见第 13 节。

| 代码入口 | 预计调整 |
| --- | --- |
| `app/src/native/placeMarker.ts` | 横向地点布局、计数、多帖子叠层、明确入口语义 |
| `app/src/native/realmaps.css` | 尺寸、锚点、叠放、文字层级、选中和紧凑状态 |
| `app/src/screens/MapScreen.tsx` | 地点与帖子数据组合、选中状态、展开预览、返回恢复 |
| `app/src/native/mapApi.ts` | 扩展计数、层级、预览列表；补充视图事件和屏幕投影所需能力 |
| `app/src/native/TencentMap.tsx`、`AmapMap.tsx`、`RealMap.tsx` | 订阅缩放／移动、提供坐标投影、更新标记可见性，避免每次缩放重建整张地图 |
| 服务端地点／帖子接口 | 层级配置、可靠归属、可见总数及热门预览列表 |

建议增加独立的展示计算模块，统一完成层级筛选、稳定排序、矩形碰撞和展示形态决策。各地图实现提供 zoom、视口和经纬度转屏幕坐标能力，并消费相同的决策结果。

计数与预览采用同一可见性口径；计数可大于预览列表长度。配置入口暂以维护端或项目配置为建议，不默认向普通浏览用户开放设置；具体由谁调整待确认。

## 11. 验收场景

1. 普通手机视口中，应用地点名称明显深于底图文字，图标始终位于名称左侧。
2. 同一地点分别有 0、1、2、超过 3 条帖子时，计数和叠层数量分别正确，不将预览数量当成总数。
3. 图片帖、透明贴纸帖、长文字帖混合叠放时，地点名称和计数可读。
4. 从远景逐步拉近，学校、区域、具体地点按配置出现；单个地点覆盖值能生效。
5. 密集区域中，先收起帖子叠层，必要时隐藏低优先级标记；视觉和点击区域均无互相覆盖。
6. 在缩放阈值附近反复缩放，不持续闪烁、不改变地点真实落点。
7. 点击叠层先展开地点帖子预览；只有点击展开后的帖子才进入帖子详情。
8. 查看详情后返回，地图中心、缩放、选中地点和预览位置恢复。
9. 三种在线地图分别验证层级、避让和点击行为；未验证的实现不得标为已通过。
10. 计数未知、图片失败、列表失败、帖子不可见时，反馈符合第 9 节规则。
11. 叠层因拥挤收起后，点击帖子数量仍能打开相同面板；未知计数和零帖子分别展示正确入口及状态。
12. 缺少区域层时，中景能按回退规则显示具体地点；单点起始阈值和禁用配置仍有效。
13. 父子地点同屏时不重复展示相同帖子；总数及展开列表不因地图叠层去重而减少。
14. 近期、旧帖、同点赞量及窗口边界数据排序正确；近期不足时才补入旧帖，分页顺序稳定。
15. 面板打开后未主动移动地图，关闭时撤销系统平移；主动拖动、缩放或使用定位控制后，关闭时保留最新视图。
16. 地图拖动／缩放结束不误开帖子；面板内容滚动不带动底图，关闭按钮和系统返回均有效。
17. 小屏（375 CSS px 宽）、大屏手机、横屏和大字体下，地点名、数量、关闭按钮及列表不被搜索栏、底部导航和系统安全区遮挡。横屏空间不足时允许面板内部滚动，关键操作始终可见。
18. 图片延迟加载、加载失败和字体尺寸变化不造成卡片跳位或持续碰撞；轻微平移不导致同一批地点频繁交换。
19. 键盘／读屏可操作各入口，面板开关后焦点恢复合理，隐藏标记不可聚焦；减少动态效果设置下仍能辨识选中与展开状态。

## 13. 首版实现记录（2026-10-28）

本节记录代码落地情况，不将测试环境的数据或地图底图样例视为正式内容。

- 三种在线地图接入共用标记层：横向图标／名称、帖子数入口、最多 3 张热门卡片、缩放层级、碰撞避让和同屏帖子去重。远景最多 2 张。
- 首版保留近景计数，确保叠层收起后帖子入口仍可用；未知计数显示“查看帖子”。沿用现有分类 PNG，重绘仍待视觉确认。
- 采用表中 15／17 的默认层级阈值，增加 0.15 zoom 的切换缓冲；停稳约 100ms 后重新计算布局。默认值需按实际地图继续校准。
- 手机端固定半屏预览、纵向分页；数量／叠层打开预览，名称／图标进入地点详情。支持关闭按钮、Escape、浏览器历史返回，以及详情返回后的预览列表位置恢复。
- 地图手势与预览滚动分区处理。关闭面板时只撤销系统自动平移，用户主动调整后保留最新地图视图。
- 新增 `GET /api/map/places`，返回维护地点的层级、归属、汇总总数和每点最多 12 条热门候选；新增 `GET /api/map/posts`，按地点及维护的下级关系提供分页和候选排除能力。现有校园流热门排序保持原口径。
- 排序使用最近 30 天优先、点赞量降序、发布时间降序、ID 升序；30 天窗口不足时补旧帖。分页在服务端保存有时效的排序快照，点赞变化不在翻页中重排，删除／停用仍在读取时过滤。快照失效后客户端重新加载。
- 数据库迁移 `026_map_display` 增加显示配置、上级外键和防循环校验。管理端“地点管理→地图展示设置”可维护层级、上级、起始缩放、优先级和坐标。现有地点默认属于具体地点层，不自动推断学校或区域。
- 地图最多返回前 500 个地点，单个分页快照最多保留前 10000 条帖子；达到上限时界面明确提示。后续扩大数据规模时需改为视口查询和更长期的分页方案。
- 底图使用服务支持的浅色样式，并对底图专属渲染层作弱化；不同地图真实配色仍需在设备上校准。

验证记录：前端构建和服务端类型检查通过；在隔离的真实 PostgreSQL 中验证汇总、排序、分页、删除可见性和循环拒绝；在 Chromium 中验证栅格地图、半屏预览、触摸滚动、详情返回、小屏及横屏。高德实际 SDK 可显示标记并打开预览；腾讯实际 SDK 在当前环境降级到高德，腾讯自身渲染仍待设备实测。

集成时需同步更新前端和后端，并由后端应用新增迁移；本轮未发布线上版本。测试仅使用独立数据库与测试素材，不修改现有正式地点归属。

## 14. 远程数据只读预览（2026-10-28）

为使用远程真实数据检查新 UI，增加独立的本地只读预览入口，不通过会自动迁移数据库的常规后端连接线上库。

- 启动：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-remote-preview.ps1 -Key <已加固的密钥文件路径>`；停止并切回本地数据：`tools/stop-remote-preview.ps1`。
- 浏览器继续使用 `http://127.0.0.1:5180/#/map`，页面显示“远程数据 · 只读预览”。常规本地后端配置和数据库保持保留。
- 本地预览 API 位于 `127.0.0.1:3003`。SSH 仅在本机监听数据库转发端口 `15543` 和远程 nginx 转发端口 `18080`，连接配置只在进程内读取，密钥与远程口令不写入仓库。
- 数据库连接强制 `default_transaction_read_only=on`，不启动迁移；预览网关拦截写入方法。普通读取与图片通过 SSH 隧道访问，公开图片重定向仍保留在本地网关。
- 远程缺少层级字段时，按具体地点默认值读取。2026-10-28 用户确认“北京交通大学”为清单内 9 个地点的上级后，本地只读预览增加显式地点 ID 对应的学校投影；仅在该学校 ID 尚不存在时补充学校与九个归属，不按名称或距离推断区域，不写入远程表。计数和热门列表按此投影查询真实帖子。正式后端仍通过 `027_bjtu_parent_place` 迁移持久维护归属，详细分批规则见《地图地标地点清单》。
- 本次已验证远程启用地点、热门帖子和图片读取，页面可打开帖子面板且无浏览器脚本异常；写入请求在本地被拒绝。只读预览不支持发帖、点赞或管理端保存。
