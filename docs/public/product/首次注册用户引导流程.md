# 首次注册用户引导流程

状态：方案草稿，供产品、设计、开发与验收评审；尚未实现。  
维护人：用户引导模块负责人（待指定）。  
最近更新：2026-11-22。  
适用范围：BJTU TimeMap 普通用户注册成功后的首次使用流程。

## 1. 目标与范围

让新用户认识五个重要功能：修改个人资料、从地图浏览帖子、发布帖子、浏览校园活动、浏览实训项目。加上欢迎页，共六个阶段。

引导以真实页面上的高亮提示和简短说明为主。用户可以实际点击入口，也可以直接进入下一阶段，不要求修改资料、发布帖子、点赞、评价或打开外部链接。

首版不介绍聊天、消息、收藏管理、活动投稿、管理员功能及高级地图工具。基础流程以约一分钟浏览为设计目标；主动编辑资料或阅读内容所花时间不计入这一目标，不设置倒计时。

## 2. 与当前项目的衔接

以下为代码现状，后文的自动引导、状态记录与重看入口均为拟新增能力。

| 模块 | 当前入口与行为 | 本方案的衔接方式 |
| --- | --- | --- |
| 登录后进入 | 普通登录通常进入广场，也有登录前目标页的回跳逻辑 | 新注册用户无回跳目标时先进入地图，再展示欢迎卡；已有目标时优先完成原任务 |
| 现有 onboarding 页 | `#/onboarding` 是昵称输入页，点击后进入广场，不是六步功能引导 | 新引导需统一接管首次使用入口，避免连续出现两套流程；资料介绍统一放在第 2 步 |
| 个人资料 | 我的 → 编辑资料；编辑页为 `#/profile-edit` | 介绍头像、昵称和个人简介 |
| 地图浏览 | `#/map`，包含地点标记、地点面板与相关帖子；部分代表帖卡片可直接打开帖子 | 重点演示“地点 → 相关帖子 → 帖子详情” |
| 发布 | `#/publish` | 指出发布入口，介绍内容、图片和地点 |
| 校园活动 | 底部活动入口，`#/activities` | 介绍活动卡片、详情、时间地点与参与说明 |
| 实训项目 | 活动页顶部标题菜单 → 实训项目；`#/activities?mode=projects` | 必须演示标题菜单，帮助用户下次自行找到入口 |
| 实训详情 | `#/project?id=…`，展示项目介绍、团队、评价；有有效体验链接时显示“立即体验” | 不使用“报名实训”的引导文案 |

活动目前没有站内报名和支付入口，参与方式以详情实际展示为准。引导不能承诺不存在的功能。

## 3. 触发与退出规则

### 3.1 自动触发条件

同时满足以下条件才自动展示：

1. 本次认证成功且服务端确认创建了新用户；不能仅根据本机是否有缓存判断新用户。
2. 当前账号未完成、未跳过本版本引导。
3. 当前处于普通用户主界面，页面已可操作，没有正在进行的保存、发布或权限弹窗。

注册识别建议由认证响应提供明确的新用户标识，具体字段与接口由开发设计时确定。现有前端会话类型没有该标识，实施时需要核对服务端响应并补齐契约。

旧用户登录、游客浏览、管理员登录管理端不自动进入本流程。上线时不能把所有缺少引导记录的老账号都当成新用户。

### 3.2 原任务优先

如果用户为查看项目或提交内容而登录，先回到登录前目标页，不强行跳走。新账号的引导保持待开始状态，在用户之后主动进入地图主页面、且没有未保存操作时展示欢迎卡。用户可以直接跳过。

### 3.3 跳过、返回与中断

- 欢迎页提供“暂时跳过”；后续阶段提供“上一步”“下一步”和“跳过引导”。阶段内可提供“暂不填写”“暂不发布”等按钮，表示继续下一阶段，不等于退出全部引导。
- 主动跳过全部引导后，本账号不再自动弹出；以后可以手动重看。跳过后保留当前可用页面；欢迎页跳过则留在地图。
- 返回上一阶段仅恢复该阶段页面和提示，不撤销用户已经保存的资料或已提交的真实操作。
- 系统返回键先关闭本阶段的子面板或详情；在阶段主提示处按返回，则收起引导，保留进度，不强行拦截退出。
- 切到其他 App、刷新或异常退出，记录当前阶段。下次进入地图时显示轻量“继续新手引导”提示，不立即跨页恢复遮罩；用户主动继续或关闭。关闭后不再自动提示，仍可手动重看。
- 遇到未保存内容时，沿用原页面的保存、保留草稿或放弃确认，不因引导切页丢失内容。用户取消离开时停留当前页。

## 4. 六步详细流程

阶段顺序固定为：欢迎 → 个人资料 → 地图帖子 → 发布 → 校园活动 → 实训项目。每阶段最多连续出现两条提示，总体保持简短。

### 第 1 步：欢迎进入 TimeMap

**位置与形式**：注册成功并进入地图后，显示居中欢迎卡片。背景保留地图，让用户知道产品从地图开始。

**推荐文案**：

> 欢迎来到 BJTU TimeMap  
> 用一分钟认识这里：完善资料、探索校园分享、发布自己的记录，再发现活动与实训项目。

**按钮**：主按钮“开始认识 TimeMap”；次按钮“暂时跳过”。

**交互与完成条件**：点击开始后进入“我的”页，定位编辑资料入口，并进入第 2 步；跳过则关闭卡片并停留地图。欢迎页不请求定位、相机或相册权限。

### 第 2 步：认识个人资料修改

**目标**：让用户知道在哪里修改头像、昵称和个人简介。

**提示 A：我的页面**

- 高亮“编辑资料”，文案：“从这里修改头像、昵称和个人简介，让同学们认识你。”
- 点击真实入口后进入资料编辑页；也可点击“下一步”直接进入第 3 步。

**提示 B：资料编辑页**

- 高亮个人简介区域，文案：“写一句话介绍自己，也可以修改头像和昵称。现在不填也没关系。”
- 按钮为“我来填写”和“暂不填写，继续”。前者收起遮罩，交由原页面处理输入、上传与保存，同时保留轻量“继续引导”入口。
- 用户保存成功后，提示“资料已保存”，由用户点击“继续引导”进入地图。保存失败时停留并保留输入；用户仍可按原页面规则退出。
- 用户不修改或取消编辑也可继续，不能用资料是否填写作为通关条件。

**完成条件**：用户选择继续第 3 步；资料是否保存另行判断，不将“看过说明”记录为“资料已完善”。

### 第 3 步：从地图浏览帖子

**目标**：理解校园内容与地点的关联，并知道如何打开帖子。

**提示 A：地图上的地点**

- 回到地图，选择当前可见且有公开帖子的真实地点，高亮地点标记。
- 文案：“拖动地图探索校园，点击地点，就能看看这里有哪些分享。”
- 点击地点后打开原有地点面板；不必先完成拖动或缩放动作。

**提示 B：地点中的帖子**

- 高亮地点面板中的一条真实帖子，文案：“点击帖子查看完整内容，读读同学们在这里的故事。”
- 用户可点击阅读，返回后继续；也可点击“下一步：认识发布”直接进入第 4 步。
- 不要求点赞、评论或收藏，不把这些操作作为完成条件。

**空数据处理**：没有帖子时，仍可介绍地点入口，提示“这里暂时还没有分享，之后可以回来看看”，提供继续按钮。地点也没有加载成功时，只介绍地图浏览方式，允许重试或继续。不能创建假帖子或跳到硬编码的示例内容。

**完成条件**：用户选择进入发布阶段；是否实际打开帖子可单独统计。

### 第 4 步：认识发布入口

**目标**：知道从哪里发布，以及发布内容需要关联校园地点。

**提示 A：发布入口**

- 返回地图，定位当前界面实际可用的发布按钮，避免在地点面板后高亮被遮挡的入口。
- 文案：“想留下自己的校园记录？从这里开始发布。”
- 点击入口进入发布页；点击下一步则直接进入第 5 步。

**提示 B：发布页**

- 将正文、图片和地点区域作为一组介绍，不逐个弹出多层说明。
- 文案：“写下内容、按需添加图片，再选择校园地点。准备好后，由你点击发布。”
- 按钮为“暂不发布，继续”和“我来试试”。选择尝试时收起遮罩，恢复原页面的完整操作，并保留“继续引导”入口。
- 引导不自动填内容、不自动选图片、不自动提交。打开发布页本身不触发相机、相册或定位授权。
- 如果用户主动发布，结果与跳转沿用原流程；成功后可以继续引导，失败时保留内容并允许重试。
- 离开时按现有草稿与离页保护规则处理；发布请求尚未确认时，不强行跳入活动页。

**完成条件**：用户选择继续活动阶段，无需真实发布。

### 第 5 步：浏览校园活动

**目标**：知道活动入口，以及判断活动是否适合自己的关键信息。

**提示 A：活动入口与列表**

- 高亮底部“活动”按钮，用户点击后进入校园活动列表；也可通过引导按钮进入。
- 文案：“从这里查看校园活动，留意活动的时间、地点和当前状态。”

**提示 B：活动详情**

- 有活动时高亮一张真实卡片，文案：“点开活动，查看详细介绍和参与说明。”
- 用户可自主打开详情，重点查看时间、地点和参与方式，不要求访问外部链接。
- 继续按钮为“下一步：发现实训项目”。点击后回到校园活动列表，进入第 6 步。
- 无活动时保留入口介绍，显示正常空状态，并允许继续；不以读取到某条活动为前提。

**完成条件**：用户选择继续实训阶段，无需参加、收藏或打开外部页面。

### 第 6 步：发现实训项目并结束

**目标**：记住实训项目藏在活动页的标题切换菜单中，知道如何查看项目与体验入口。

**提示 A：切换内容模式**

- 高亮活动页顶部“校园活动”标题及下拉箭头。
- 文案：“点击这里，可以在校园活动和实训项目之间切换。”
- 点击标题后展示原菜单，高亮“实训项目”；用户选择后进入项目列表。允许直接点击“带我看看”完成相同导航。

**提示 B：项目列表与详情**

- 有项目时高亮真实项目卡片，文案：“在这里浏览同学们的实训成果，点开查看介绍与体验方式。”
- 用户可自主打开详情。只有项目实际存在有效体验链接时才介绍“立即体验”；不要求离开 App，不要求评价或点赞。
- 列表为空或加载失败时，保留切换入口的教学，显示原页面空态或错误信息，依然允许结束。

**结束卡片**：

> 已认识主要功能  
> 现在可以探索地图、记录校园生活，或继续看看活动和实训项目。

**按钮**：主按钮“开始探索地图”；次按钮“留在实训项目”。两者都将引导标记为完成；主按钮返回地图，次按钮停留实训列表。结束不再追加新的教学任务。

## 5. 通用交互规范

### 5.1 必须遵循项目 UI 设计规范

用户引导的 UI 设计与开发**必须遵循[《时光坐标 UI 设计规范》](../UI设计规范.md)**。该要求覆盖欢迎卡片、高亮遮罩、提示气泡、步骤进度、按钮、结束卡片及重新查看入口，并作为 UI 验收依据。

- 颜色、字体、字号、间距、圆角和动效统一使用项目既有设计变量；变量以 `app/src/styles/tokens.css` 为唯一维护入口，不另建同义变量或独立视觉风格。
- 按钮优先复用公共 `Button` 组件，按规范区分主要、次要和文字操作，并遵循加载、禁用、焦点及触控区域要求。
- 提示卡片与遮罩须符合规范中的文字对比度、移动端适配、原生安全区和减少动态效果要求，与现有页面保持一致。
- 本文补充引导特有的交互规则；涉及视觉样式时以项目 UI 设计规范为准。如确需调整通用规范，应先同步更新规范文档，再应用到引导组件。

### 5.2 引导交互要求

- 第 2 至第 6 步显示“第 X/6 步 · 阶段名称”；同一阶段的两条提示不改变总步数，欢迎页计为第 1 步。
- 每次只强调一个操作目标。遮罩保留高亮区域和引导控件可点击；输入、滚动、地图拖动等自由操作前先收起遮罩。
- 提示位置按目标计算，优先避开底部导航、系统安全区和软键盘。目标不在可见范围时先滚动到目标，不能指向空白位置。
- 页面加载时先显示原有加载态；目标就绪后再出现高亮。不使用固定延时假定目标已出现。
- 数据失败或目标不存在时，转为不依赖目标的说明卡，提供重试、继续和跳过，不能无限等待。
- 按钮触控区域至少 44 × 44px。文字保持足够对比度；支持键盘操作、可见焦点和读屏标签。弹层显示时管理焦点，关闭后恢复到合理位置。
- 动效只用于解释目标变化，尊重减少动态效果设置；不用长动画或闪烁迫使用户关注。
- 自动导航使用受控的阶段返回位置，避免“上一步”依赖浏览器历史而跳回登录页。退出引导后不留下循环返回的教学页面栈。

## 6. 状态记忆与提示协调

### 6.1 账号状态

建议服务端按用户记录引导版本、状态、当前阶段和更新时间，前端缓存用于快速恢复。首版状态可采用：未开始、进行中、已完成、已跳过。

- 账号 A 的完成记录不能影响账号 B；退出登录不清除该账号的引导结果。
- 换设备或重装后，已完成、已跳过的账号不再自动展示；本机缓存不能单独保证这一点。
- 保存进度失败不阻止页面使用，同一会话内用内存避免重复弹窗；后续同步时，已完成或已跳过不能被旧的进行中记录覆盖。
- 小幅文案修改不重新触发；未来新增重要功能需要再次教育时，另行定义版本升级策略。
- 手动重看是独立的一次浏览，不把已完成账号重置成待自动引导；中途退出重看也不影响原有完成状态。

### 6.2 重看入口

拟在“我的”的设置菜单中增加“使用指南／重新查看新手引导”。选择后从欢迎卡开始，显示同样的跳过与返回控件。该入口是本方案新增项，不代表当前页面已有。

### 6.3 与实训项目首次提示协调

当前活动页已经有“点击这里，切换实训项目”的本机首次气泡，规则见[实训项目入口首次提示](实训项目入口首次提示.md)。

- 新引导运行期间临时隐藏该气泡，避免两个提示重叠；仅隐藏不算用户已了解入口。
- 用户在第 6 步实际打开切换菜单后，沿用原组件关闭并记忆气泡的行为。
- 用户在到达第 6 步前跳过，引导结束后恢复该气泡原有规则，不提前写入已关闭标记。
- 该气泡继续按本机记忆，与新引导的账号状态分开维护。

## 7. 开发拆分建议

1. **注册识别与状态契约**：确认认证响应中的新账号判定；设计按账号存储、读取和更新引导进度的接口，并定义老用户迁移规则。
2. **全局引导组件**：实现六阶段配置、页面切换、目标定位、高亮、提示卡、进度、退出与恢复；不为每个页面复制一套控制逻辑。
3. **页面接入**：为编辑资料、地图地点、帖子卡片、发布入口、活动入口、模式切换菜单和项目卡片提供稳定的目标标识与就绪条件。
4. **业务操作衔接**：接入资料保存、发布中的状态以及原有离页保护，让用户自主操作后可以回到引导。
5. **提示协调与重看**：接入已有实训气泡的临时抑制逻辑，增加手动重看入口，处理现有昵称 onboarding 页的入口归并。
6. **验证**：覆盖首次注册、原任务回跳、跳过、中断恢复、无数据、网络失败及移动端布局。

阶段推进只控制引导，不代替原页面提交资料、发布内容或访问第三方网站。接口名、存储字段和组件命名留到实现设计时确定。

| 欢迎页跳过 | 留在地图，再登录或换设备不再自动弹出 |
| 中途跳过 | 停留当前页面，保存跳过状态，不强行回首页 |
| 不填资料、不发布、不点赞 | 仍可走完整个流程并完成引导 |
| 主动修改资料或撰写帖子 | 遮罩收起，原页面可正常操作；继续引导不丢失输入 |
| 保存失败、发布结果未确认 | 沿用原页面处理，不能假成功或强行切页 |
| 地图无帖子、活动和项目为空 | 正常说明入口，可继续或结束，不展示假数据 |
| 页面加载失败或目标被移除 | 可重试、继续或跳过，无空白高亮和无限等待 |
| 中断、刷新、再次进入地图 | 可以主动继续；不强制跨页恢复；关闭邀请后不再自动提示 |
| 上一步与系统返回 | 阶段切换正确；子面板优先关闭；不意外回到注册登录页 |
| 切换账号、重装、换设备 | 账号间状态独立，已完成和已跳过状态一致 |
| 实训阶段 | 从活动页标题菜单进入，不出现不存在的报名承诺 |
| 原有实训首次气泡 | 引导期间不重叠，未学到切换入口时不误记为已了解 |
| 手动重看后中途退出 | 原有完成／跳过状态不被重置 |
| 320、390、430px 与桌面宽度 | 提示不溢出，不遮挡目标；安全区、键盘与滚动正常 |

## 9. 效果观察

如项目接入行为统计，建议仅记录引导曝光、开始、阶段到达、阶段继续、跳过位置、完成和重看，不记录用户输入的资料或帖子正文。

主要观察开始率、各阶段退出情况、完成率，以及引导后是否能自行再次找到编辑资料、发布、活动与实训入口。引导完成与真实功能使用应分开统计，避免把“点击下一步”误认为用户已经发布或参加活动。
