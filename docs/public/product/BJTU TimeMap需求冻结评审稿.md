# BJTU TimeMap 需求分析与产品设计文档

## 项目背景

校园地标、建筑、食堂与公共空间承载着学生的日常生活和共同记忆，但地点介绍、照片、学生分享与活动信息往往分散。BJTU TimeMap 以校园地图和地点为线索，将地点资料、用户帖子与校园活动连接起来，并增加实训项目展示入口，方便同学了解和体验项目成果。

### 需要解决的问题

1. 校园地点资料分散，难以从地理位置直观了解地点及相关内容。
2. 学生分享与具体地点缺少关联，校园记忆不便发现和讨论。
3. 活动的时间、地点和参与方式不够集中，用户提交活动缺少统一入口。
4. 实训成果分布于不同仓库或体验网站，缺少统一展示与访问入口。

### 用户角色与边界

| 角色 | 主要能力 | 使用边界 |
| --- | --- | --- |
| 游客 | 浏览公开地图、地点资料、帖子、校园活动和实训项目 | 写操作需登录；不得查看他人私人记录 |
| 普通用户 | 发布帖子、互动、提交活动、管理个人资料与自己的内容 | 不得维护公共地点、直接发布正式活动或修改他人内容 |
| 管理员 | 具备普通用户能力，并维护公共内容、处理举报和审核活动投稿 | 管理操作需经过服务端权限校验并保留必要记录 |

产品面向北交大学生使用。普通注册账号不应被默认展示为已通过学籍认证；是否增加学校身份验证不纳入本次默认范围。

### 平台与地点范围

产品以手机使用为主要场景，交付形态包括手机浏览器和 Android App。浏览、账号及公共业务数据使用同一业务服务；拍照、定位、保存和分享允许按平台采用不同方式。具体必验平台见第10节。

校园地图和地点发帖以北京交通大学主校区为主要范围。活动允许使用团队维护的特殊地点，不能因此将全部活动地点自动开放为帖子发布地点。多学校、多校区运营不作为本次承诺。

### 一级入口

底部导航统一为“地图、广场、活动、我的”，默认进入地图。

| 一级入口 | 主要内容 | 主要后续操作 |
| --- | --- | --- |
| 地图 | 校园地标、关联帖子与地图内容 | 地点面板、地点简介、帖子详情、在此发布 |
| 广场 | 用户帖子双列列表 | 排序、地标筛选、帖子详情、发布帖子 |
| 活动 | 校园活动；可切换到实训项目模式 | 活动详情、提交活动；项目浏览和外部体验 |
| 我的 | 个人资料、我的发布、我的收藏、我的提交 | 编辑资料、查看自己的记录、活动收藏、账号操作；管理员可进入管理端 |

实训项目复用活动一级入口内的内容切换，不新增第五个底部导航。公共地点资料、正式活动和实训项目不作为普通用户帖子混入广场。

###  关键浏览链路

1. 地图 → 点击或搜索地标 → 地点底部面板 → 帖子/活动/地点简介与照片。
2. 地点面板 → 在此发布 → 自动带入该地点的帖子编辑页。
3. 地点面板 → 查看全部帖子/活动 → 进入对应列表并带入地点筛选。
4. 广场 → 帖子详情 → 评论、收藏、分享或举报。
5. 活动 → 提交活动 → 我的提交 → 查看审核结果；通过后可进入公开活动。
6. 活动入口 → 切换实训项目 → 全部项目/人气榜 → 项目链接或体验网址。

关闭地点面板后保留地图位置与缩放；从帖子详情返回列表时尽量恢复原排序、筛选和浏览位置。

###  发布入口

广场发布入口进入帖子编辑页，地点面板“在此发布”携带地点。校园活动模式的“＋”进入活动提交，实训项目模式不显示面向普通用户的项目投稿入口。“我的”提供个人记录管理，不强制设置帖子发布悬浮按钮。

##  核心业务规则

### 帖子与地点

- 每个帖子必须且仅关联一个团队维护、当前允许发帖的预设地点。
- 帖子可为纯文字、纯图片或图文；空白内容且无图片时不能发布。
- 帖子直接公开，采用举报与事后处理机制；活动投稿使用单独的审核流程。
- 作者可删除自己的帖子，管理员按权限处理违规内容；他人不能以作者身份操作。
- 帖子编辑是否纳入本次交付见第10节，不将“重新发布”当作原帖编辑。
- 删除或下架后，帖子应退出地图、广场、地点公开列表及他人主页等公开展示面；收藏入口应明确说明内容不可用。
- 同一地点的多条帖子不生成校园足迹，不代表真实到访。

### 创作与草稿

- 用户可使用原图发布，也可主动生成主体贴纸；不得强制所有图片抠图。
- 图片加字支持文字内容、颜色、样式、位置、缩放与旋转调整；成图应与预览一致。
- 主体贴纸保留透明背景，可调整白色描边；识别失败可重试、换图或退回原图。
- 退出未完成编辑时提供保存草稿、放弃编辑、继续编辑选项。
- 草稿保存在当前设备，按账号区分，不承诺跨端同步；恢复草稿需要重新生成贴纸时应明确提示。
- 上传、创作生成和发布分开反馈。保存草稿、预览或保存图片均不能产生公开帖子。
- 独立下载、将创作直接设为头像不作为本次默认验收要求，个人头像通过资料编辑管理。

### 排序与互动

最新帖子按发布时间从新到旧排列。重复点赞或收藏不得重复计数，取消后同步更新状态；删除评论后不计入有效评论量。

当前服务端记录的近期热门规则作为本轮评审方案：

> 候选范围：近7天发布的公开有效帖子。热度 = 点赞数 × 2 + 有效评论数 × 3 + 收藏数 − max(0, 距发布小时数 − 24)。按热度降序，同分按发布时间降序。

冻结前须核对实际查询是否与上述规则一致，并补齐小时计算、完全同分的稳定排序以及地图是否复用同一算法。未经核对，不将代码注释视为验收通过证据。

###  匿名发布

当前代码包含匿名发布能力。建议默认关闭，由用户主动选择；匿名仅对普通公众隐藏署名，服务端仍保留真实归属以支持作者管理和违规处理。地图、广场、详情、收藏及公开主页等入口应使用一致的匿名规则，不能通过作者头像或主页跳转暴露真实身份。

### 活动与投稿

- 正式活动由管理员维护，也可来自用户投稿审核通过后的发布。
- 用户投稿未通过审核前不得进入公开活动列表或地图活动展示。
- 审核状态与活动状态分开：审核包含待审核、已通过、未通过；公开活动包含即将开始、进行中、已结束、已取消。
- 默认活动列表展示即将开始和进行中的活动，按开始时间从近到远排列；历史或取消活动可筛选查看。
- 支持全部/今天/本周时间筛选、活动状态筛选及地点筛选；时间按北京时间解释。
- 活动详情展示标题、封面或占位、介绍、时间、地点、主办方、来源及参与方式；可进入地图查看地点。
- 参与方式使用说明或外部链接，不提供站内报名及支付。
- 未通过投稿显示原因，允许作者修改后重新提交；待审核和已通过投稿的修改、撤回规则见第10节。
- 公开活动可收藏和取消收藏，个人入口可回顾已收藏活动。

### 实训项目

- 项目由管理员统一维护，无须关联校园地标，不套用活动时间、审核或帖子发布规则。
- 项目名称、简介为必要内容；封面、小组名称、人数、项目链接和体验网址可选。
- 项目链接可指向代码仓库或介绍页，体验网址指向可访问的产品；未配置时隐藏相应按钮。
- 全部项目按管理员设置的展示顺序升序排列；人气榜按点赞数降序排列；同值按项目名称中文排序，再按唯一标识稳定排序。
- 公众仅可查看已上架项目；未上架项目仅在授权管理范围可见。
- 登录用户可点赞或取消，同一用户对同一项目最多保留一个有效点赞；项目点赞与帖子点赞独立计算。
- 人气榜按全量已上架项目计算，不能仅对截取的一部分项目排序。

### 账号、权限与举报

- 普通用户采用手机号验证码登录，管理员另有密码登录方式；首次登录建号与注册限制见第10节。
- 发布、互动、活动投稿与项目点赞等写操作需登录；登录失效时明确提示。
- 我的收藏、草稿和投稿审核记录仅向本人开放，不向其他普通用户公开。
- 举报进入待处理记录，不因举报成功自动下架内容。
- 管理员处理举报时记录处理结果及原因；必要操作记录管理员、对象、时间和动作。
- 权限校验不能仅依靠隐藏按钮，普通用户直接请求管理操作也应被拒绝。

##  用户故事与验收标准

### US-01 从地图了解校园地点

作为学生，我希望从地图进入地点，查看简介、相关照片及帖子和活动，了解该地点承载的校园内容。

1. 搜索和点击地标打开对应地点面板，不出现地点名称与内容错配。
2. 地点简介页可浏览资料、封面和相关照片，支持大图查看与返回。
3. 历史照片显示已有年代和来源；不明信息不编造，缺少资料时显示空状态。
4. 无帖子或活动不妨碍地点基础资料浏览；允许发帖的地点仍提供发布入口。
5. 从面板进入列表时携带正确地点筛选；关闭面板后地图位置与缩放不重置。
6. 缺少有效坐标或地点不可用时，不执行错误定位，显示合理提示。

### US-02 发布地点内容并恢复草稿

作为学生，我希望关联地点发布文字或图片，并在中断编辑后恢复草稿。

1. 必须选择一个可发布地点，从地点面板进入时正确预填。
2. 纯文字、纯图片、图文可按确认后的限制发布，空白内容不能发布。
3. 发布成功后对应地点、广场和我的发布可查到同一帖子，无人工待审核状态。
4. 上传失败或网络异常时不能提示成功，重复提交不产生重复帖子。
5. 退出时可保存草稿、放弃或继续编辑；保存后在当前设备同一账号可恢复。
6. 作者可删除自己的帖子，他人无权删除；删除后公开入口同步处理。
7. 若匿名功能通过评审，默认非匿名；匿名发布后各公开入口均遵守确认后的身份隐藏规则。

### US-03 互动并发现帖子

作为学生，我希望在广场或地点列表发现内容，并通过点赞、评论、收藏和分享参与交流。

1. 广场以双列展示用户帖子，提供热门和最新排序，首次默认热门。
2. 可搜索并筛选地标，清除筛选恢复全部；多选按确认后的组合规则生效。
3. 列表、地图和收藏入口打开同一帖子详情，不回落到其他帖子。
4. 点赞和收藏可取消，重复请求不重复增加计数；收藏可在个人入口查看。
5. 评论附属于帖子详情，支持评论、回复和删除自己的评论；其他用户不能删除。
6. 分享使用平台支持的方式，取消分享不显示错误成功信息；不可分享时给出可理解的替代提示。
7. 排序对互动撤销、评论删除、时间变化及内容下架保持一致。

### US-04 浏览并收藏校园活动

作为学生，我希望了解活动安排和参与方式，并查看举办地点或收藏活动。

1. 活动列表和详情的标题、时间、地点和状态一致。
2. 时间、状态及地点筛选生效，可清除地点筛选；结束和取消活动有明确状态。
3. 从活动进入地图能定位正确地点；地点不可定位时有明确提示。
4. 收藏与取消收藏保持一致，个人活动收藏入口可查看结果。
5. 必要信息缺失的活动不能正式发布；不出现站内报名和支付流程。

### US-05 制作图片文字与主体贴纸

作为学生，我希望给图片加字或提取主体贴纸，用于地点内容创作。

1. 支持原图直接发布，生成贴纸由用户主动触发。
2. 图片文字可编辑、移动、缩放和旋转，清空后不残留在结果中。
3. 创作结果与预览一致；主体贴纸保留透明区域，描边开关生效。
4. 生成失败可重试、换图或返回原图；处理中不误用未完成的结果发布。
5. 创作预览和草稿保存不自动创建帖子；最终发布仍需关联地点。
6. 多主体选择、精细边缘调整等能力若未单独确认，不作为默认验收项。

### US-06 过去与现在拼图（已取消）

保留原编号供追溯，本次不实现和验收新老照片组合、布局切换、年份合成及拼图导出。地点照片浏览由US-01覆盖。

### US-07 在地图浏览关联内容

作为学生，我希望在地图中发现与地点关联的照片、主体贴纸及文字内容，并进入对应帖子。

1. 地图按地点聚合内容，缩放或展开不改变帖子与地点归属。
2. 照片或贴纸点击进入对应帖子，透明主体可正确显示。
3. 文字弹幕来自符合公开条件的文字帖子，并可关闭；具体范围及数量按第10节冻结。
4. 删除或下架内容退出地图展示；卡片偏移不改变实际地理关联。
5. 不展示由发帖生成的个人足迹点，不将帖子位置表述为真实到访轨迹。

### US-08 举报并管理公共内容

作为用户，我希望举报不当内容；作为管理员，我希望处理举报、审核投稿并维护公共资料。

1. 举报成功进入管理端待处理列表，不自动下架内容。
2. 处理结果及原因可记录，重复处理或状态变化时给出明确反馈。
3. 下架帖子退出所有公开展示入口，不能通过旧链接继续正常浏览。
4. 管理员可维护地点、活动、实训项目并审核投稿；普通用户无权操作。
5. 管理操作保留必要记录，可识别操作者、对象、时间和动作。
6. 评论举报及具体处理方式按第10节确认后的范围验收。

### US-09 浏览实训项目并互动

作为学生，我希望集中查看同学的实训项目、访问项目资料和体验网站，并为喜欢的项目点赞。

1. 从活动入口切换到实训项目，可查看全部项目和人气榜，切换不新增底部导航。
2. 公众仅看到已上架项目；项目名称、简介及已提供的团队信息展示正确。
3. 封面或团队资料缺失时显示合理占位，不编造人数或成员信息。
4. 已配置的项目链接与体验网址显示正确，未配置时隐藏相应入口。
5. 未登录点赞引导登录；登录后可点赞及取消，重复操作不增加重复票数。
6. 全部项目与人气榜遵守第5.6节排序；取消点赞后计数和排名保持一致。
7. 管理员新增、编辑、排序和上下架后，公众再次获取列表时展示对应结果。
8. 无项目时显示空状态，加载失败可重试，不用演示点赞数替代真实数据。

### US-10 管理个人资料和记录

作为用户，我希望编辑个人资料，并回顾自己的发布、收藏和活动提交。

1. 我的页面展示当前账号的头像、昵称和简介；可修改资料并在重新读取后保留。
2. 我的发布、我的收藏、我的提交按账号隔离，不能展示其他用户的私人记录。
3. 活动收藏有明确入口；不可用的收藏内容不跳转为其他内容。
4. 退出登录后清理当前会话及私人展示，重新登录另一账号不串用旧记录。
5. 管理端入口按角色显示，服务端同时校验权限。

### US-11 提交活动并查看审核结果

作为用户，我希望提交校园活动并查看审核情况，以便分享可靠的校园信息。

1. 活动提交入口与帖子发布入口区分，必须登录后提交。
2. 提交时校验确认后的必填信息，失败不产生虚假的成功记录。
3. 待审核投稿仅向作者及授权管理员开放，不进入公开活动列表。
4. 我的提交可查看待审核、已通过、未通过记录及相应结果。
5. 审核通过后产生可关联的公开活动，未通过显示原因并可修改重提。
6. 待审核修改撤回、已通过后变更和重新审核按第10节确认后的规则验收。

## 异常处理与质量要求

1. 列表、详情、地图和个人入口使用一致的对象标识与权限规则，内容不存在时明确告知，不替换成其他对象。
2. 加载中、空数据、无筛选结果、权限不足、网络失败分别有可理解的反馈；可恢复的读取失败提供重试。
3. 相机、相册和定位在使用时申请必要权限；用户拒绝后仍可使用不依赖该权限的浏览功能。
4. 不将技术异常栈直接当作主要用户提示，不将开发验证码投递模式描述为真实短信已送达。
5. 存在离线缓存时说明内容可能过期，不能以缓存显示推断写操作成功。
6. 外部项目或活动链接仅接受有效HTTP/HTTPS地址；不可用时允许返回应用，不承诺第三方网站持续可用。
7. 公开展示素材有来源记录，历史年代不明时如实标注；不公开他人的草稿、投稿隐私和账号敏感信息。
8. 页面在目标手机尺寸下可操作，主要按钮不被键盘、弹窗或底部导航遮挡；
