## 1. 规则与数据基线

地点类别决定“看什么”，展示级别决定“默认何时出现”，碰撞策略决定“当前能放下多少”。地点级别表示默认显示优先级，不代表文化价值。

按用户最新确认，只纳入[分类资料](../BJTUTimeMap_校园地点分类资料.md)中的 26 个具体地点，不纳入茅以升坐像、郑振铎铜像、留园。校园总入口“北京交通大学”独立计算，不是第 27 个可发帖地点。

| 逻辑视图 | 普通模式的候选 | 累计具体地点数 |
| --- | --- | ---: |
| 校园周边 | 仅校园总入口 | 0 |
| 全校概览 | 一级 | 6 |
| 校园局部 | 一级＋二级 | 17 |
| 近距离 | 一级＋二级＋三级 | 26 |

累计数量指数据完整且全部落入视野时的候选，不承诺屏幕同时画出 26 个名称。实际还要扣除停用、坐标无效、视口外和被避让／聚合的地点。

本方案替代[旧帖子展示方案](地图帖子展示UI优化与实现说明.md)中的学校→区域→具体地点缩放分段；本轮没有维护区域节点的必要。旧结构字段保留兼容，不据此虚构区域。

## 3. 现有代码与字段兼容

核对本地源码后的关键现状：

- `server/src/migrations/026_map_display.sql` 已有 `display_level: 'school' | 'area' | 'place'`、`min_display_zoom`、`display_priority`、`parent_place_id`。
- `server/src/mapRoutes.ts` 已返回这些字段，并提供公开帖子数量及热门预览；`/api/map/places` 目前只接收单个 `category`，最多返回 500 条并带 `truncated`。
- `app/src/api/client.ts` 的 `listMapHierarchy` 只保留 ID、名称、旧 displayLevel 和父级；`ApiPlaceListItem` 没有数字展示级别。首页仍通过 `listPlaces` 构造标记。
- `MapHandle` 已有投影、中心、zoom 和尺寸方法，尚无统一视图订阅与视野边界接口。三个在线适配器的建图 effect 依赖 markers，直接按缩放更新 markers 会有重建地图的风险。
- 前后端当前类别为“地标、教学楼、活动场地、运动场地、食堂”，与新资料不同。

用户建议的数字 `displayLevel` 概念成立，但该字段名已被结构层级使用。推荐本轮新增 **`displayTier: 1 | 2 | 3`**，数据库为 `display_tier`；不改变旧 `displayLevel` 的类型。否则会破坏已有校园简介判断、管理接口与地图层级缓存。

| 字段 | 拟定含义 | 规则 |
| --- | --- | --- |
| `displayLevel`（已有） | 结构角色，school／area／place | 校园总入口为 school；26 个具体地点均为 place |
| `displayTier`（新增） | 具体地点的默认出现级别 | 具体地点为 1／2／3；school／area 为 null |
| `displayPriority`（已有） | 同级别内避让排序 | 不改变出现门槛；首轮沿用已维护值，未知为 0 |
| `minDisplayZoom`（已有） | 特定地点出现门槛覆盖 | 通常 null；若使用，按 provider 配置解释并明确记录，不能误当统一物理尺度 |
| `parentPlaceId`（已有） | 经维护确认的内容归属 | 不从距离、名称或展示级别推导 |
| `allowPosting`（拟新增） | 是否可被新帖选择／提交 | 具体地点 true，校园／区域 false；前后端共同校验 |

若未来统一把 `displayLevel` 改为数字，应先将旧角色迁为 `nodeType` 并版本化所有调用方；本轮不做此破坏性更名。

## 4. 数据迁移与分类切换

新增迁移文件，使用仓库下一个可用版本并注册到 `server/src/db.ts`；不改写已经执行的 026 迁移。

建议迁移步骤：

1. 盘点实际数据库节点、学校／校区归属、分类和帖子外键。资料表不等于数据库已有全部 26 条，不按名称猜 ID。
2. 加入 nullable `display_tier smallint`，约束取值只能为 1／2／3 或 null。先不对旧数据施加“所有具体地点必须有值”的强约束。
3. 建立经人工核对的地点 ID→目标类别／tier 配置；按上表回填。缺失地点按资料导入并校验坐标系；同名／重复记录先核对，不能自动合并或搬迁帖子。
4. 为既有校园总入口配置 school、tier=null、allowPosting=false。若不存在，使用真实维护数据创建；`previewHierarchy` 下的虚拟学校节点仅为预览，不作为生产迁移来源。
5. 更新分类 CHECK、`server/src/placeCategories.ts`、前端 `PLACE_CATEGORIES`、管理表单、筛选和发布选择器。已核对的运动场地→运动场；活动场地中的指定四项→校园地标；湖泊／园林／道路→休闲场所；留园不纳入目标集合；其他记录逐项审核，不能把全部旧“地标”一律改成校园地标。
6. 回填完成后加角色一致性约束：本次纳管的 26 个 place 必须有 tier，school／area 的 tier 为 null；其他历史 place 未纳管前允许 tier=null，不把线上活动、外校区等记录强制塞进三级。allowPosting 默认策略按实体用途回填并校验，不能给全部历史 place 一律开放发帖。
7. 核查具体地点 26 个、分类 7／4／2／4／9、tier 6／11／9、无重复 ID／无效坐标、帖子外键仍有效，再切换首页数据源。

后端可先同时识别旧单分类参数和新多分类参数，待新版前端发布后再收紧兼容。类别值切换需要后端约束、接口和前端协调发布；不能只改按钮文案。

迁移前备份被改记录的 ID、原类别、旧层级和父级。回退先关闭新分级策略，再恢复兼容读取；有新类别数据后不能直接恢复旧 CHECK。本文不执行真实数据删除；对用户排除的两项不导入、不配置标记，如数据库已有同名记录，先核对关联内容再安排停用，不自动删除关联帖子。

## 5. API 契约

优先扩展现有 `GET /api/map/places`，避免再造平行地点来源。下面是拟新增／扩展行为，不是当前接口已支持的参数。

```text
GET /api/map/places?categories=食堂,教学楼
```

- `categories`：五类中的零到五项，以逗号分隔并 URL 编码；省略表示全部，重复项去重，非法值返回 400。类别并集在服务端过滤。
- 保留旧 `category` 单值兼容；同时传两个参数返回 400，避免不明确的覆盖顺序。
- 每个 item 新增 `displayTier`、`allowPosting`，保留旧 `displayLevel`、父级、坐标、优先级与预览。前端完整读取这些字段，不通过 `listMapHierarchy` 的四字段缓存替代。
- 26 点规模可一次加载完整校园地点，在前端做缩放、视口和碰撞处理。不要每缩放一小步发网络请求。
- 首轮只服务已明确配置的北交大数据范围；多学校启用前必须补全真实归属和服务端范围参数，不因顶部切换学校就假定地点接口已隔离学校。
- 现有 500 条上限与 `truncated` 必须保留并消费。当前 26 点应为 false；若为 true，不把响应当完整全集，应补充分页／收窄范围或提示数据不完整。

单条扩展响应示意（仅展示字段结构；ID、坐标继续采用真实资料）：

```ts
interface MapPlace {
  id: string
  name: string
  category: '校园地标' | '食堂' | '教学楼' | '运动场' | '休闲场所'
  latitude: number | null
  longitude: number | null
  enabled: boolean
  displayLevel: 'school' | 'area' | 'place'
  displayTier: 1 | 2 | 3 | null
  allowPosting: boolean
  displayPriority: number
  minDisplayZoom: number | null
  parentPlaceId: string | null
  postCount: number | null
  previews: MapPostPreview[] // 复用并补齐现有公开帖子 DTO
}
```

`postCount` 为服务端有权限查看的真实计数；未知时 null，不能用已取到的 previews 长度冒充。校园总入口的汇总只按已维护归属统计；没有完整归属时不展示总数。首次只展示简介和照片即可，不依赖学校帖子汇总。

搜索继续基于完整有效地点接口，不能仅搜索当前已画出的 markers。发布列表只返回 enabled 且 allowPosting 的具体地点；所有新建／修改帖子入口在服务端再次校验，不依赖前端隐藏。

文字弹幕需独立候选读取或扩展现有地图接口，按有效视口、类别和公开可见性筛选纯文字帖。现有 `/api/map/posts` 按地点分页不能直接充当全视野完整弹幕池；如果逐地点读取，应合并、去重、限并发并处理部分失败。

## 6. 缩放状态与阈值配置

不在本文固定最终 zoom 数值。使用每个 provider 一份配置 `campusEnterZoom / tier2Zoom / tier3Zoom`，满足从小到大严格递增，并在支持的 zoom 范围内。逻辑视图为：

```text
zoom < campusEnterZoom                  → 校园周边
campusEnterZoom ≤ zoom < tier2Zoom       → 全校概览
tier2Zoom ≤ zoom < tier3Zoom             → 校园局部
zoom ≥ tier3Zoom                        → 近距离
```

校准流程：以 390px 手机拟合 26 个地点的校园边界，预留顶部工具栏和底部导航；确认一级六点能辨认，以此校准校园进入门槛；放大到常用建筑不拥挤时校准二级，再放大到相邻配楼和园林可辨时校准三级。随后测试 320／430px 宽、横屏、各 provider 与最大 zoom，记录配置与截图。

可增加约 0.15–0.25 zoom 的进入／退出滞回作为调试起点，避免阈值附近反复闪动。完整的三级状态必须在当前地图的最大 zoom 前可达；字体放大或小屏主要通过减少卡片和避让适配，不通过任意隐藏搜索目标应付。

## 7. 候选、筛选与搜索优先级

分两阶段处理：先决定有资格出现的地点，再决定呈现形式。

```text
完整地点数据
  → 已启用、合法坐标、当前校园归属、当前权限
  → 普通缩放候选 / 分类突破 / 搜索焦点强制加入
  → 有效视口与边缘缓冲
  → 稳定排序
  → 标签避让或地点聚合
  → 精选卡片预算与弹幕预算
```

建议选择逻辑：

```ts
function eligible(p: MapPlace, mode: ViewMode, categories: Set<string>, focusId: string | null) {
  if (!p.enabled || !validCoordinates(p)) return false
  if (p.id === focusId) return p.displayLevel === 'place'
  if (categories.size > 0) return p.displayLevel === 'place' && categories.has(p.category)
  if (mode === 'surroundings') return p.displayLevel === 'school'
  return p.displayLevel === 'place' && p.displayTier !== null && p.displayTier <= tierFor(mode)
}
```

前置范围校验还应限制为本次已纳管的具体地点与校园入口，避免旧思源碑、第二食堂、线上活动等记录未经确认就混入目标集合。此伪代码省略归属和权限前置校验，不能直接作为服务端授权规则。`minDisplayZoom` 非 null 时，仅在普通模式覆盖该具体地点默认门槛；分类／搜索不受它限制。校园总入口的普通隐藏条件不由这个字段决定。

搜索选择“知行校训碑”等三级地点时：完整搜索 → 校验有效地点 → 设置 focusId → 必要时读取单点数据 → 飞到支持的可见缩放 → 避开抽屉聚焦并打开详情。即使当前只筛食堂，选中的碑仍作为临时焦点显示，已生效类别保持不变；关闭详情／取消焦点后恢复分类和级别规则。选中点必须有可点击名称，其他预览先让位；焦点不与普通地点合成聚合。

发布后返回的具体地点、深链打开的有效地点使用同一临时焦点通道。用户拖出视野后不把焦点标记钉在屏幕边缘；清除选择或关闭详情后结束突破。

## 8. 地点碰撞与聚合

26 点无需为了规模立即引入重型聚合库，首轮可用共用屏幕空间算法：

1. 用 provider 的 project 将地点转成容器像素，以实际标签盒和触控盒判碰撞，避开头部、工具、筛选面板、抽屉与版权区域。
2. 稳定排序：选中点优先 → 普通模式 tier 小的优先 → displayPriority 降序 → 原排序 → ID。分类模式弱化 tier，优先保留匹配点；前一帧已保留项可用于同优先级稳定，不能压过焦点。
3. 优先收起帖子卡片，再尝试标签的有限上／下／左右偏移。只偏移标签或引线，不改地理锚点。间距可从 8px 起调。
4. 仍重叠的普通地点合成聚合点，以唯一 placeId 计数；选中点独立。聚合成员只来自本次已通过分类／tier 规则的候选，不能把隐藏三级点偷偷计入概览。
5. 聚合和独立地点形成互斥集合，每个地点只计一次。孤立的一个点不显示“1”聚合。
6. 点击聚合拟合成员边界并设置可用区域 padding；最大 zoom 或相同坐标仍不可分时打开成员列表，列表选择后进入焦点模式。

高德 JS API 2.0 的标注支持缩放显示范围、避让与优先级，可用于适配器优化；仓库当前加载的是 1.4.15，不能直接照搬 2.0 类名和参数，需单独核验或升级后再接入。[高德官方标注说明](https://developer.amap.com/api/javascript-api-v2/guide/amap-massmarker/label-marker)

邻近标记聚合、聚合数字随放大拆分的交互可参考官方说明；这是产品交互参考，不要求项目切换到 Google 或直接加载其库。[Google 官方聚合说明](https://developers.google.cn/maps/documentation/javascript/marker-clustering?hl=zh-cn)

| 校园局部 | 一级＋二级 | 4 | 2 |
| 近距离 | 全三级 | 6 | 2 |

这些是首轮可调预算，碰撞后可以更少；每个地点首版最多一张精选卡，避免把多帖叠层作为层级实现前提。预览沿用现有地图服务端热门顺序：近 30 天优先、点赞降序、时间降序、ID 稳定排序。地点详情的热门公式不同，不由前端擅自改成同一种。

卡片未显示不影响地点可达；没有合适图片不生成占位照片。透明贴纸保持透明，与照片共享总预算。文字开关只影响文字预算，搜索焦点和地点标签不受影响；面板遮挡时按实际剩余可见区域重新预算。

## 10. 地图适配与生命周期

建议扩展 `MapHandle` 的能力如下，方法名可在实现评审时调整：

```ts
getBounds(): { north: number; south: number; east: number; west: number } | null
subscribeView(listener: (view: MapViewState) => void): () => void
// MapViewState 包含 provider、center、zoom、bounds、size、moving
```

复用已有 project／unproject／getSize；所有 bounds 和地点坐标必须转换到统一业务坐标系，核实资料坐标来源后再转换，避免 GPS／国内 SDK 坐标重复转换。未确认坐标系的资料不能承诺精确落点。

- 将三个适配器的实例初始化与覆盖物更新 effect 分开。SDK 实例只随容器、provider 等必要条件重建，不能随 marker 数量变化重建。
- 覆盖物按 placeId 增量增加、更新、删除，统一渲染模型，避免三个 provider 各自实现一套业务规则。
- 视图事件通过 requestAnimationFrame 合并；连续手势时更新投影，移动结束统一重算候选和碰撞。若有视野请求，可从 150–250ms 防抖起调，并丢弃过期响应。
- 订阅返回清理函数，provider 切换时取消旧监听和待处理任务，防止旧地图响应覆盖新状态。
- 筛选面板开合不改变地图容器大小；抽屉沿用 `mapFocus.ts` 的可见区聚焦能力。内容变化后更新 marker extent，不能仍假定固定卡片高度。
- 每个 provider 的阈值独立校准；失败降级时保留中心、筛选和逻辑视图意图，不照搬旧 provider 不支持的 zoom。
- 离线自绘底图当前无校准投影，继续明确提示“不支持标记”；本文不把三级数据直接绘制到未经校准的 SVG 上。

## 11. 状态反馈与回归验收

地点接口失败：显示地点读取失败和重试；帖子预览失败：保留地点，提示内容暂不可用。分类无结果、视口外无结果、标签被聚合、缩放门槛隐藏是不同状态，不统一显示“暂无地点”。校园周边只有入口属于正常态。

为验证增加可读状态，例如 `data-map-view-mode`、`data-map-candidate-place-ids`、`data-map-visible-place-ids`、`data-map-cluster-members`。候选数、独立标记数、聚合数分别记录，不复用当前 marker count 表达全部含义。

| 用例 | 预期 |
| --- | --- |
| 数据一致性 | 26 个唯一具体地点，类别 7／4／2／4／9，tier 6／11／9，无已排除地点 |
| 累计层级 | 完整校园视野下候选集合满足一级 ⊆ 一二级 ⊆ 全三级，数量 6／17／26 |
| 校园周边 | 普通模式只有学校节点，进入校园后学校节点隐藏，无父子标签重复 |
| 类别突破 | 概览筛食堂可获得四个食堂候选；多类别为并集，恢复全部后重新遵守 tier |
| 搜索突破 | 食堂筛选时搜索知行校训碑，仍定位高亮并打开详情，关闭后恢复筛选 |
| 密集区域 | 思源楼及配楼不遮挡主要触控区；聚合数字按不同地点计数，点击可展开 |
| 相邻点层级 | 普通局部视图可见学生活动中心、校史馆，学活食堂／银杏大道不进入候选；近景纳入，筛选对应类别时可提前纳入 |
| 卡片预算 | 候选地点增多不等于卡片全开，卡片不足可少显示；锚点不随卡片变化 |
| 弹幕 | 关闭立即停止，移出视口候选清除，后台暂停，不影响照片与地点 |
| 生命周期 | 缩放导致候选变化时地图实例不重建；中心不跳回默认；监听清理无重复 |
| 安全提交 | 校园／聚合不出现在发帖列表；伪造学校 placeId 提交也被服务端拒绝 |
| 降级与边界 | 三个在线 provider 的三级均可达；最大 zoom 重叠有列表；离线明确不支持 |
| 数据异常 | 停用、缺坐标、权限失效目标不强制显示；truncated 不被当完整全集 |

实施时为候选选择和聚合去重增加针对性单元测试，复用 `server/tests/map-display.test.ts` 补接口字段、多分类和发布限制验证；通过实际地图交互测试校验投影与 SDK 生命周期。文档阶段只核对内容与链接，不把计划中的测试写成通过记录。

## 12. 实施拆分与完成条件

1. 数据层：确认 ID 与坐标、回填 tier、切换分类、落实校园非发帖约束。
2. 读取层：扩展地图 DTO 和多类别接口，前端接入完整数据并处理截断／部分失败。
3. 地图层：拆生命周期、加入视图订阅、实现累计候选和搜索焦点突破。
4. 展示层：统一标签、避让／聚合、卡片预算与弹幕；与[页面复刻说明](地图页面复刻说明.md)联调。
5. 实机验收：记录设备、视口、provider 和校准参数，完成上表用例后再标记交付。

完成条件是 26 点数据和校园入口真实可用、三个层级可达、筛选搜索可突破且恢复正确、触控无遮挡、发布限制在服务端生效。zoom 数值、卡片预算和像素细节允许根据实机结果调整，并回写配置及文档。
