# 北京交通大学地标数据维护手册

更新日期：2026-11-05。供内容维护与图片录入使用。共 26 个目标具体地点，另有 1 个校园总入口。本文最初由数据清单生成，2026-11-05 起手工维护；24 个地点的图片已登记（原图在仓库 `assets/place-photos/`，学四食堂、学苑餐厅暂无图片），资料中的简介／校史仍需内容负责人审核。

## 使用方式

- 先按地点 ID 查找记录，再更新简介／校史／照片；不要为了补图重新创建地点。
- 机器可读清单：[bjtu-places.json](data/bjtu-places.json)。名称、ID、分类、tier 由开发维护；队友可补 description、history、contentOwner（负责人）、lastReviewedAt（审核日期）、contentStatus（审核状态）、notes（备注），并填写 photos 中的素材信息。
- 本手册是查看与交接文档，修改手册不会自动写入数据库。修改 JSON 后运行 `node tools/build-place-handbook.mjs` 重新生成。
- 2026-11-05 说明：上面提到的 `docs/public/data/bjtu-places.json`、`tools/build-place-handbook.mjs`、`tools/update-place-content.mjs` 目前不在仓库中，本轮直接手工编辑本手册；以后补回这些文件前，不要假设能用生成器覆盖本文。
- 本轮图片登记：file 为仓库内 `assets/place-photos/` 下的原图，title 为地点名，source 为「真实照片拍摄」，yearLabel 为「2026年」、yearSort 为 2026，position 为 0。本地库的 mediaId 换个环境就无效，所以 mediaId 一栏写「线上上传后登记」，线上用 `tools/import-place-photos.mjs` 上传后再回填。
- 本地基础导入默认保留数据库已有简介和坐标；审核后的内容更新请使用管理员地点编辑接口或 `tools/update-place-content.mjs`，避免导入覆盖队友刚补充的内容。
- “已规划 ID”不等于远程已有记录：远程尚未执行本轮迁移。先核对目标环境的管理员地点列表，缺记录时交给开发导入。
- 图片走媒体上传和地点照片关联接口；不要把本机路径直接写进数据库作为图片 URL。

## 图片登记格式

每个地点的 photos 数组可填以下素材信息；file 为本地待上传路径，不会直接展示给用户：

```json
{
  "file": "素材/图书馆.jpg",
  "title": "图书馆外观",
  "source": "摄影者姓名／授权来源",
  "yearLabel": "2026年",
  "yearSort": 2026,
  "position": 0,
  "mediaId": null
}
```

封面先用 position=0，其他图片依次排序；使用有授权的照片，source 和 yearLabel 必填，不知道年代可如实填“年代不详”、yearSort=null。mediaId 在真实上传后登记，不能编造。位置、排序、分类与展示级别不随图片增减变化。

上传流程：`POST /api/media` → 取得 mediaId → `POST /api/admin/places/:id/photos`。现有 `tools/import-place-photos.mjs` 支持按规范名称匹配、单张批量上传，先运行其 `--dry-run`；管理员 token 通过环境变量传递，不写进本文件或 JSON。

本轮已排除茅以升坐像、郑振铎铜像、留园；旧库中的相关记录保留历史关联，不进入目标地图及新帖选择。

简介更新示例：将审核后的 `{"description":"简介正文","history":"校史正文"}` 保存为本地 JSON，使用 `node tools/update-place-content.mjs --api http://127.0.0.1:3007 --id <地点ID> --file <JSON路径>` 预览，确认差异后加 `--apply`。管理员 token 仅通过 TIMEMAP_TOKEN 环境变量传入。此命令不上传照片。
