# 操作失误记录：`git add -A` 把子代理进行中的改动一起提交了

> 时间：2026-09-21 17:04（Asia/Shanghai）

## 发生了什么

提交 `af9c622`（本意只是"按审核记录 19 给 ① 改名 + 更正注释"）实际包含三个文件：

```
scripts/gates/m4/gate-server.sh    |  6 +++---
scripts/m4/backup-restore-joint.sh | 17 ++++++++++++++++-
server/src/index.ts                | 20 ++++++++++++++++++++   ← 不是我这轮改的
```

`server/src/index.ts` 那 20 行是**子代理正在进行中**的 barrier 接线
（`import { acquireMediaMutationLock, isBarrierTimeout } from './mutationBarrier.ts'`、
在 media INSERT 前取锁、把锁超时翻成 503）。

原因：我用了 `git add -A`，而当时**有一个后台子代理正在同一个仓库里改文件**。

## 为什么这值得单独记

1. **提交的内容与提交信息不符**：提交信息说"改名"，里面却混进了 barrier 接线。
   将来有人 bisect 或读历史会得到错误结论。
2. **子代理仍会自己提交**：我给它下的指令包含"完成后 git commit"。
   于是同一个改动可能被提交两次，或者它 commit 时发现工作区已被清空而困惑。
3. **半成品进了历史**：那 20 行是否完整、是否能通过 typecheck/build 还不知道
   （子代理还没汇报）。**不能因为"已经提交了"就当作已完成**。

## 纪律（本项目应新增的一条）

> **在有后台代理改同一个仓库时，提交只能用显式路径**（`git add <path>`），
> 绝不用 `git add -A`。

理由：`-A` 的语义是"把我看不见的所有改动都收进来"，
而"有并发写入者"时，"我看不见的改动"恰恰是**别人的半成品**。
这与本项目已经确立的"多进程协作时不要用模糊的操作符"是同一条纪律
（例如不能 `rm -f "$VAR"*` 而要先确认变量非空）。

## 处置

- 不重写历史（`af9c622` 保留）：把已发生的事如实记下来，比掩盖更有价值；
  而且重写历史会影响已推送的远程分支。
- 等子代理汇报后，**验证 `index.ts` 的接线是否完整可用**（typecheck + build），
  再决定是否补一个修正提交。
- 后续本轮及今后提交一律改为 `git add <具体路径>`。
