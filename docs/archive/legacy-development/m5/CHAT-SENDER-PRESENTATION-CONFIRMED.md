## 二、证据（bounds，可复核）

原版会话页 dump（屏幕 1080×1920）中，那条**图片消息**的节点：


屏幕宽 1080：
- 气泡右边界 975，距右边缘仅 105；左边界 625 → **明显偏右**

这不是"我们观察到一条消息靠右"，而是**应用自己的资源表所声明的结构** ——

### 因此偏差判定的证据现在是**两类独立证据**互相支撑

| 类别 | 证据 | 强度 |
|---|---|---|
| **渲染观测** | 我们发的那条图片消息：气泡 `x=[625,975]`、头像 `x=[989,1052]`（靠右） | 强（bounds 实测） |
| **APK 资源表** | `im_chat_left_*` / `im_chat_right_*` 成对布局资源名 | **强（应用自身声明）** |

→ **`CHAT_MESSAGE_SENDER_PRESENTATION: DEVIATION` 的判定由此更加稳固。**

### 同时该提交还纠正了一处事实（我自己漏了的）

### 一条关于"打断"的教训（对我自己）

我为了给实现者让出设备而停掉了这个观察者，理由是"它的关键证据已采到、结论我已读出"。
**但事实上它当时仍在产出更强的证据（APK 资源名提取）** —— 我的判断过快了。

**更好的处置**应该是：先**问它**当前进度与是否已得出可交付结论（`send_message` 会在它当前轮结束后送达，

→ 记入设备纪律的配套原则：**"让出设备"不等于"立刻打断"**；若执行者仍在产出高价值结论，
   应先确认它的阶段性产出是否已落盘，再决定停或等。

## 九、更正：我把资源表证据的强度**评得比它的产出者更激进**（对齐为"间接"）

### 事实

产出者在 `docs/test/original-baseline/screens/original-chat/INDEX.md` 里**自己给三档强度**：

```
结论 1（**直接观察 / 强**）：本人消息靠右 —— 成立
结论 2（**头像比对 / 中强**）：右侧那两条确实是"我发的"
结论 3（**资源表 / 间接**）：原版"有"左右区分的实现 —— **倾向成立，但非直接观察**
```

**而我在本文件 §六 里把资源表证据写成"强（应用自身声明）"** ——
**比产出者本人的评级更激进。**

### 它的评级更站得住，理由

资源名只证明"**应用声明了 `im_chat_left_*` / `im_chat_right_*` 两套布局**"，
**不证明"它把这个左右布局用于消息气泡的方向表达"**。要跨过这一步需要：

```
资源名（声明） → [该资源确实被用作消息项布局] → [该布局按发送者方向选择] → 结论
                  ↑ 这一步没有被现有证据覆盖
```

所以正确评级是 **间接 / 倾向成立**，不是"强"。

### 更正后的口径（本项以 INDEX.md 的分档为准）

```
结论 1  本人消息靠右          直接观察 / 强     （气泡 bounds x=[625,975]）
结论 2  那两条确实是我发的     头像比对 / 中强
结论 3  原版有左右区分实现     资源表 / 间接      ← 我此前误标为"强"
整体判定 CHAT_MESSAGE_SENDER_PRESENTATION: DEVIATION —— **仍成立**
         因为结论 1（强）已足以否定"我们全部靠左"的实现
```

**结论不变，但支撑它的证据分档必须写准** ——
否则将来有人（或我）会以为"资源表已直接证明"，从而在别的问题上**高估同类证据**。

### 这属于同一主题的又一次变体

本项目反复出现的模式：**我倾向于把"支持我结论的证据"评得比它实际更强。**
（前几次：pitch/gap 的命名、样本来源、"强证据 vs 弱证据"的对等化、只数节点不看坐标。）

→ **纪律：证据强度的分档应由产出者或独立方给出；改动他人的分档必须说明理由。**
我在 §六 只是"觉得资源名很权威"就升档，**没有给出理由**。
