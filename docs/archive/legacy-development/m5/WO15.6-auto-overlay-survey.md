# WO15.6：全 app 排查"**首次进入自动弹出**的阻断式覆盖层"

> 时间：2026-09-22 10:13｜Round 266
> 起因：WO#15 期间发现地图页的地理授权弹窗会**跨 Gate 残留**，导致 WO#14 门禁偶发失败。
> 问题：**还有没有别的同类**（自动出现、全屏、会挡住后续门禁）？

## 〇、先把"搜索范围"证明出来（否定性结论的前提）

审核纪律（本轮刚沉淀的 Source validity）：**要声称"没有别的"，必须先证明查了该查的全部。**
```
扫描范围：app/src 下**全部 35 个 .tsx 文件**（Get-ChildItem -Recurse -Include '*.tsx'）
匹配模式（**枚举**，不是凭印象）：modal / Modal / overlay / Overlay / mask / Mask / dialog / Dialog / sheet / Sheet

  CampusScreen.tsx      mask=1  overlay=2

```
⚠️ 局限（不夸大）：本次只按 **class 名**匹配。若某个覆盖层用了不含上述词的 class 名
（例如 `.tipBox` / `.guideLayer`），**本排查不会命中**。
⇒ 所以结论的准确措辞是「**按枚举的 class 名模式、在全部 35 个 tsx 里**没有发现其它自动覆盖层」，
  而**不是**"绝对不存在"。

## 一、逐个判定：**自动 vs 用户触发**（只有自动的才可能跨 Gate 残留）

| 文件 | 覆盖层 | 触发方式 | 会不会跨 Gate 残留 |
|---|---|---|---|
| **MapScreen** | `.map__modal`（地理授权） | ⚠️ **自动**：`if (!granted || forceAsk) setTipOpen(true)`（行 316）；另 deny 时行 577 也会开 | ✅ **会** → **已修**（`dismiss-blocking-modals.mjs`） |
| LoginSelectScreen | `dialogOpen` 弹窗 | 用户触发：**只在 `login()` 里且 `!agreed` 时** `setDialogOpen(true)`（行 27–31） | ❌ 只有门禁去点「登录」才会出现 |
| UpgradeDialog | `.up__mask` 全屏遮罩 | **路由驱动**：`App.tsx:118 {root === 'upgrade' && <UpgradeDialog />}` | ❌ 只有导航到 `#/upgrade` 才出现 |
| CampusScreen | `.switcher__mask` / overlay | 用户触发（点顶部学校选择器） | ❌ |
| ChatScreen | `mask` / `sheet` | 用户触发（如 @ 面板 / 附件） | ❌ |
| FeedDetailScreen | `Mask` / `Sheet` | 用户触发（评论面板） | ❌ |
| Drawer.tsx | `mask` | 用户触发（点三横线菜单） | ❌ |

## 二、结论

```
**"首次进入自动弹出的全屏覆盖层"这一类里，只有 1 个成员：地图页的地理授权弹窗。**
 ⇒ WO#15 期间修掉的正是它；**没有发现第二个需要加进 dismiss 列表的**。
```

**连带确认**：我在 `dismiss-blocking-modals.mjs` 的容器选择器列表里保留了
`[data-blocking-modal]` 这个**通用钩子**（目前无元素使用它）。
它的用途不是"现在有用"，而是**给未来同类弹窗一个显式登记位**：
以后新增自动覆盖层时，只要给容器加上 `data-blocking-modal`，
就会被收尾清理自动认出来 —— 而**不**需要再回来改清理脚本。
（同时该脚本仍保留 `.map__modal-wrap` / `.map__modal` 这类**具体**选择器，
 因为"按已知容器找"在 WO#15 里已被证明比"猜几何形状"可靠。）

  若将来出现**必须滑走/必须点遮罩**才能关的弹窗，需要扩展该脚本
  （且扩展后仍要遵守"SELFTEST 先证明它真的会生效"的纪律 —— 见 WO#15 的教训）。
