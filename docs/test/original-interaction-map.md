# 原版交互清单（逐按钮实测）

> 方法：在 MuMu 上打开原版 app，对每个可点击元素执行「截图 → `adb shell input tap` → 截图 → 比对」，
> 再用视觉模型识别点击后的界面。工具：`tools/probe.ps1`。
>
> **前置条件（重要）**：模拟器的逻辑显示必须处于 `rotation 0`。
> 此前设备是 `rotation 1`（横屏坐标系），截图是竖屏图像，两者需要换轴换算（图像点 (px,py) ↔ 逻辑点 (py, 1080−px)），
> 点击极易点偏；`wm set-user-rotation` 在本机不可用，用 `settings put system accelerometer_rotation 0`
> + `settings put system user_rotation 0` 后才落到 rotation 0，此时截图坐标 = 点击坐标。

## 十二、个人页左上角抽屉（原版实测）

点个人页左上角「三横线」会从左侧滑出抽屉，**8 项**（顺序即原版顺序）：

```
账号与安全 / 编辑资料 / 校园认证 / 隐私设置 / 黑名单 / 版本信息 / 联系我们 / 扫一扫
```

demo 已按此实现真抽屉（`components/Drawer.tsx`），并为每项建了二级页
（`#/account` `#/verify` `#/privacy` `#/blacklist` `#/about` `#/contact`，扫一扫走 `#/scanner`）。

**重要限制**：抽屉里的菜单项在原版里大多会打开
`com.xingin.xhsreactnative.ui.XhsReactActivity`（React Native 页面）。
在本机环境下（未登录、无后端）这些页面渲染为 20KB 左右的空白页，
**无法取得它们的真实界面**——因此 demo 的六个二级页用的是自拟内容，
只保证入口与文案一致，不敢声称内部结构还原。

同理，以下页面在本机取不到真实界面，demo 内容为自拟：

| 页面 | 原因 |
|---|---|
| 群聊 `campusx://group` | 需要会话参数，deep link 打开是空页 |
| 群公告 `campusx://announce` | 同上 |
| 抽屉各二级页（账号与安全/校园认证/隐私设置/黑名单/版本信息/联系我们） | 打开的是 RN 页面，未登录+无网络时渲染空白 |

## 十七、设备端截图的「渲染冻结」坑

给 30 个路由批量截图时出现过一次：**连续 30 张截图的哈希完全相同**。

原因：MuMu + WebView 组合下渲染器偶发冻结——**DOM 在更新**（CDP 断言全部通过、路由确实切换了），
但 `screencap` 一直返回同一帧缓存画面。

- 排查线索：文件大小与 MD5 完全一致（1699195 字节 ×30）；
- 恢复方式：`am force-stop` + 重启应用（与更早那次"应用点不动"是同类现象）；
- **对验证的影响**：CDP 类断言（路由回归 34、交互闭环 19）读的是 DOM，不受影响，所以
  验收套件一直是绿的而截图是陈旧的——两者必须分开看；
- 已在 `tools/device-shots.ps1` 加入冻结守卫：连续相同帧自动重启应用并重截该页。

## 十四、个人资料页（原版实测：个人页四个入口都指向它）

| 卡片 | 内容 |
