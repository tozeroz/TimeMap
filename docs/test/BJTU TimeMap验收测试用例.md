# BJTU TimeMap 验收测试用例

## 使用说明与验收范围

覆盖US-01至US-11，其中US-06已取消，只检查取消范围与正常照片浏览边界，不设计拼图成功用例。其余10条用户故事逐条映射到用例，另补导航、账号、跨端和异常处理。

用例依据需求文档中的用户故事和验收标准编写，按US编号建立追溯关系。第3节给出本轮用例设计所采用的测试参数、判定方法和范围限制；这些约定用于明确预期结果，不表示测试已经执行或项目已经通过验收。原需求中的条件性条款按本文件的范围说明处理，不据旧图或已有页面扩大验收范围。

P0为主要闭环、身份权限、数据一致性等关键项，P1为重要边界与异常，P2为体验项。优先级是测试排期建议，不自动构成业务范围增减。

每条用例均在一轮测试数据快照上执行；对批量列举的入口或操作，必须在证据中逐项记录，有一项未通过不能把整条判为通过。前置数据准备、固定时钟和接口重放仅用于隔离的测试环境，不在正式环境中修改业务数据或时间。

### 筛选、排序与地图约定

|项目|本轮测试参数与判定方法|
|---|---|
|地标筛选|多选采用“属于任一所选地点”的合并结果，与当前排序同时生效；清除地点筛选后恢复全部地点|

|地图排序|地图聚合预览与广场热门分别核对，不要求共用同一热度公式；本轮重点验证公开状态、内容归属、点击对应及展示配置|
|地图显示参数|执行前导出候选版本的地点层级、最小显示级别、优先级及聚合配置为测试输入，按该快照在阈值前/恰好/后比较；阈值、卡片数量和帧率不是本文件新增的产品指标|
|弹幕|验证公开纯文字来源、区域归属及开关效果；不验未经需求规定的固定播放频率和同屏数量上限|
|返回列表|同一会话中从详情正常返回时，比较返回前的地点筛选、排序和可见帖子；允许图片重新加载，不要求像素级滚动误差或应用重启后的恢复|

广场与地点局部热门可能采用不同时间衰减实现，FED-010/011明确以广场接口作为公式验证对象；若需要统一所有入口的算法，应先同步需求与专项用例，不将未约定的跨入口排名相同作为本次通过条件。

### 验收范围与测试限制

本轮不验收过去与现在拼图、校园足迹、路线导航、站内报名支付、原帖在线编辑、独立下载创作/直接设头像、跨设备草稿同步，以及未单独纳入的多主体选择或精细边缘调整。聊天等历史功能不作为本次核心用例的准出要求。

本文件不设定未在需求中规定的响应时间、并发数、弹幕频率或历史数据清理周期，不构成性能、压力或长期稳定性测试报告。外站故障与本系统链接配置错误分开记录；功能缺失、错误、权限泄露和数据不一致仍按对应预期记录，不能用“未约定指标”掩盖功能问题。

需求中仍存在的条件性或失效章节引用，由第5节的需求摘要与本章测试边界衔接；若执行时出现实际争议，记录具体用例、影响和处理结论，再决定通过、失败、阻塞或不适用，不预先将整组用例设为阻塞。

## 执行记录与缺陷处理

执行时为每条用例记录实际结果、执行状态、环境版本、执行人、日期、证据和缺陷编号。所有用例初始为“未执行”，不提前填写“通过”或“阻塞”。同一用例在不同平台分别记录，保留失败与复测历史，不能将一种平台的结果直接视作另一平台通过。

|用例编号|平台及版本|执行日期/人员|实际结果|状态|证据/缺陷编号|复测结果|
|---|---|---|---|---|---|---|
|填写本轮用例编号|执行时填写|执行时填写|执行后如实记录|未执行|执行后填写|复测后填写|

状态定义：未执行＝尚未测试；通过＝全部步骤和入口满足需求及测试约定且有证据；失败＝已执行且不满足预期；阻塞＝环境、数据或判定依据缺失导致无法继续；不适用＝有记录的范围排除。失败后的复测不能抹掉原结果，保留缺陷与新证据。

缺陷至少记录：编号、对应用例/需求、版本环境、复现步骤、预期/实际、截图或脱敏接口证据、严重程度、负责人和处理状态。写入/幂等问题需附前后对象id及记录数量，权限问题附脱敏响应而非令牌，排序问题附数据快照和独立计算结果。

建议执行顺序：账号与导航 → 地图地点 → 发帖草稿 → 图片创作 → 浏览互动 → 活动投稿及审核 → 活动浏览 → 实训项目 → 管理与下架联动 → 跨端异常。每轮结束清理专用数据或恢复快照，不删除非测试内容。
