# 校园广场「校园手账墙」UI 改版需求

日期：2026-11-02  
适用页面：`#/campus`  
状态：本轮设计与开发依据；完成情况以文末实施记录为准。  
参考图：`E:/code/BJTUTimeMap/校园广场无网格页眉.png`

## 1. 改版目标与版本关系

校园广场是一面由学生共同记录的校园手账墙：文字像便签、照片像贴上去的相片、主体贴纸直接融入页面。视觉还原目标约为参考图的 80%，优先还原结构、比例、层次和材质；真实帖子的照片、头像与文字不要求与样图相同。80% 是设计目标，不作为未经比对的测量结论。

本文取代旧《校园广场参考图复刻说明与实施方案》中关于统一白底卡片、底部作者行和贴纸浅绿底的设计要求。旧《校园广场 UI 复刻实施说明》保留为上一轮实现记录，不能作为本轮验收依据。

本轮保留热门/最新、地点多选筛选、消息、帖子详情、作者主页、点赞、发布及底部导航。学校内容隔离、语音帖子、自动抠图、分页接口不在本轮新增范围内。

## 3. 内容类型与组件规则

统一结构为「作者标签 → 内容主体 → 可选正文 → 地点与点赞」。外层帖子容器透明，承担布局与语义，不添加白色大底板、统一矩形阴影或黑色渐变。

### 3.1 作者标签

- 头像为约 34–38px 圆形，带白色描边；昵称放在白色圆角小标签内。
- 标签位于内容左上缘，头像略微突出，局部压住纸张或照片上缘。
- 为标签预留实际布局高度，不能只绝对定位后让上一帖覆盖它。
- 标签保持水平，正文和图片的轻微倾斜不影响昵称阅读；长昵称单行省略。
- 点击作者进入现有用户主页，与帖子详情、点赞是独立交互区域。

### 3.2 纯文字便签

- 浅杏、浅绿、浅米黄使用固定色板，由帖子 ID 稳定选择；刷新和切换排序不随机换色。
- 纸张可有轻微不规则边缘、纸纹、局部胶带、淡线条或小涂鸦；装饰不盖住正文。
- 短句可用设备可用的楷体/手写风格回退，长正文使用系统字体。
- 高度由文字决定；预览最多约 6 行，全文在详情中查看。禁止将文字预览转成图片。
- 只有纸张本体带轻阴影；地点与点赞位于纸张之外。

### 3.3 普通照片

- 照片直接展示，约 6px 小圆角，无额外白底信息板。
- 依据真实宽高比预留空间，极端比例沿用合理限制；不统一强制为竖图。
- 正文位于照片下方，最多 2–3 行；无正文时不补造标题。
- 多图帖子沿用首图预览，点击后进入现有详情能力。

### 3.4 主体贴纸

- 以真实 `imageMode === 'sticker'` 区分；不凭透明背景或照片内容猜测类型。
- 图片及展示容器均透明；移除浅绿矩形底、模式角标、矩形投影和底部渐变。
- 图片使用 `object-fit: contain` 完整展示主体；不裁掉猫耳、勺子等突出部分。
- 可使用轻微轮廓投影，白色描边仅沿素材主体轮廓存在，不做成矩形相框。
- 正文若存在，放在主体下方；地点与点赞直接落在网格背景上。
- 素材应提供带 alpha 的 PNG/WebP，并在生成或上传阶段裁去多余透明空边。列表展示不会自动抠图，也不会将原图伪装为透明素材。
- 不将 `mapMediaId` 自动当作广场首图；若首图不是贴纸成品，应修正发布产物与媒体映射，不能靠 CSS 消除照片底色。

### 3.5 文案图片

用户已经合成文字、贴纸和背景的完整图片，按普通成品图片展示，不额外叠加纸张、胶带或手写文案。当前类型仅有 `photo/sticker`，本轮不新增后端枚举；成品图使用照片分支，独立正文仅展示用户确实填写的内容。

## 4. 布局和视觉参数

以下为手机 CSS 初始值，按参考图比例及实际渲染微调，不直接照搬原图像素。

| 项目 | 规范 |
| --- | --- |
| 页面底色 | 接近 `#fbfaf7` 的米白 |
| 正文/昵称/图标 | 接近 `#092752` 的深蓝 |
| 强调色 | 暖橙，圆形发布按钮和选中装饰较鲜明；小字操作确保可读性 |
| 方格 | 约 18px，1px 极淡灰蓝线；仅内容墙显示 |
| 标题 | 约 30px、粗体；学校/校区入口约 14px |
| 内容区 | 左右边距 16–18px，列间距 16–20px |
| 帖子间距 | 约 24px；包含作者标签预留，照片/便签可轻微倾斜 |
| 作者 | 头像 34–38px，昵称 13–14px |
| 正文 | 图片说明 13–14px；短便签约 18–20px |
| 元信息 | 12–13px；地点左对齐，点赞右对齐，长地点省略 |
| 操作热区 | 作者、地点、点赞、消息等实际按钮最小 44px 高 |
| 发布按钮 | 约 48–52px，位于底栏和底部安全区之上 |

双列继续使用稳定的接口顺序交错分列，列内自然堆叠；不做随机绝对定位。320px 下缩小间距及装饰，不出现横向滚动。桌面沿用现有居中受限宽度，不拉成横向信息墙。两列 DOM 按列阅读的既有局限需要记录；本轮不宣称已实现按行的辅助技术阅读顺序。

## 5. 数据、交互与状态

- 真实数据：不将参考图里的猫、水果杯、头像、昵称、点赞数插入实际列表。
- 学校入口：沿用现有有来源的上下文；当前没有接通学校内容隔离，保留中性「学校与校区」，不硬写参考图校名来暗示筛选已经完成。
- 地点：沿用实际地点名称；缺少地点时留空，点赞仍靠右。地点多选、清除和 URL 预选继续生效。
- 点赞：独立按钮，选中以颜色和实心图标共同反馈，沿用单帖请求锁及失败处理；不触发详情跳转。
- 点击：图片/便签/正文链接进入详情，作者进入主页；不使用整张帖子的绝对定位透明点击层，防止覆盖邻帖。
- 加载：预留媒体和作者空间，展示当前加载反馈；切换条件继续阻止过期响应覆盖新列表。
- 空状态：热门无内容可查看最新，筛选无结果可清除，最新无内容可发布。
- 失败：保留重试入口；图片失败保留作者、正文、地点、点赞和中性占位。
- 离线：明确显示缓存状态，不把缓存或本机记录包装成在线新内容。
- 无障碍：保留可见焦点、按钮名称、点赞状态和减少动效支持；纸张装饰不承载必要信息。

## 7. 验收标准

- [ ] 页头和工具栏无网格，内容墙有连续且不抢眼的淡网格。

- [ ] 纯文字为固定浅色便签，照片为独立相片，地点/点赞位于外部同一行。

- [ ] 加载、空、错误、图片失败、离线和未登录状态保持真实反馈。
