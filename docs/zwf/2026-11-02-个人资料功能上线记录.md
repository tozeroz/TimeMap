## 发布期间故障与修复

约 14:19–14:39，后端重启到恢复就绪之间 API 出现不可用，静态网页未提前切换。原因分两部分：

1. 主机 396MB 内存下出现明显 I/O 等待和换页，新 Node 进程启动及数据库连接显著变慢。短时暂停经确认的只读 `apt-get check -qq` 检查，使用 trap 恢复，未停用安全代理。
2. Windows 工作区历史 SQL 使用 CRLF，首次后端包保留了 CRLF，线上原迁移记录使用 LF。启动后 checksum 保护正确触发，迁移停止，030 未执行。

最初预检只核对规范化源码，遗漏了实际产物中的换行，未能提前拦截。修复在 `server/build.mjs` 的 SQL loader 边界规范化 CRLF 为 LF，不改历史 SQL 业务内容、线上历史 checksum 或校验规则。

重新构建后，解码实际产物内全部 30 条迁移，逐条确认其中 29 条与线上已有记录完全一致，只有 030 是新增。修正包重发后 13 秒就绪；日志确认 14:38:57 为 30/30 ready。前端约 14:43 完成切换。

后续发布必须验证实际构建产物中的迁移字节，不能仅比对规范化源码或以本地测试库通过替代生产历史核对。
