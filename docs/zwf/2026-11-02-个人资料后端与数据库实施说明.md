# 个人资料后端与数据库实施说明

日期：2026-11-02。范围：参考图所需的个人资料编辑、本人资料回读及“我的”页面同步。  
状态：代码与迁移 030 已完成本地联调并于 2026-11-02 部署生产；[上线记录](2026-11-02-个人资料功能上线记录.md)包含发布故障、修复、备份与验证。

本次用户明确要求补齐后端与数据库，因此此前仅支持昵称、其余只读的限制已被本轮实现取代。[页面实施说明](2026-11-02-个人资料编辑页UI复刻实施说明.md)已同步更新。

## 1. 数据库迁移

新增 `server/src/migrations/030_user_profiles.sql`，已加入 `server/src/db.ts` 的显式迁移清单，打包时内联。没有修改历史迁移及其校验和。

| users 字段 | 含义与规则 |
| --- | --- |
| display_name | 复用昵称字段，PATCH trim 后非空，最多 40 个 JS 字符单元，兼容原接口 |
| bio | 新增 text，非空默认空串，最多 160 Unicode 码点；空串清除 |
| avatar_media_id | 新增可空 UUID，关联现有 media |
| avatar_media_scope | 新增固定 public，由 CHECK 及复合外键保证头像不能引用私有聊天媒体 |
| profile_school_id | 新增服务学校上下文外键，不是认证学校或服务端推断的学籍 |
| school_campus_id | 复用已有校区字段，没有新建重复校园归属字段 |
| college_id | 新增可空学院 ID |
| enrollment_year | 新增可空 integer，CHECK 1900–2100，表示入学年份 |

campuses 和 colleges 增加 `(id, school_id)` 唯一约束；users 的校园和学院复合外键保证学校一致。选了校区或学院就必须有学校上下文。既有明确校区关联按实际校区回填学校上下文；未关联用户不自动分配校区或学院。

头像索引便于引用查询。新列有空值/默认值，兼容旧用户；旧客户端仅修改昵称时保持原行为与返回结构。资料是自填信息，保存不会改变角色、登录凭证或权限。

## 2. 服务学校配置

后端支持环境变量 `PROFILE_SERVICE_SCHOOL_ID`；缺省采用已有迁移 012 中北京交通大学的 ID：`b0000000-0000-4000-8000-000000000001`。

学校名称、校区和学院均查真实表，不能仅凭学校字符串或第一条候选推断用户归属。学校不在允许写字段里。配置学校不存在时资料接口返回不可用，不给用户提供假的校名或候选。

学院候选沿用现有数据库中的子集，响应 `collegeListComplete: false`。本轮没有批量补造学院、学校、校区或学生资料。

## 3. 接口

### 本人完整资料

`GET /api/users/me/profile`，需要有效登录。返回：

```typescript
{
  id: string
  displayName: string
  bio: string
  avatarMediaId: string | null
  campusId: string | null
  collegeId: string | null
  enrollmentYear: number | null
  school: { id: string; name: string }
  options: {
    campuses: Array<{ id: string; name: string }>
    colleges: Array<{ id: string; name: string }>
  }
  collegeListComplete: false
}
```

用户身份从登录会话确定，不能请求读取另一人的完整资料。完整资料及写响应禁止共享缓存，使用 `Cache-Control: private, no-store`。

### 修改本人资料

扩展原 `PATCH /api/users/me`，允许以下字段；可部分更新，未提供的字段保留原值：

| 字段 | 有效值 | 清除 |
| --- | --- | --- |
| displayName | trim 后 1–40 字符 | 不允许清除 |
| bio | trim 后最多 160 字 | 空字符串 |
| avatarMediaId | 本人上传的公开 JPG/PNG/WebP 媒体 UUID | null |
| campusId | 当前服务学校下的真实校区 UUID | null |
| collegeId | 当前服务学校下的真实学院 UUID | null |
| enrollmentYear | 1900–2100 的整数 | null |

未知字段、空对象、数组、`userId`、`role`、`schoolId` 等均拒绝，不静默丢弃。旧客户端只传 displayName 时仍返回 `{id, displayName}`；扩展资料写入返回与本人完整资料读取相同的结构。新前端统一提交完整草稿并使用返回值确认成功。

状态码：401 未登录；400 校验失败；404 本人行不存在；503 数据库不可用、资料学校未配置或备份屏障阻塞；其余保存失败 500。错误不返回原始 SQL 或用户的其他资料。

### 本人身份读取与头像

`GET /api/auth/me` 兼容增加 `bio`、`avatarMediaId`，供“我的”使用，原身份字段保留。`GET /api/users/:id` 没有扩展校园、学院或年级读取能力。

媒体上传 `POST /api/media` 新增 `purpose=avatar`，复用已有上传、文件内容探测、大小限制、幂等、媒体访问和存储流程，只接受图片。前端支持 JPG/PNG/WebP、最大 5MB；最终由服务端根据实际文件内容判断。头像是公开媒体，不能上传私有聊天媒体 ID 来冒充头像。

上传成功只是获得媒体 ID，点击“保存修改”后才更新用户的头像关联；取消编辑不会写入用户资料。清除头像解除关联，不直接删除旧媒体文件。现有清理器不会扫 public 媒体，本轮没有新增 public 孤儿回收；未采用上传和被替换的图片可能保留，后续清理应先排除 users 头像及其他引用。

## 4. 一致性与权限

- 事务中锁定当前用户行，再读取未提供字段、校验、写入和回读，避免并发部分更新相互覆盖。
- 任何字段校验失败，全部回滚，不先改昵称后发现学院非法。
- 校区、学院重新检查所属学校；头像重新检查 owner_user_id、public scope 与 MIME。
- 引用媒体写入复用现有媒体变更共享锁，备份窗口阻塞时给出可重试 503。
- 返回数据库中的最终资料；失败不更新本地身份缓存，前端保留待保存草稿。
- 本人所有完整资料接口依据会话，不接受客户端指定目标用户。

## 7. 运行、部署与限制

当前 `.env.local` 的 5174 预览连接线上 API，部署后已能读取完整资料。线上 readiness 已确认 30/30；没有切换现有用户会话或代替用户修改线上资料。

发布顺序：

1. 发布构建后的后端，让正常迁移流程执行 030，确认 `/api/ready` 显示 30/30。
2. 确认服务学校配置及真实学校数据存在；验证登录后的本人资料读取与图片上传。
3. 再发布对应前端，检查刷新、保存和返回“我的”。
4. 若前端回退到旧版本，新增列可保留；不要直接删除已应用迁移或改历史校验和。需要数据库回退时另做经过备份验证的迁移方案。

本次已配套发布前后端及迁移。没有头像裁剪编辑器、图片处理队列、校园身份认证，也未扩展他人主页的校园资料公开范围。

构建注意：`server/build.mjs` 现对 SQL loader 的 CRLF 换行统一为 LF，防止 Windows 工作区换行进入产物后与线上既有迁移校验和不一致。没有关闭校验，也没有修改线上历史迁移记录。本地原有测试库仅对已证明内容相同、只差换行的历史 checksum 做了 LF 规范化，便于继续使用修正后的构建。
