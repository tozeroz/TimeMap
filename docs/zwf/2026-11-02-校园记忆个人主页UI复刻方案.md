# 校园记忆个人主页 UI 复刻方案

日期：2026-11-02  
适用页面：`#/me`（我的）  
状态：根据用户参考图整理的实施草案；本文件不代表页面已完成改版。  
参考图片：`E:/code/BJTUTimeMap/校园记忆个人主页.png`，941 × 1672 像素。图片在仓库外，未复制进项目；团队共享时需另行提供该参考图。  
代码依据：当前本地 `zwf` 工作区。维护归档：`docs/zwf/`。

## 1. 复刻目标

将当前以功能入口列表为主的个人中心，调整成以个人校园记忆为主的主页：上方集中展示头像、昵称和编辑资料；下方通过「我的发布 / 我的收藏」切换双列内容墙。设置类操作收进菜单，主区域留给内容。

视觉关键词：暖米白底、深蓝文字、浅桃头像、橙色选中标记、轻量植物装饰、双列错落照片、低装饰密度。

本次文档约定：

- 「参考图可见」是截图直接展示的内容。
- 「建议实现」是为形成完整功能补充的交互与状态，不当作截图已证明的行为。
- 昵称 `tozero`、首字母 `t`、照片、文案、日期和点赞数均为设计样例；正式页面读取真实数据。
- 本轮先调整前端页面组织和展示，不以复刻为理由新增数据库字段。

## 3. 比例与布局标尺

参考图不是 CSS 像素图。以下以约 390px 宽移动端为换算基准，按 `截图尺寸 × 390 / 941` 估算，再根据真实字体和安全区微调。表中尺寸是实施初值，不是逐像素测量结论。

| 区域 | 建议初值 | 说明 |
| --- | --- | --- |
| 页面宽度 | 手机占满可用宽度；桌面沿用最大 430px 居中容器 | 不把 941px 当页面宽度 |
| 页面背景 | 暖米白 | 顶栏、主体、底栏保持整体感 |
| 内容左右边距 | 14px | 参考图约 33px |
| 双列间距 | 9–10px | 参考图约 22px |
| 单列宽度 | 约 176px（390px 视口） | `(容器宽 − 两侧边距 − 列间距) / 2` |
| 顶部图标视觉尺寸 | 22–24px | 实际点击区域至少 44 × 44px |
| 头像 | 78–80px 圆形 | 桃色底，无粗描边、无重投影 |
| 头像文字 | 38–42px，粗体 | 来自昵称首个可见字符 |
| 昵称 | 18px，700 左右 | 居中，长昵称可换至两行 |
| 编辑资料按钮 | 88–96px 宽、视觉高约 24px | 扩大实际点击范围至至少 44px 高 |
| 主标签栏 | 约 44px 高 | 两个标签等宽 |
| 标签文字 | 15–16px，600–700 | 激活深蓝，非激活灰蓝 |
| 选中下划线 | 约 40 × 3px | 橙色、圆头，位于标签文字下方 |
| 标签栏底边 | 1px 浅灰线 | 横跨内容宽度 |
| 标签栏至卡片 | 11–12px | 两列顶部对齐 |
| 卡片圆角 | 5–8px | 阴影极弱或无阴影 |
| 正文与照片标题 | 14–15px | 窄屏优先可读性，不机械缩小字号 |
| 地点、日期、点赞数 | 12–13px | 灰蓝文字，地点图标用橙色 |
| 卡片纵向间距 | 9–10px | 各列独立向下排列 |
| 底部导航 | 约 54px + 平台安全区 | 复用现有导航，不遮住最后一张卡 |

参考图的头像区较舒展，头像中心位于屏幕中轴。叶片在头像右下方，不挤占昵称和按钮空间。页面主要留白集中在资料区，卡片区相对紧凑。

建议顶部工具栏保留，资料区和内容区在同一个主体滚动容器内滚动；主标签栏第一版随内容滚动。吸顶行为无法从静态图确认，暂不额外引入。

## 5. 内容卡片规则

### 5.1 照片卡

参考图包含两种可见信息布局：

- 明湖、图书馆卡：照片下方叠加或展示地点；白色底部横排标题和点赞。
- 思源碑猫咪卡：照片下方先展示标题，第二行展示地点和点赞。

建议统一为可适配内容的规则：标题较短时，地点叠在图片左下角，底部标题与点赞同行；标题或地点较长时，底部改两行，第二行放地点和点赞。使用真实文本长度和容器约束决定布局，不能按固定帖子 ID 指定样式。

- 使用第一张实际媒体作为预览；点击进入已有帖子详情 `feed?id=...`。
- 普通照片保留原始宽高比，并设置合理的极端长图预览上限；截图中不同照片高度不同，不统一裁成正方形。
- 图片的地点标签采用白字和轻微渐变底，避免照片亮部导致文字不可读。
- 缺少地点时省略标签；长地点单行省略，完整名称在详情页可读。
- 标题来自帖子正文的短预览，最多两行，完整正文在详情页展示；不新增假标题字段。
- 点赞数使用服务端值。列表卡第一版以展示为主，心形不额外承担写操作，避免嵌套按钮；如后续要求直接点赞，再复用现有点赞接口与反馈逻辑。
- 多图可显示真实图片数量角标，但属于可选增强，不是参考图复刻必须项。
- 贴纸或混合媒体不能为了复刻卡片而强行铺底裁切；应检查 `ApiPost → FeedPost` 转换和现有渲染器，保留内容原有透明与变换语义。

### 5.2 纯文字卡

- 浅桃白底，留出约 14px 内边距；正文深蓝，行高 1.7–1.8。
- 底部一行：左侧橙色地点图标与地点名，右侧发布时间。
- 截图正文「晚课结束，绕校园走了一圈。风很轻，今天也值得被记住。」仅用于视觉对照，正式内容读取 `body`。
- 正文按长度自然撑高；长文最多预览约 6 行，再以省略表达，点击查看全文。
- 日期来自 `createdAt`，按北京时间显示：本年用「10月30日」，跨年补年份。截图没有年份，不代表所有记录都能省略年份。
- 缺少日期或解析失败时不拼造日期；缺少地点时保持日期靠右。

### 5.3 双列排列与顺序

建议采用保留源数组 DOM 顺序的双列网格瀑布流：第 1、3、5 条视觉上进左列，第 2、4、6 条进右列；测量卡片高度后计算网格行跨度，让各列自然向下排列。卡片在 DOM 中仍按 1、2、3、4 顺序出现，不将数据拆成两个独立排序的列表，也不使用会重排顺序的 dense 填空模式。

这样能得到参考图中左侧大图、右侧先短文字再长照片的错落效果。图片预留比例，加载完成或宽度变化时更新跨度；检查键盘焦点顺序与视觉对应关系。CSS columns 通常按整列排布，与上述交替规则不同，不直接作为默认实现。若第一版暂未实现高度测量，使用保持源顺序的双列网格，并在实施说明中记录卡片下方留白与参考图的差异。

在 320px 窄屏仍优先保留双列；大字号或卡片正文无法正常阅读时允许回退单列。桌面不扩展为三列或全屏内容墙。

## 6. 数据来源与现有能力

| 页面内容 | 已有来源 | 约束 |
| --- | --- | --- |
| 身份与昵称 | `me()` → `GET /api/auth/me` | 当前权威身份来源 |
| 首字头像 | `SessionUser.displayName` | 当前会话用户类型无头像字段；继续首字占位 |
| 我的发布 | `listPosts({ authorId: identity.id, sort: 'latest' })` | 服务端按作者筛选，不从全站列表客户端过滤 |
| 我的帖子收藏 | `listMyFavorites()` → `GET /api/me/favorites` | 使用真实收藏列表 |
| 我的活动收藏 | `listMyActivityFavorites()` → `GET /api/me/activity-favorites` | 现有能力必须保留 |
| 图片 | `ApiPost.images` 与 `mediaUrl()` | 使用实际媒体，不把参考图裁成假帖子 |
| 地点、正文、日期、点赞 | `ApiPost` 的实际字段 | 不写死参考图数值 |
| 编辑资料 | `profile-edit` | 复用已有编辑与身份刷新逻辑 |
| 消息 | `message` | 复用已有消息页 |

当前收藏页既包含帖子收藏，也包含活动收藏，默认活动。参考图只展示了帖子形态，不能据此删除活动收藏。建议主页「我的收藏」展示帖子卡，同时在该标签内提供清晰的「活动收藏」入口，进入现有收藏页并保持原有活动默认项。主标签默认「我的发布」；这一默认值属于新主页的建议，不改变旧收藏页默认行为。

现有列表接口可能只返回有限窗口。本次复刻不得将返回数组长度包装成「全部发布数」或「全部收藏数」；没有分页契约时，不展示假的「全部加载完成」。需要全量历史浏览时另行补充分页设计。

## 7. 交互与信息入口迁移

| 元素 | 建议行为 |
| --- | --- |
| 菜单 | 打开现有 Drawer；容纳账号设置、清除本机缓存、退出登录及管理员入口 |
| 分享 | 截图无法确认目标；建议第一版提供「分享 TimeMap」并分享站点入口，不分享含令牌或私人收藏的链接 |
| 消息 | 打开已有消息页 |
| 编辑资料 | 已登录进入资料编辑；未登录进入登录流程 |
| 我的发布 | 原地切换帖子面板，不跳走 |
| 我的收藏 | 原地切换收藏帖子面板，同时提供活动收藏入口 |
| 内容卡 | 打开对应帖子详情；返回后恢复主标签和浏览位置 |
| 底部主导航 | 地图 / 广场 / 活动 / 我的，目的路由沿用现有实现 |

分享使用 Web Share API 时，用户取消不报失败；不支持时复制站点入口并提示成功。公开个人主页地址尚未在本方案中定义，不能擅自构造可分享的 `#/me?userId=...` 链接。当前分享按钮无点击处理，落地时应实现明确动作，或先不展示，不能保留无响应按钮。

设置和管理功能的迁移应先核对 `MeScreen` 当前所有入口再移入菜单；管理端仍按角色显示，权限继续由服务端校验。清除缓存和退出登录保留既有确认、会话清理行为。

切换标签保留各自已加载内容和滚动位置，避免每次重复显示全屏加载。请求按当前用户及标签隔离，快速切换或退出后，旧响应不能覆盖新身份的数据。编辑资料返回后刷新昵称，头像首字同步更新。

## 8. 完整页面状态

| 状态 | 展示方式 |
| --- | --- |
| 身份加载中 | 头像与昵称骨架，主标签可见，暂不请求带作者条件的列表 |
| 未登录 | 明确「登录后查看校园记忆」，提供登录入口，不显示样例昵称与样例帖子 |
| 身份接口网络失败 | 明确加载失败并可重试，不能直接判断为未登录 |
| 发布列表加载中 | 双列骨架，保留资料区 |
| 没有发布 | 「还没有留下校园记忆」＋进入现有发布流程的按钮 |
| 收藏为空 | 「暂无可展示的收藏内容」，保留活动收藏入口；不推断用户从未收藏过 |
| 列表失败 | 在当前标签面板显示错误与重试，资料区仍可用 |
| 图片失败 | 保留标题和地点，展示轻量图片不可用提示，避免整个卡片消失 |
| 长昵称、长标题 | 自然换行与合理截断，不顶出页面 |
| 下架或删除 | 重新进入或返回刷新后服从服务端结果，不从旧本地假记录补回内容 |
| 停留期间退出或切换账号 | 清除上一身份的私人面板数据，重新验证身份 |

现有 `me()` 在 `MeScreen` 中将无法取得身份统一视为不可用，现有页面文案为「未登录」。实现上表中网络错误与未登录的区分时，需要先检查客户端是否保留 HTTP 状态与错误类型；若未保留，应调整内部请求结果类型，而不是仅改页面提示字样。

## 10. 实施顺序

1. 核对身份、发布、帖子收藏、活动收藏和全部现有设置入口。
2. 完成资料区、工具栏、叶片装饰和底部导航的页面内样式。
3. 接入「我的发布 / 我的收藏」原地切换，处理真实身份和错误状态。
4. 完成照片卡、文字卡和双列内容布局，验证混合媒体。
5. 把设置类操作收进菜单，接好分享与编辑资料返回刷新。
6. 检查返回位置恢复、账号变化、图片失败、窄屏和键盘操作。
7. 运行构建与必要静态检查，记录与参考图的有意差异。

- [ ] `npm --prefix app run build`、相关 lint 检查通过，已知警告如实记录。
- [ ] 使用授权素材或测试夹具做页面验证，不向远程库写入截图示例数据。

## 12. 评审时需明确的产品选择

以下采用本方案建议即可进入实现；若团队有其他取舍，在开发前更新本节。

| 选择 | 本方案建议 |
| --- | --- |
| 分享内容 | 分享 TimeMap 站点入口；公开个人主页另行设计 |
| 活动收藏 | 在「我的收藏」面板保留独立可见入口 |
| 卡片心形 | 先展示真实点赞数，不在个人列表新增直接点赞交互 |
| 标签栏吸顶 | 第一版不吸顶 |
| 独立「我的发布 / 我的收藏」路由 | 保留，主页改为内嵌内容面板 |
| 内容图片与日期 | 使用真实字段，参考图仅作为样式样例 |
