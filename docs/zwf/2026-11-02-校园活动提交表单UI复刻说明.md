# 校园活动提交表单 UI 复刻说明

日期：2026-11-02  
参考图：`E:/code/BJTUTimeMap/校园活动提交表单界面.png`  
适用模块：活动页入口、提交活动表单。  
状态：供活动闭环负责人实施的设计说明；本轮只实现活动页橙色加号，表单和投稿接口尚未实现。

## 1. 目标与范围

以参考图为主要视觉依据，复刻目标为 80% 以上。核心是米白整页、深蓝文字、橙色重点、编号分组及左右字段布局，不改成通用白色卡片堆叠。图中填写的活动名称、时间、地点属于示例，空白新表单不能自动填入这些内容。

闭环为：活动页加号 → 表单 → 提交审核 → [我的提交](2026-11-02-个人主页我的提交UI复刻说明.md) → 管理员审核 → 公开活动／修改重提。两页的 UI 完成不等同于审核闭环完成。

本轮已在 `app/src/App.tsx` 的活动页增加橙色悬浮加号，复用广场加号尺寸、颜色及安全区位置， accessible name 为「提交活动」。点击当前显示「活动提交功能正在接入，暂时无法提交。」；这是明确的临时反馈，不调用普通帖子发布，也不假装投稿成功。队友接入真实表单后必须替换此反馈。

## 2. 入口与路由约定

- 入口位于活动页右下角，在底栏上方，随页面固定，不随列表滚动。
- 按钮约 48px，鲜橙底、白色加号、轻阴影，与广场发布按钮一致。
- 不能挡住筛选面板、对话框；沿用现有层级关系，面板遮罩应覆盖悬浮入口。
- 后续建议路由 `#/activity-submit`，重提可带 `submissionId`；这是建议，当前没有注册。
- 右上角「我的提交」建议跳转 `#/me?tab=submissions`，由个人主页消费参数并激活对应标签；不是仅修改 URL。
- 未登录点击加号，进入登录；登录成功回到原投稿入口。需核实现有登录返回机制再实现，不能假设已有支持。
- 返回表单前页时保留活动列表筛选与滚动位置。有编辑内容时离开需要确认，取消离开应保留内容。

## 3. 页面拆解

| 层级 | 参考图表现 | 实现要求 |
| --- | --- | --- |
| 顶部栏 | 左返回，中间「提交活动」，右橙色「我的提交」 | 三段对齐，标题水平居中，两侧热区不能挤压标题 |
| 引导语 | 「把校园里的精彩，分享出来。」 | 左对齐深蓝粗体，手机窄屏允许自然换行 |
| 审核说明 | 浅橙横条、时钟图标、橙色说明 | 文案为「提交后由管理员审核，通过后公开展示。」 |
| 01 基本信息 | 浅橙圆形编号、粗体分组名、右侧「必填 3 项」 | 表示共有三个必填字段，不是实时剩余数 |
| 02 活动介绍 | 简介与封面上传区域 | 右侧输入列宽度与上一组保持一致 |
| 03 补充资料 | 主办方、来源、外部链接、类型 | 轻分隔线，不加独立卡片底 |
| 底部 | 进度说明与橙色「提交审核」 | 在正常文档流末尾，滚动可达，预留系统安全区 |

表单为二级页面，不展示四项底部主导航，不画额外的假时间、电池或手势条。沿用项目开发态模拟状态栏和正式端安全区规则。

## 4. 字段与展示规范

| 字段 | 必填 | 控件及文案 | 校验 |
| --- | --- | --- | --- |
| 活动名称 | 是 | 单行输入；右侧 `当前字数 / 60` | trim 后非空，最多 60 字，计数算法前后端一致 |
| 活动地点 | 是 | 定位图标、地点名、右箭头；下方「请选择已启用的校园地点」 | 从权威地点列表选择，保存地点 ID；不可任意填一个地名 |
| 开始时间 | 是 | 日历图标、`YYYY-MM-DD HH:mm`、右箭头 | 合法时间；明确按北京时间 UTC+8 解释并转换传输 |
| 结束时间 | 否 | 同上，标签旁灰色「选填」；下方「须晚于开始时间」 | 不填可为空，填写时严格晚于开始时间 |
| 活动简介 | 否 | 有细边框的多行文本；右下 `当前字数 / 300` | 最多 300 字，不把占位文案当作提交值 |
| 封面图片 | 否 | 虚线框、图片上传图标、「上传活动海报」；下方建议说明 | 复用上传能力，校验类型/大小，失败可重试；限制以接口契约为准 |
| 主办方 | 否 | 下划线单行输入 | trim；最大长度由接口明确，不自行假定无限长 |
| 信息来源 | 否 | 下划线单行输入 | 同上 |
| 原文／报名链接 | 否 | 链接图标；占位「粘贴 HTTP 或 HTTPS 链接」 | 非空时解析为 HTTP/HTTPS URL，禁止其他协议 |
| 活动类型 | 否 | 占位「如：讲座、文体、展览」 | 当前活动类型是开放文本，不擅自改成固定枚举 |

外部链接下显示「报名通过外部链接完成。」；底部显示「审核进度可在“我的提交”中查看。」。不新增站内报名功能。三个必填标签后有橙红星号，同时设置真实 required/aria-required 语义，不只依靠颜色表达。

## 5. 视觉参数与适配

参数按 390px 手机 CSS 宽度起步，不直接使用原图像素。优先复用现有语义 token；需要时增加页面局部变量，避免修改其他页面颜色。

| 项目 | 建议值 |
| --- | --- |
| 背景 | 米白，接近 `#fbfaf7`，无方格 |
| 主文字 | 深蓝，接近 `#092752` |
| 辅助文字 | 灰蓝；保证可读对比度，不照搬过浅小字 |
| 强调 | 品牌橙；浅橙提示底与编号底 |
| 页边距 | 18–20px；顶部栏 14–18px |
| 顶栏 | 高约 48px，标题 18px/700，右操作 14px |
| 引导语 | 22–24px/750，行高约 1.4 |
| 分组标题 | 17px/700；编号圆约 28px |
| 标签／输入 | 14px；辅助说明和计数 12px |
| 左标签列 | 约 88px；右输入列 `minmax(0, 1fr)` |
| 输入行 | 单行最小 44px，含辅助文案约 64–76px |
| 简介框／封面框 | 简介约 76px 起，封面约 96px；小圆角 4–6px |
| 主按钮 | 高 44–48px，左右 14–18px，圆角约 10px，白色粗体 |

320px 时标签可换行；「原文／报名链接」不得挤出输入列。多行文本和错误提示允许把行撑高。横屏及桌面沿用项目居中受限宽度。键盘弹起后当前输入和提交按钮均可滚动到可见位置。

## 6. 状态与交互

- 初始状态：空表单，无样图活动数据；提交时校验必填，错误定位到对应字段并聚焦首个错误。
- 地点选择：加载、失败重试、空列表；已禁用地点不能新选。编辑旧投稿时若原地点失效，明确提示重新选择。
- 上传：展示进度、预览、更换和移除；上传未成功前不能带无效封面 ID 提交。选填封面允许用户移除失败文件后继续提交。
- 提交中：按钮显示「提交中…」并禁用，保留内容；服务端支持幂等，不能只防前端连点。
- 成功：服务端返回投稿 ID 与待审核状态后，进入「我的提交」并显示新记录。
- 失败：显示可理解的原因和重试，字段不清空；会话过期不丢失未提交内容。
- 重提：加载本人未通过投稿，预填真实字段，展示审核原因；成功后回到待审核，保留审核历史。
- 本轮闭环不扩展待审核修改/撤回、已通过活动修改/撤回。

## 7. 数据衔接与开发文件

当前 `app/src/api/client.ts` 有管理员新建活动与活动读取能力，不能让普通用户调用管理员接口代替投稿。`server/src/timemap.ts` 是现有活动路由主要入口；迁移应新增文件，不改写已执行的历史迁移。

建议新增 `ActivitySubmitScreen.tsx` 及局部 CSS，在 `App.tsx` 注册真实页面；复用已有地点、媒体上传、按钮与图标。接口须覆盖创建投稿、读取本人单条、修改重提，与管理员审核衔接。字段建议沿用 `title/placeId/startsAt/endsAt/description/coverImageId/organizer/source/externalLink/activityType`，具体请求契约由闭环负责人确定并记录。

服务端从登录身份确定提交人，不能接受客户端指定他人身份。审核前投稿及封面访问范围需要明确：现有 `activity` 上传用途按公开媒体处理，不能直接据此宣称私有投稿封面已隔离。审核状态与活动时间状态分开保存。
