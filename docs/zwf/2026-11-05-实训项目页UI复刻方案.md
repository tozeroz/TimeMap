## 2. 复刻方向与首屏布局

采用参考图的米白底、深蓝标题、蓝灰辅助文字和橙色操作强调。参考图左右两屏是同一页面的不同状态，正式页面通过页签切换展示，不做左右并排。

看见同学们的创意，为喜欢的项目点赞

全部项目             人气榜
橙色细下划线标识当前页签
每个项目可点赞一次，支持取消
────────────────────────────────────
全部项目                         N 个项目

[封面] 项目名称
       一句话简介
       小组图标  第三小组 · 5人
       体验项目 ↗                 ♡ 128
────────────────────────────────────
其余项目……

地图          广场          活动          我的

人气榜在每行封面左侧增加排名，前三名用奖牌标识，其余为数字；信息区适当收紧，点赞置于右侧，仍保留体验入口。

| 区域 | 复刻方式 |
| --- | --- |
| 标题切换 | 标题与向下箭头构成同一按钮；菜单锚定标题下方，暖白底、轻阴影、小圆角，选中项橙色并带勾选 |
| 顶部刷新 | 保留现有刷新图标，刷新当前模式的数据；标签随模式改为“刷新活动”或“刷新项目” |
| 页签区 | 实训模式完整替换时间、状态、地点三组筛选；两个文字页签以间距和细下划线区分 |
| 点赞说明 | 页签下方一行蓝灰色说明，与列表标题之间用细线分隔 |
| 全部项目行 | 左侧圆角封面，右侧名称、简介、小组信息；底部橙色体验入口和爱心计数 |
| 人气榜行 | 排名、封面、项目文字、点赞依次排列；前三名低饱和金银铜，避免大面积亮色背景 |
| 已点赞 | 橙色实心爱心、计数及轻底色“已点赞”提示；窄屏可调整提示位置，不能遮住项目名称 |
| 内容组织 | 整页连续背景、细横线、舒适留白；不逐项叠加厚边框、重投影或大色块 |
| 底部及发布 | 保留现有 Shell 导航和安全区；普通用户在实训模式下不出现右下角发布按钮 |

截图中的人气榜未展示体验入口，但用户明确要求项目可体验，方案在人气榜文字区补充同样的“体验项目 ↗”入口。截图排序文字旁的箭头不代表已有其他排序方式，本期仅展示固定排序说明，不增加无选项的伪下拉。

## 3. 初始视觉参数

以下是对截图的估算，实施时结合真实浏览器渲染调整，不能将图片像素直接当作 CSS px。优先复用现有活动页颜色和间距令牌。

| 项目 | 建议初始值 |
| --- | --- |
| 页面背景 | `#F8F6F2` 附近米白，优先沿用 `--c-bg` |
| 主文字 | `#0C304A` 附近深蓝，优先沿用 `--c-text` |
| 辅助文字 | `#607083` 附近蓝灰，正式采用值需满足对比度 |
| 操作及选中态 | 沿用现有 `--c-primary`、`--c-brand` 橙色令牌 |
| 分隔线 | `#DCD9D4` 附近浅灰，1px |
| 排名色 | 金 `#C4A35A`、银 `#9AA4B0`、铜 `#BE8C69` 附近的低饱和色；配深色数字 |
| 左右留白 | 常规手机约 20–24px，320px 窄屏可降至 16px |
| 页面标题 | 28–30px、粗体，箭头约 18–22px |
| 副标题及提示 | 13–15px，行高约 1.6，允许自然换行 |
| 页签 | 16–18px，选中项半粗体，下划线 2px |
| 列表区标题 | 20–22px、粗体；右侧说明 12–14px |
| 项目名称 | 17–19px、粗体，长名称可换行 |
| 简介及小组信息 | 13–15px，行高约 1.5 |
| 封面 | 全部项目约 88–104px，人气榜约 64–76px；接近方形，圆角约 10px，使用 `object-fit: cover` |
| 排名区 | 约 24–28px 宽，数字对齐，奖牌不能侵占封面和文字空间 |
| 项目行 | 上下留白约 14–18px，文字与封面间距约 12–16px |
| 点击区域 | 标题、页签、体验和点赞实际触控区域至少 44px；图标可小于触控区域 |

验收视口：320×740、390×844、430×932、1440×900。桌面沿用现有居中移动端画布。窄屏优先让简介、小组信息和操作区换行，必要时将点赞移到文字区底部；不压扁封面或缩小到难以阅读。底部导航不得遮挡最后一个项目。

## 4. 与当前代码的对应关系

已核对 `ActivitiesScreen.tsx`、`activities.css`、App 路由与发布入口、会话和登录回跳代码，并检索前后端的实训项目相关实现。

| 当前情况 | 方案 |
| --- | --- |
| `ActivitiesScreen` 顶部为固定“校园活动”与副标题 | 改为模式选择标题，校园活动保留“发现校园里的新鲜事”，实训模式使用确定副标题 |
| 页面已有时间、状态、地点筛选及活动列表 | 仅在校园活动模式渲染；项目模式使用独立页签、请求和列表状态，不复用活动字段解释项目 |
| 当前地点筛选依赖 `placeId` 路由参数 | 项目请求不携带活动地点、状态和时间；切回校园活动恢复原筛选，避免隐形过滤项目 |
| `App.tsx` 对 `root === 'activities'` 单独渲染发布按钮 | 模式必须能被 App 感知；建议使用路由查询参数表达模式和页签，统一决定发布按钮是否展示 |
| 活动页已有刷新、加载、错误、空状态和封面降级 | 复用视觉模式，项目状态文案与请求独立；刷新只作用于当前模式 |
| 活动行的星形按钮调用活动收藏接口 | 项目点赞独立建模，不将活动收藏或广场帖子点赞接口作为项目点赞接口 |
| `api/session.ts` 已有会话、登录和管理员角色读取 | 复用身份来源；后端独立验证项目写入权限和点赞用户身份 |
| 登录使用 `timemap.login.return`，目前仅接受 `activity-submit` 回跳 | 扩展受控回跳目标以支持实训页，保留原活动投稿逻辑；只新增存储字段不能实现回跳 |
| 现有 `AdminScreen` 有活动维护入口 | 增加独立项目维护区，管理项目资料和展示状态，不混入普通活动投稿审核 |
| 本轮检索未发现专用实训项目实现 | 新增项目数据表、项目点赞关系、公开查询与管理员接口；不能仅用前端静态数组交付正式功能 |

建议保留 `#/activities` 作为默认校园活动入口，用 `mode=projects` 表达实训模式，用 `view=all` 或 `view=popular` 表达项目页签。无参数或非法参数回落到校园活动；切换模式和页签可使用替换导航避免累积无意义历史，登录回跳恢复模式、页签及可用的滚动位置。

## 5. 交互规则

### 模式与页签

- 首次进入无模式参数的活动页默认展示校园活动；首次切入实训项目默认展示全部项目。
- 下拉菜单点击外部、选择选项或按 Escape 后关闭；关闭后焦点回到标题按钮。提供展开状态和当前选择的可访问表达。
- 切回校园活动恢复原时间、状态、地点筛选；实训模式完全隐藏这些控件及其弹层。
- 页签支持键盘操作和清晰焦点；切换时不得将另一个页签的旧请求结果覆盖当前内容。
- 页面右上刷新当前列表及真实统计；刷新不改变模式、页签或原有校园活动筛选。

### 项目内容与体验

- 全部项目展示本班所有对外展示的项目，数量来自服务端；如分页，必须可继续加载至全部，不能只显示固定前若干条。
- 全部项目建议按管理员维护顺序排列，同顺序时按名称和 ID 排序；该默认顺序属于实施建议，人气榜始终使用点赞规则。
- 每项包含封面、名称、一句话简介、小组名称、人数、体验网址、点赞数和当前用户点赞状态。
- “体验项目”打开管理员录入的 HTTP/HTTPS 网址。网页新窗口使用相应隔离属性；原生端沿用现有外链打开方式。
- 管理端校验网址格式和协议；缺失或无效地址应阻止发布。历史异常数据在前台显示“体验暂不可用”，不提供无响应按钮。
- 封面缺失或加载失败显示同尺寸占位和简短提示，保留名称、简介、体验和点赞功能。

### 点赞与排名

- 浏览项目和榜单无需登录，点赞需要登录。未登录点击提示并引导现有登录页，记录受控返回目标；登录成功回到原页，由用户再次点击确认点赞。
- 每个用户对每个项目最多点赞一次，可取消，可为多个项目点赞，不增加“只能选一个项目”的限制。
- 建议使用幂等的点赞和取消接口，由服务端返回权威点赞数与当前用户状态；数据库对 `(user_id, project_id)` 建立唯一约束，并以事务保证计数一致。
- 当前项目请求中禁用该项目点赞按钮，不阻塞其他项目；失败保留原状态并给出重试提示。401 按登录失效处理，不能显示点赞成功。
- 全部项目与人气榜共享更新结果；登录、退出和重新进入时重新读取当前用户状态，避免跨账号残留。
- 人气榜在服务端按点赞数降序、项目名称升序排列，名称相同时按唯一 ID 排列。中文名称采用固定的中文排序规则，开发与生产保持一致，不依赖各浏览器默认语言排序。
- 点赞成功后更新榜单顺序和排名；如采用分页，由服务端重新取得榜单，不能仅对当前一页重排后冒充全榜排名。首次实施优先按本班项目规模获取完整项目集。
- 前三名按行序显示 1、2、3 的低饱和金银铜标识，同赞数仍按名称规则分出先后，不引入并列名次。颜色之外保留可读数字与排名语义。

### 管理员维护与权限

- 项目由管理员统一录入、编辑、调整顺序及上下架；建议字段包括封面、名称、简介、小组名称、人数、体验网址、展示顺序、展示状态。本班项目集由管理员维护，本期不增加用户自行选班流程。
- 普通用户和未登录用户在实训模式下隐藏右下角发布按钮。建议管理员也从管理端项目维护入口操作，实训列表不复用“提交活动”按钮。
- 管理端表单显示必填和错误反馈，提交中防重复；保存后刷新前台数据。封面上传沿用媒体机制，扩展用途与读取权限时同步核对服务端。
- 所有维护接口在服务端验证管理员身份；前台隐藏按钮仅控制展示。下架项目不进入公开列表和榜单，其点赞接口也不再接受新操作。
- 建议下架保留历史点赞，重新上架后继续累计；永久删除行为需单独明确，本期以可恢复下架满足维护需求。

## 6. 状态与验收

| 状态 | 触发 | 反馈与下一步 |
| --- | --- | --- |
| 默认校园活动 | 无模式参数进入活动页 | 标题带箭头，原活动筛选、列表与发布规则可用 |
| 默认项目列表 | 从下拉选择实训项目 | 显示副标题、全部项目页签、点赞说明，不显示活动筛选和普通发布按钮 |
| 加载 | 首次读取或刷新项目 | 同布局骨架或加载提示，数量不伪装为 0，避免旧内容冒充新榜单 |
| 空列表 | 管理员尚未发布项目 | 显示“暂无实训项目”，说明“项目由管理员统一录入，敬请期待”；普通用户无发布引导 |
| 查询失败 | 网络或服务异常 | 显示“项目加载失败”和重试入口，不替换为截图示例数据 |
| 未登录或会话过期 | 点击点赞或服务端返回 401 | 引导登录并保留回跳目标，不增加计数 |
| 点赞提交中/失败 | 点赞或取消请求 | 当前按钮防重复；失败恢复可操作并提示，数量与服务端一致 |
| 点赞成功 | 接口成功返回 | 实心爱心与“已点赞”状态同步，两页签数量一致，榜单重排 |
| 部分可用 | 封面损坏或历史网址异常 | 封面占位或体验入口不可用，其余可用功能保留 |
| 项目下架 | 管理端修改或点赞时返回不可用 | 刷新并移除不可展示项目，提示当前项目已不可用 |

实施后检查：

1. 四个视口下标题、副标题、菜单、长项目名和小组信息不重叠；大字号下操作可到达，底部导航不遮挡最后一项。
2. 下拉选择、外部关闭、Escape、焦点返回、键盘页签切换、读屏名称和点赞 `aria-pressed` 正确，排名可通过数字辨认。
3. 默认校园活动；项目模式不出现活动筛选，切回后筛选恢复；直接项目链接、刷新和登录返回均能恢复指定模式。
4. 全部项目能浏览完整本班项目集，封面、名称、简介、小组和体验链接对应正确；空列表和失败状态不显示虚构项目。
5. 未登录、会话过期、点赞、重复请求、取消、多个项目点赞及并发请求下的唯一性和计数正确，失败不显示假成功。
6. 榜单按点赞数降序；同赞数按固定名称规则，重名按 ID；刷新和不同客户端结果一致，前三名颜色和编号正确。
7. 两页签点赞同步，刷新旧响应不覆盖刚完成的点赞；网络慢、连续切换模式及切后台后状态合理。
8. 普通用户在项目模式无发布按钮，校园活动原发布入口可用；管理员能维护，非管理员直接请求维护接口被拒绝。
9. 项目新增、修改、排序、上下架后前台变化正确；封面异常、无效外链、项目操作中被下架都有明确反馈。
10. 浏览器验证使用隔离测试项目和测试账号；已有活动筛选、收藏、详情、投稿、登录回跳和底部导航不退化。
