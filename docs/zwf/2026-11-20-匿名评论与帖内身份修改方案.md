# 匿名评论与帖内身份修改方案

日期：2026-11-20

## 目标与展示规则

解决同一评论区所有匿名参与者都叫「匿名同学」、无法辨认对话关系的问题。匿名身份以单条帖子为范围，不建立跨帖可追踪的用户代号。

- 匿名帖子显示随机名称（例如「匿名同学·A1B2C3」）和系统头像；同一帖各处名称一致，不同帖子独立生成。
- 评论区内，帖子作者标记「楼主」；匿名帖作者的评论强制匿名，沿用本帖随机名称，并显示楼主标记。
- 其他人可选择「匿名评论」，首次匿名参与分配「匿名同学 01、02……」，在本帖内永久复用。不同帖子独立分配，编号相同不代表同一人。
- 匿名评论使用按帖内代号着色的系统头像。颜色只辅助辨识，以文字编号为准。
- 每条评论提供回复入口，展示「回复 某人」；回复目标必须使用目标评论公开身份，不能直接读取真实昵称。
- 用匿名方式提交的评论不返回真实用户 ID、昵称或头像。作者本人通过 `isMine` 管理自己的评论。
- 普通帖作者可自行选择是否匿名；匿名帖作者不可通过关闭开关暴露身份。匿名与实名发言是逐条选择，界面明确提示。

## 数据与接口

新增迁移 `042_comment_anonymous.sql`：评论增加 `is_anonymous`；新增帖内匿名身份表，以 `(post_id, user_id)` 唯一保存编号，另设 `(post_id, number)` 唯一约束。删除评论不删除身份记录。真实归属保留供权限检查和审核。

创建评论时在事务内锁定帖子行，核验帖子及回复目标，分配或复用编号后写评论。相同帖子的并发写入顺序分配，不依赖客户端、当前可见评论数量或真实用户 ID 截断。

`POST /api/posts/:id/comments` 新增可选布尔字段 `anonymous`，默认 false，拒绝字符串等类型。服务端会话决定作者，匿名楼主强制遮罩。提交响应与读取评论树共用公开身份规则。

评论读模型增加 `anonymous`、`isMine`、`isPostAuthor`。匿名作者的 `authorId` 恒为 null；`replyTo` 由目标评论的公开身份生成。匿名帖作者的历史评论自动按新规则遮罩，其他历史评论保持实名。

## 前端改动

在现有评论面板增加匿名开关、简短身份说明、楼主标记、回复与取消回复入口。发送时传入 `parentId` 和匿名选择，失败保留正文与目标，成功清空回复目标。匿名评论自己的删除按钮基于 `isMine` 展示。使用现有样式体系，不改详情页整体结构。

## 验收

1. 两位匿名参与者依次获得不同编号，同人多次评论、回复及刷新复用编号。
2. 删除全部评论后再次匿名发言仍复用编号，新参与者不占用已分配编号。
3. 跨帖独立编号；并发首次评论不重复分配。
4. 匿名楼主历史评论、创建响应、回复目标均不含真实昵称或 ID；楼主能删除自己的匿名评论。
5. 匿名与实名评论、顶层与多层回复均可正常提交，评论计数包含回复。
6. 错误类型、跨帖回复、已删除目标、未登录及已下架帖子保持拒绝。
7. 运行服务端类型检查、前端构建与匿名身份回归测试；数据库集成验证依赖本地测试 PostgreSQL。

## 追加：匿名帖子随机名称

按 2026-11-20 追加需求，匿名帖子从统一名称改为「匿名同学 + 六位随机后缀」。使用随机帖子 UUID 的带版本 SHA-256 摘要生成，完全不使用用户 ID、昵称或手机号；同一条帖子跨刷新、列表、详情、收藏、地图及楼主回复保持一致。同一作者的不同帖子独立生成，名称不作为全局用户身份。有限名称空间不承诺绝对无碰撞。

历史匿名帖子自动得到稳定名称，无需迁移数据库。前端必须直接展示服务端返回的名称，不得重新替换成「匿名同学」。匿名发布提示已同步更新；其他参与者的帖内编号规则保持不变。匿名帖子仍使用中性系统头像及匿名标记，不开放作者主页。
