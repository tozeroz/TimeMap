# 管理员分类筛选与地图展示接入方案

日期：2026-11-22。状态：已按用户确认方案实现、验证并部署正式网页与后端。实际实现与验证见第 8 节，正式发布见[部署记录](2026-11-22-管理员分类与地图筛选部署记录.md)。

## 1. 这次具体增加什么

复用管理中心已有的「内容管理」「地点管理」，增加分类设置和查找条件；普通用户的发帖流程保持现状。

| 对象 | 管理员操作 | 用户地图端展示 |
| --- | --- | --- |
| 校园故事 | 给已有用户帖子设置或取消“校园故事”标签 | 一帖一卡，复用最近更新卡片，只增加故事标签，点击进入原帖 |
| 拍照打卡地 | 将已有地点设为打卡地，并挑选该地点的带图帖子作为展示素材 | 一地一卡，突出地点名称、距离、照片及地点入口 |

故事归属于帖子，打卡属性归属于地点，不建立独立故事文章，不要求管理员额外编写完整打卡指南。普通带图帖子不自动成为打卡推荐，正文有“故事”等关键词也不自动归类。

本方案以本轮用户确认的规则为准，替代早先维护方案中“独立故事文章、独立指南编辑”的设计。

## 2. 内容管理：筛选帖子、设置校园故事

### 管理入口和筛选栏

进入「管理中心 → 内容管理」，在现有帖子列表上方增加：

```text
搜索：帖子正文或作者昵称
地点：[全部地点 ▼]
故事分类：[全部 / 校园故事 / 未标记故事]
帖子状态：[公开 / 已下架 / 全部]
                         [重置筛选]
```

条件按交集生效，默认展示全部分类的公开帖子，保留查看已下架帖子的入口。搜索和翻页在服务端完成，不能只在当前已加载的若干条帖子里筛选。地点按真实地点 ID 筛选，不以同名文字匹配。

### 每条帖子如何操作

保留现有作者、正文、地点、时间、匿名状态与下架操作，补充封面缩略图、原帖预览和故事分类操作：

```text
林同学 · 公开                         昨天
老校门，藏着交大的记忆……
地点：南门                    [校园故事]

[预览原帖] [取消校园故事]             [下架]
```

- 未标记的公开帖子显示「设为校园故事」；已标记的显示标签和「取消校园故事」。
- 设置与取消均为明确按钮，保存成功后更新列表；处理中禁用重复提交，失败保留原状态并支持重试。
- 下架状态可查看历史标记，但不能新增推荐标记；取消故事标记不会删除或下架原帖。
- 第一版逐条维护，先不做批量标记和自动识别。

### 管理员日常流程

搜索或按地点查找 → 预览原帖 → 设为校园故事 → 在“校园故事”条件下复查。需要移出栏目时取消标签，原帖及其互动保持不变。

## 3. 地点管理：设置打卡地、挑选照片

### 地点列表的筛选

「管理中心 → 地点管理」增加地点名称搜索与下列条件：

```text
打卡状态：[全部 / 推荐中 / 已暂停 / 未设置]
地点状态：[启用 / 停用 / 全部]
```

每个地点只维护一份打卡设置。新增「设置拍照打卡」或「编辑打卡设置」按钮，不复制新地点，不额外保存另一套坐标。

### 打卡设置表单

```text
地点：银杏大道（使用已有地点，名称和坐标不能在这里另填）

推荐说明：[可选，简短说明看点]
展示帖子：[选择该地点的公开带图帖子]
          [照片缩略图 · 作者 · 发布时间]
          [设为封面] [上移] [下移] [移除]

推荐状态：(●) 推荐中  ( ) 暂停

[取消]                              [保存]
```

- 选帖弹层只查询这个地点直接关联的公开带图帖子，第一版不自动包含子地点，避免把上级校园与具体机位混为一处；可搜索正文、分页和预览。
- 第一版最多选择 9 篇帖子，每篇以管理员选中的一张公开图片作为展示项；第一项为封面，可调整顺序。不会把原帖所有配图未经选择自动塞入卡片。
- 至少选中一张有效公开图片，才能保存为“推荐中”；尚未选好素材可保存为“暂停”。不通过上传私人聊天图片补充封面。
- 移除展示素材仅取消引用，不删除用户帖子或图片。设置打卡地也不会给这些帖子添加“校园故事”标签。
- 推荐说明为空时不显示，不自动用普通帖正文生成管理员推荐理由。

### 日常维护

选择已有地点 → 设置打卡 → 挑选用户照片 → 确认封面与顺序 → 保存为推荐中。过季、施工或其他原因暂不适合推荐时切换为暂停；恢复后继续使用同一份设置。

## 4. 用户地图端如何筛选和呈现

### 校园故事

只查询有故事标记、原帖公开且关联地点启用的帖子，继续受当前学校、范围和地标类别限制。每篇故事独立展示，使用原来的帖子卡片，仅补充“校园故事”标签。

点击封面或正文进入原帖详情，点击地点沿用现有地点入口；原作者、头像、匿名身份、点赞、评论及收藏全部来自原帖。管理员不成为故事作者，也不复制原帖。

故事分类本身不限定近 7 天，旧故事也可长期保留。若提供新旧或热度排序，排序只改变故事顺序，不套用“最近更新”或“附近热门”的 7 天窗口；排序文案应与真实口径一致。第一版可先使用原帖发布时间倒序。

### 拍照打卡

只查询推荐中、地点启用且至少仍有一张有效展示图片的打卡地，继续受当前学校、范围和地标类别限制。同一地点只返回一张地点卡片。

按已确认的卡片设计呈现：大号地点名、“拍照打卡地”标签、真实距离与地址、管理员选择的照片轨道、可选推荐说明，以及“查看地点 / 相关帖子”。照片保留原作者或匿名展示名，点击可进入对应原帖；“相关帖子”优先打开该地点的现有帖子列表。

默认按地点名称与 ID 稳定排序；定位距离先用于展示，不在分页后按当前页局部重排。需要“距离最近”排序时单独增加服务端排序参数。

### 不受这次影响的区域

“最近更新”、默认附近记录和原来的热门排序继续使用现有帖子卡片及查询口径；原地图底图、地标标记、顶部标签排布、面板拖拽和关闭行为保持现有规则。

无内容时显示对应分类暂无内容，提供返回全部记录的入口，不再用“正在整理中”掩盖请求失败。加载、空结果和错误重试分别处理。

## 5. 数据失效、权限与操作记录

- 原帖删除、下架后，故事和打卡引用立即退出公开查询；撤下的图片、私人图片和已不属于该地点的帖子不得继续作为打卡素材。
- 封面失效时使用其余有效展示项的第一张；全部失效则该地点退出打卡筛选，后台标记“需补充展示图片”。管理员保存的暂停状态与素材失效原因分别显示。
- 地点停用时，相关故事和打卡地退出公开地图筛选。更改地点名称后，卡片读取当前名称。
- 下架不自动抹除历史分类记录；原帖重新公开且仍满足条件时可恢复展示，管理员可提前取消标签或移除引用，避免恢复。后台明确提示这条规则。
- 所有管理查询和写入均由服务端验证管理员权限。公开接口不返回真实匿名作者、管理员内部信息或下架素材。
- 设置/取消故事、修改打卡素材顺序、暂停/恢复推荐都记录管理员、对象、时间和变更摘要；操作记录与写入放在同一事务内。
- 设置接口使用“设为 true/false”等确定值，重复提交不产生重复分类。打卡设置带版本号校验，管理员同时编辑时提示刷新，避免后保存者无提示覆盖前者。

## 6. 拟实施的数据与接口

以下数据已通过新增迁移 `047_map_curation.sql` 实现，未修改已应用的历史迁移。

| 数据 | 保存内容 |
| --- | --- |
| 帖子故事分类记录 | post_id 唯一、是否为故事、最后维护管理员与时间 |
| 地点打卡设置 | place_id 唯一、推荐/暂停、可选说明、版本号、维护时间 |
| 打卡展示素材 | 地点、原帖 ID、选中的图片 ID、顺序；校验图片确实属于原帖 |
| 现有操作日志 | 复用已有日志，增加上述动作类型 |

管理端复用帖子和地点列表接口，增加搜索、分类和状态条件及稳定游标分页；新写接口分别负责故事标记和地点打卡设置。选帖复用公开内容读模型，但管理查询必须按地点、帖子状态与图片权限在服务端过滤。

公开查询将普通帖子发现、故事发现、打卡地点发现明确区分。故事复用原帖子返回结构并补充分类字段；打卡使用地点及展示素材结构，不伪装成普通帖子，不把地点数当成帖子数。范围条件和总数统计先在服务端应用，再分页。

旧客户端未传新条件时保持现有接口行为，已有记录默认不标记为故事、不设置为打卡地，不迁入示意图中的样例内容。

## 7. 实施顺序与验收

1. 新增存储及权限校验，补充故事设置、打卡设置和审计。
2. 在内容管理接入搜索、筛选和故事标记；在地点管理接入打卡设置和选图。
3. 接通地图两个分类查询，故事复用帖子卡片，打卡复用地点卡片并按正式字段调整。
4. 验证筛选组合、跨页无遗漏/重复、重复提交、多人编辑、素材失效、匿名遮罩、权限和错误重试。
5. 回归最近更新和默认附近记录的卡片保持原样，地图标记与面板关闭行为不变。

验收示例：管理员将一条南门帖子标记为故事，该帖出现在“校园故事”；取消标记后消失但原帖仍公开。管理员设置银杏大道为打卡地并选择两张有效用户照片，“拍照打卡”只出现一张银杏大道卡片；暂停后该地点退出这个分类，其他地图功能仍可使用。

## 8. 本地实现与验证记录

### 管理入口

- 管理中心 → 内容管理：搜索正文/当前作者昵称、筛选地点/故事标记/公开状态，逐条设为或取消校园故事；保留预览与带原因的下架操作。
- 管理中心 → 地点管理 → 拍照打卡维护：筛选地点名称、推荐状态与地点启用状态，进入设置弹窗选图、排序和保存。原“地点资料”子入口保留新建、启停用能力。
- 帖子与选图列表按原帖时间倒序及 ID 稳定分页，地点按当前名称及 ID 稳定分页。照片编辑冲突返回 409，保留当前表单供核对，关闭后重新打开获取最新版本。

### 接口与迁移

- `GET /api/admin/curation/posts`：`q/placeId/story/status/photos/cursor/limit`，`photos=1` 仅返回有效公开带图帖子。
- `PUT /api/admin/curation/posts/:id/story`：确定值 `enabled`，事务内写故事标记与审计；同值重试不重复审计。
- `GET /api/admin/curation/places`：按 `q/checkin/status` 筛选，返回有效展示图数量和版本号。
- `GET/PUT /api/admin/curation/places/:id`：读取/保存打卡设置；保存须提交版本号、推荐状态、说明与至多 9 个帖子/图片引用。
- `GET /api/map/discover?filter=stories`：复用原帖读模型，故事不受 7 天时限影响；支持最新和热度排序。
- `GET /api/map/discover?filter=checkins`：按地点稳定分页，`totalKind=places`，返回有效展示项和地点信息；只影响打卡卡片，不更新地图标记。
- 新增 `047_map_curation.sql`：`post_story_labels`、`place_checkins`、`place_checkin_photos`。2026-11-22 正式部署时已完成备份、迁移演练并应用新增迁移，后端和网页已更新；未写入推荐样例。

### 已完成验证

- 前端生产构建、服务端类型检查、服务端构建与产物加载冒烟通过。
- `server/tests/map-discovery.test.ts` 在本机随机隔离 schema 验证：管理权限、故事设置/取消与审计去重、旧故事保留、筛选与分页、打卡版本冲突及并发保存、私有/跨地点图片拒绝、匿名遮罩、下架过滤、失效封面回退、暂停/停用地点、打卡分页与非法游标，以及原最近更新查询口径不变。
