## 页面与交互

- 头部为“校园活动”和“发现校园里的新鲜事”，右侧刷新按钮在加载时显示忙状态。
- 时间筛选显示全部/今天/本周，选中项为橙字和下划线；状态行显示全部、即将开始、进行中、已结束、已取消，窄屏可左右滑动。
- 地点选择复用权威地点列表，支持名称搜索、单选、全部地点与清除。地点请求失败单独反馈，不将失败当成空列表。
- 活动海报按3:4比例裁切展示，右侧为标题、服务端状态、日期、地点、主办方（存在时）、来源和地图查看。海报缺失或加载失败显示明确占位。
- 海报和标题进入活动详情，星标独立收藏/取消收藏；收藏失败保持原状态。未登录收藏进入登录页。
- 地图查看按地点 id 跳转 `#/map?placeId=...`，不按名称猜测地点；地点停用或缺少坐标时显示“暂不可定位”。
- 本轮保持单地点活动模型，不伪造“校园内·多个地点”。真正多地点需要后续扩展数据结构。
- 全部或历史状态使用“活动列表”标题，避免将历史活动称作近期；即将开始和进行中使用“近期活动”。

## 筛选与数量口径

1. 状态初值为 `all`，实际向服务端传 `status=all`，包含历史及取消活动。后端仍兼容未传状态的旧调用者，其默认范围仍为即将开始和进行中。
2. 今天按北京时间 `[今天00:00, 明天00:00)`，本周按 `[周一00:00, 下周一00:00)`。活动与窗口有交集才显示；恰在窗口起点结束、恰在窗口终点开始的活动不纳入。
3. 无结束时间按既有规则视为开始后两小时结束；不在前端自行计算状态。时间显示统一使用北京时间，避免海外设备时区与筛选不一致。
4. 跨日列表只显示简短日期区间，完整时间保留在提示和活动详情；同日显示开始、结束时刻；跨年和历史年份保留年份信息。
5. 总项数来自同一筛选查询、同一查询快照的 SQL 窗口计数，计算发生在200条返回上限之前。总数超过已加载数量时显示上限说明，可继续使用筛选缩小范围。
6. 新前端连接尚未升级的旧后端时，总数区域降级为“已加载 N 项”。自然日/自然周修正需要同时更新后端，只有部署前端不会改变旧后端的时间算法。

## 验证

- 前端构建：`npm run build --prefix app`。
- 前端检查：`npm run lint --prefix app`。无错误，仓库现有的 React effect/Fast Refresh 等警告仍保留；本页原有导出辅助函数的 Fast Refresh 警告也保留。
- 后端类型检查：`npm run typecheck --prefix server`。
- 后端构建由本地启动脚本执行，包括构建产物加载冒烟。
- 真实 PostgreSQL 集成：自然日/自然周边界、跨日/跨周、两小时缺省结束时间、取消状态、地点筛选、非法参数、超过200项的总数，以及空结果。
- 浏览器：320×812、390×844、1440×900，无文档横向溢出；浏览器时区设置为洛杉矶，仍验证北京时间显示正确。
- 交互：全部/时间/状态/地点查询、快速切换筛选的过期响应丢弃、收藏/取消/失败、未登录引导、地图和详情跳转。
- 状态：骨架屏、加载错误、空结果、地点部分失败及重试、长标题/长地点、缺海报/海报失败、旧服务器总数降级和返回上限说明。
- 可访问性：44px主要操作区域、筛选按下态、收藏按下态、导航当前页、面板键盘循环/Escape/焦点恢复和减少动效。
- 活动详情仍能正常显示封面、完整时间和查看地点入口；公共底栏沿用原有四条路由。
- 真实本机接口的活动列表及四个底部导航入口已只读检查通过；本机部分活动没有封面，因此实际页面如实显示“暂无海报”。

## 边界与本地查看

- 本轮复刻界面与现有单地点业务，参考图中的海报素材不自动进入产品；实际效果取决于管理员录入的封面和真实活动。
- 排序沿用后端规则：全部/历史按开始时间倒序，其余按开始时间升序，并非固定复制参考图三条活动的顺序。
- 接口提供总数但没有新增翻页功能，超过200项时通过筛选缩小范围。
- 未进行 Android 真机、系统文字放大和真实账号收藏写入验收；后端日期规则已在隔离的真实 PostgreSQL 上验证。
- 本地环境启动后访问 `http://127.0.0.1:5180/#/activities`。本轮没有发布线上，部署时需配套更新前后端。
