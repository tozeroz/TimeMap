# 地图地点优先刷帖

从地图代表帖、地标抽屉或地点详情打开帖子后，按以下顺序浏览：

1. 用户点中的帖子。
2. 同一地点的其余公开帖子，按发布时间倒序；包括地点面板尚未加载的帖子。
3. 其他地点的公开帖子，按发布时间倒序。

向下继续浏览、向上回看，返回键仍回到原地图或地点。校园广场、收藏及个人帖子列表维持各自的来源顺序。

新增 `GET /api/posts/:id/browse`，服务端根据点中帖子的真实地点生成去重的顺序。只加载 ID，正文和图片仍按需读取。列表是进入时的快照，期间新增内容在下次进入时加入；下架内容不进入新列表。首次加载失败时保留已知的本地点列表，并提供重试入口。当前接口返回完整 ID 列表，帖子量大时可进一步改为分页。

实现涉及 `feedBrowse.ts`、`FeedDetailScreen.tsx`、`MapScreen.tsx`、`PlaceSections.tsx` 与服务端帖子接口，不增加数据库迁移。

验证：服务端类型检查、前端构建通过；`server/tests/run-place-browse.mjs` 在本机 PostgreSQL 隔离 schema 验证排序及下架限制；`tools/checks/place-browse-browser.mjs` 验证同地点未展示帖子优先、跨地点续刷、向上回看与返回地点。尚未部署线上。
