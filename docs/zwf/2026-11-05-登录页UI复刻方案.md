## 2. 复刻方向与首屏布局

采用参考图的暖白底、深海军蓝文字、橙红色主按钮和绿色协议链接。页面任务是让用户确认品牌、输入手机号、阅读协议并获取验证码；管理员密码作为右上角次级入口。

```text

时钟图钉标识  北交时光

欢迎回到TimeMap
用手机号登录，留住校园里的每段时光

手机号码
┌────────────────────────────────┐
│ +86  │  请输入手机号            │
└────────────────────────────────┘

          获取验证码（橙红色胶囊按钮）

□ 我已阅读并同意 用户协议 与 隐私政策

下方保留舒适留白
```

| 区域 | 复刻方式 |
| --- | --- |
| 顶部操作 | 返回按钮白色圆底、轻投影、深蓝箭头；右侧灰色“管理员登录”，保持至少 44px 点击区域 |
| 品牌行 | 左侧时钟与地图图钉标识，右侧深蓝粗体“北交时光”；优先复用现有 `app/public/timemap-logo.png`，实施前核对是否为独立图形、是否包含留白或文字 |
| 欢迎区 | 左对齐大标题，下面为低一级蓝灰色副标题；保留上方品牌与下方表单之间的层次 |
| 手机号输入 | 独立“手机号码”标签；白底细边框大圆角，固定 +86 与输入区之间有竖分隔线 |
| 主操作 | 全宽橙红色胶囊按钮，白色粗体“获取验证码”；不添加纹理或无关插画 |
| 协议行 | 左侧方形复选框，右侧灰色正文、绿色条款链接；文本可自然换行，链接与勾选操作分离 |
| 背景及留白 | 接近纸白的纯色；下部留白随屏幕高度伸缩，输入区域不能依赖固定整页高度定位 |

不将系统时间、电量和底部手势横条绘制进正式网页。沿用 Shell 对开发预览、正式网页和原生安全区的现有处理。

## 4. 与当前代码的对应关系

已核对 `LoginScreen.tsx`、`LoginSelectScreen.tsx`、`login.css`、App 路由和登录 API 调用。

| 当前情况 | 方案 |
| --- | --- |
| `#/loginselect` 是品牌拼贴与“登录 TimeMap”按钮，之后才进入 `#/login` | 推荐合并为手机号登录入口：把参考图实现于 `LoginScreen`，保留 `loginselect` 地址作为兼容入口，统一进入新页，避免所有已有登录入口都需要改写 |
| `LoginScreen` 标题为“输入手机号”，下面有验证码/管理员密码切换条 | 首屏替换为品牌行、欢迎标题、副标题；管理员入口移到右上角，普通手机号首屏不再显示模式切换条 |
| 已有 `requestLoginCode`、`verifyLoginCode`、`adminLogin` | 复用接口及会话存储，不新建认证协议、不修改管理员权限规则 |
| 已有验证码输入、重新获取与倒计时 | 保留后续功能，使用新页面视觉补齐；参考图只提供验证码发送前状态，后续状态作为同风格延伸，不声称逐像素还原 |
| 当前协议同意在选择页，手机号页仅有“登录即表示同意”文字 | 合并后统一由手机号页管理一个明确的同意状态，避免重复勾选或直接访问手机号页绕过本次交互 |
| 协议名称目前为不可点击的 `span` | 改为真实可访问的条款入口；当前 `#/privacy` 是隐私设置，不应将其当作隐私政策正文 |
| 管理员成功进入管理端，普通登录默认进入校园广场 | 保留现有成功去向；保留 `timemap.login.return` 的活动投稿返回逻辑，不能因视觉改造丢失 |

若保留 `LoginSelectScreen` 文件供历史用途，也应明确只有一个正式手机号登录入口。兼容路由使用替换导航，返回按钮应回到登录前来源；避免 `loginselect → login → 返回 loginselect` 形成循环。无有效来源时回到地图页。

## 5. 交互规则

### 手机号与协议

- +86 为当前固定区号，展示为文本，不提供没有其他国家选项的伪下拉按钮。
- 手机号使用 `type="tel"`、`inputMode="tel"`、`autoComplete="tel-national"`，有可关联的标签；输入及粘贴处理应与现有 API 接受的手机号格式一致，不擅自扩大或缩小登录范围。
- 协议复选框默认未选中，选中状态通过原生 checkbox 或等价可访问控件表达。
- 为接近参考图，主按钮首屏保持橙红色；点击时先检查手机号与同意状态，不符合时就地给出提示并聚焦对应控件，不发送验证码请求。
- 点击协议链接只打开正文，不改变勾选状态，不触发验证码请求。返回条款后保留手机号和本次同意状态。
- 原选择页含未成年人规则文案；合并前应核对现有正式条款要求。没有正式决策时，不能仅为贴近截图而静默删除已有必需条款。

### 获取验证码及登录

- 请求时显示“发送中…”并防重复提交；失败保留手机号和勾选状态，展示可恢复的错误。
- 成功后明确展示当前号码对应的验证码区域、六位验证码输入、倒计时和“重新获取”；主按钮变为“登录”。
- 倒计时以截止时间计算，切后台回来仍显示合理剩余时间；组件卸载时清理计时器。限流等待以服务端反馈为准，不能仅靠前端倒计时解除服务端限制。
- 提供“修改手机号”：清除旧验证码与发送状态，后续校验与新号码绑定。原号码尚在冷却时如何限制重发，继续由服务端判断。
- 按接口真实返回区分短信发送与开发投递提示；不能把 `dev-sink` 描述成短信已发到手机。
- 错误码、过期、429 限流及网络不可用各有准确反馈；无论成败都不在界面显示口令或验证码日志。
- 普通用户成功保留当前登录去向；活动投稿回跳信息继续生效。

### 管理员登录

- 右上角“管理员登录”切入现有密码流程，标题显示“管理员登录”，输入区为手机号和密码，主按钮为“登录”。品牌行仍显示“北交时光”。
- 提供明确的“返回手机号登录”入口；切换时清空密码与错误，避免验证码发送状态将管理员手机号锁定为不可修改。
- 密码输入支持 `autoComplete="current-password"`，提交中防重复请求；返回普通登录时不保留密码。
- 手机号不存在、不是管理员、密码错误继续使用统一提示“手机号或密码不正确”；网络和服务故障应提示可重试，不能冒充凭据错误。
- 管理员成功仍进入管理端；UI 入口不能替代服务端权限校验。
- 管理员密码配置的运维命令属于维护文档，不放在面向用户的登录主流程中。

## 6. 状态与验收

| 状态 | 触发 | 反馈与下一步 |
| --- | --- | --- |
| 默认/空输入 | 首次进入 | 完整欢迎区，手机号可输入，协议未选；提交时给出具体缺项提示 |
| 未同意 | 号码有效但尚未勾选 | 提示阅读并同意相关条款，保留号码，不调用发送接口 |
| 加载 | 发码、验证码登录或管理员登录中 | 按钮显示当前动作，禁用重复提交，不阻塞无关的可读内容 |
| 失败 | 无效号码、错误验证码、过期、限流、网络失败 | 区分原因，保留适用草稿，提供修改、等待或重试路径 |
| 部分可用 | 条款正文加载失败或标识图片失败 | 条款失败有重试且不能伪装已阅读；标识失败保留“北交时光”文字，登录区域仍可用 |
| 成功 | 获取验证码或完成登录 | 前者进入验证码态并显示真实投递方式；后者更新会话并跳转原定页面 |
| 管理员凭据拒绝 | 管理员接口拒绝身份凭据 | 统一凭据错误提示，不泄露账号身份；仍可返回手机号登录 |

实施后检查：

1. 四个视口下，两处目标文案完全一致，长标题、协议换行和系统放大字号不重叠。
2. 原生安全区与软键盘下不遮挡输入、登录按钮及协议；网页不新增假系统状态栏。
3. 键盘 Tab 顺序、Enter 提交、可见焦点、字段标签、错误关联与读屏提示；正文对比度、触控区域符合页面约束，减少动画设置下无装饰动画。
4. 未同意或号码无效不发请求；成功发送、重新获取、修改号码、切后台倒计时、组件卸载计时器清理均正确。
5. 验证码/管理员切换、密码清除、管理员拒绝、投递渠道异常、普通登录去向和投稿回跳不退化。
6. 协议/政策入口可打开真实批准文本，隐私设置页不冒充政策页。
7. 浏览器验证优先使用隔离模拟接口，不向真实手机号试发短信；真实通道联调另行记录。
