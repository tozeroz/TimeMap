# 个人主页「我的提交」UI 复刻说明

日期：2026-11-02  
参考图：`E:/code/BJTUTimeMap/个人主页的校园活动提交 уҳәа.png`。  
适用页面：`#/me` 的活动投稿标签。  
状态：设计与实施依据，本轮尚未新增「我的提交」页面或投稿查询接口。

## 1. 目标与边界

在现有个人主页上增加第三个标签「我的提交」，展示当前用户自己提交的校园活动及审核结果。目标视觉还原度 80% 以上，与[活动提交表单说明](2026-11-02-校园活动提交表单UI复刻说明.md)共同验收。

保留已实现的个人资料头部、「我的发布」「我的收藏」、活动收藏入口及底部导航。不要为加入标签重写整页资料或破坏已有功能。图中头像字母、tozero、三张活动封面、日期及审核结果均为排版示例，线上必须使用真实用户和投稿数据。

「我的提交」只存在于本人主页，不展示在他人主页，也不等同于收藏活动或报名记录。

## 2. 页面结构

| 区域 | 样图特征 | 实现要求 |
| --- | --- | --- |
| 顶部操作 | 菜单、分享、消息 | 沿用当前已接通的入口，不为了复刻增加无效按钮 |
| 资料头部 | 大号圆形头像、昵称、描边编辑按钮、少量叶片装饰 | 保留当前数据逻辑，不硬编码示例昵称和头像 |
| 一级标签 | 我的发布／我的收藏／我的提交 | 三列等宽，未选灰蓝，选中深蓝粗体＋橙色短下划线 |
| 审核筛选 | 全部／待审核／已通过／未通过 | 横排四枚胶囊，选中浅橙底和橙色字，未选浅灰底 |
| 投稿列表 | 左封面、右信息，条目间细线 | 透明底单列，不包成浮起的白色圆角卡片 |
| 底部导航 | 地图、广场、活动、我的 | 保留既有路由；我的选中为橙色，不新增全局投稿加号 |

资料头部、标签与列表属于同一滚动内容，底部导航固定。新增内容应沿用现有个人主页滚动位置保存机制；切换标签不应意外回到活动页。

## 3. 列表项结构

每条由封面和信息列组成。信息列依次为「标题与审核徽标 → 地点及开始时间 → 状态说明／审核原因 → 操作」。

| 审核状态 | 徽标 | 辅助信息 | 操作 |
| --- | --- | --- | --- |
| 待审核 | 浅橙底、橙字「待审核」 | 提交于 MM月DD日 HH:mm；等待管理员审核 | 查看提交 |
| 已通过 | 浅绿底、绿字「已通过」 | 审核通过；如活动仍公开，显示「已公开展示」 | 查看活动 |
| 未通过 | 浅红底、红字「未通过」 | 浅橙原因区域，「审核原因：…」 | 查看提交＋橙色「修改后重提」 |

标题、地点、时间、提交时间、原因和状态均读取服务端。已通过不等于永远公开：若关联活动被移除、取消或不可访问，按实际状态解释，不能始终写「已公开展示」。缺少公开活动 ID 时不给出错误详情链接，应展示可理解的状态与恢复入口。

### 封面与文案

- 左侧封面近正方形，小圆角，`object-fit: cover`；与公开活动详情使用同一真实封面来源。
- 没有封面或图片失败时，保留相同尺寸的米色占位和图片图标，不插入示例海报。
- 标题通常两行内展示，超长截断；可通过查看提交阅读完整内容。
- 地点和开始时间同一行，以小圆点分隔；窄屏允许分行，不能压缩至不可读。
- 审核原因不以单行省略隐藏；列表可显示 2–3 行，在提交详情中提供全文。
- 状态用文字和颜色共同表达；不用只有红绿颜色的圆点替代状态名。
- 今年日期可显示 `11月08日 14:00`，跨年需要年份；所有时间以 Asia/Shanghai 格式化。

## 4. 视觉参数

按 390px CSS 宽度起步，原图像素不能直接作为手机 CSS 值。颜色与表单页统一，优先复用现有 token。

| 项目 | 建议 |
| --- | --- |
| 背景／正文 | 米白 `#fbfaf7`／深蓝 `#092752` |
| 页面边距 | 14–18px |
| 头像／昵称 | 沿用当前个人主页比例；样图头像约 76px、昵称 18px/700 |
| 编辑资料按钮 | 深蓝细描边胶囊，热区高至少 44px |
| 一级标签 | 15–16px；下划线宽约 48px，高 2–3px |
| 筛选胶囊 | 可见高约 30px，实际点击区至少 44px；间距约 8px |
| 列表封面 | 约 104px，圆角 6px |
| 封面与正文间距 | 14–16px |
| 活动标题 | 16px/700，行高 1.4 |
| 元信息／操作 | 13px；次要说明 12–13px |
| 状态徽标 | 11–12px，内边距约 4px 7px，小圆角 |
| 条目间距 | 上下约 12–16px，分隔线极淡灰蓝 |
| 原因提示 | 浅橙底、橙色文字，小圆角，内边距约 8px |
| 重提按钮 | 橙底白字，圆角约 10px，实际热区至少 44px |

320px 下封面可缩到 82–88px，信息列 `min-width: 0`。标题与徽标允许改为上下排布；底部两个操作可换行，不能挤成一团。「未通过」条目高度自然增加，不强制所有条目等高。大字号时允许上下封面布局。桌面继续使用现有受限宽度外壳。

## 5. 标签、筛选与导航

- 默认保留当前主页选择记忆行为；从表单「我的提交」或提交成功进入时，显式激活 submissions 标签。
- 建议使用 `#/me?tab=submissions`；实际路由实现需同步到表单。当前尚无此参数消费逻辑，不能声称已接通。
- 一级标签使用 tablist/tab/tabpanel 语义；把现有两项键盘切换扩展为三项，支持左右、Home、End，而非沿用两项互换逻辑。
- 状态筛选可用带 aria-pressed 的按钮。切换后读取对应真实结果，过期响应不能覆盖新条件。
- 点击「查看提交」进入本人投稿详情；点击「查看活动」进入现有公开活动详情。
- 「修改后重提」进入表单并加载未通过投稿，不直接将状态改成待审核；必须再次提交成功后更新。
- 对多处入口保持一致：表单返回、个人主页标签、提交成功定位不能产生互相跳错的循环。

## 6. 内容与异常状态

| 状态 | 反馈及可继续的操作 |
| --- | --- |
| 未登录 | 提示登录后查看自己的活动投稿；提供登录入口 |
| 首次加载 | 预留列表结构，显示加载状态，避免先闪空列表 |
| 全部为空 | 「还没有提交过校园活动」，提供「去提交活动」 |
| 某筛选为空 | 如「暂无未通过的提交」，可切回全部；不能误说用户从未投稿 |
| 请求失败 | 错误提示与重试，不显示假成功或假记录 |
| 封面失败 | 仅替换封面，保留标题、审核状态和操作 |
| 审核状态更新 | 刷新或返回页面时获取新结果；失效状态下重提由服务端阻止 |
| 重提成功 | 更新原投稿审核状态，移出未通过筛选，不重复追加同一投稿 |
| 投稿不存在／无权访问 | 显示无法访问及返回列表，不回退到他人或默认记录 |

不必新增实时推送才能交付，返回刷新和手动重试需可靠。是否实现分页由服务端契约决定：有游标则正确加载，没有全量依据则不能显示「已加载全部」。若后续加入缓存，必须按当前用户隔离并退出时清理，不能显示上一账号投稿。

## 7. 接口、权限与实施范围

主要修改点是 `app/src/screens/MeScreen.tsx`、对应个人主页样式、`app/src/api/client.ts`、`app/src/App.tsx`；建议拆出 `MyActivitySubmissions` 和投稿条目组件。不要将投稿卡片混入 `FeedPost` 类型或帖子列表。

服务端需要本人投稿列表、本人投稿详情、审核结果和关联公开活动 ID。推荐响应包含投稿 ID、活动字段、审核状态、提交时间、审核原因、关联活动 ID；状态枚举在接口设计中明确，不把展示中文字符串当技术枚举。

服务端从会话获取本人身份，过滤及单条访问都需要校验所有权；不能先拉全站投稿再由前端筛成“我的”。管理员接口独立校验权限。审核通过与公开活动生成保持一致性，并防止重复审核生成多个活动。

管理员审核后台不属于本说明的 UI 复刻对象，但属于队友负责的整体闭环，必须有可实际执行的审核入口。不能以数据库手动改状态作为最终交付方式。

## 8. 验收与交付

按表单文档的统一权重评分，总分达到 80 分以上，附同宽截图、各项理由及差异；不能用样图截图直接充当页面。

- 在 320、390、430px 和桌面检查三标签、四筛选、三种状态条目、超长标题与原因、无封面等情况。
- 不改变原有我的发布、我的收藏、活动收藏及资料编辑行为，回归底部导航和消息入口。
- 使用用户 A、用户 B、管理员：A 投稿；B 无权查看；管理员驳回；A 看原因并修改重提；管理员通过；A 能进入公开详情，公众列表和地点活动区同步可见。
- 刷新、重新登录及直接访问本人列表路由仍读取持久化结果。
- 验证键盘、可见焦点、按钮名称、状态文字、减少动效及底部安全区；确认重提按钮未被底栏遮挡。
