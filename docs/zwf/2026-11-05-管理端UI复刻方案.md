# 管理端 UI 复刻方案

日期：2026-11-05。状态：待评审方案。参考：用户提供的《管理端ui.png》。适用：管理中心公共框架与活动管理面板。仅新增方案文档，未修改运行代码、数据或部署环境。

## 1. 复刻范围与方向

采用“暖白背景、深色文字、校园绿强调色、日期牌活动卡片”的方向。管理员首先扫描活动名称、日期、状态和待核查信息，再进行查看、编辑、取消或恢复操作。

第一轮复刻图中可见的管理中心头部、分类导航和活动管理页面；其他面板保留现有功能，跟随公共头部和导航统一样式。截图未展示其他面板及弹层，不能据此声称整个管理端已完成逐页还原。

现有 React + TypeScript + CSS 可以实现，无需更换框架或引入组件库。优先复用 Screen、TopBar、现有 SVG 图标及 API。

## 2. 页面结构

```text
管理中心：返回 / 居中标题及副标题 / 盾牌标识
分类导航：举报处理 / 投稿审核 / 内容管理 / 活动管理 / 地点管理 / 操作记录
活动管理标题、副标题                         + 新建活动
搜索活动名称、地点
全部 / 即将开始 / 进行中 / 已结束 / 已取消       筛选
符合条件数量                                 刷新
活动卡片 × N
仅展示已录入活动。
```

| 区域 | 参考图特征 | 落地方式 |
| --- | --- | --- |
| 头部 | 居中双行标题，左返回，右盾牌 | 标题“管理中心”，副标题“时光坐标 · 校园记忆地图”；盾牌作为管理员标识，不添加无功能点击 |
| 分类导航 | 文字导航、绿色选中项和短下划线 | 替换现有胶囊式 tab；保留第六项“操作记录”，窄屏横向滚动，选中项自动进入可视区域 |
| 标题区 | 左大标题及说明，右绿色按钮 | “活动管理 / 维护校园活动信息”；主操作为“＋ 新建活动” |
| 搜索 | 全宽白底圆角细边框 | 按活动名称、地点搜索；提供清除操作，与状态及高级筛选取交集 |
| 状态筛选 | 选中实心绿，未选白底描边 | 五种状态单选；“全部”包含已结束、已取消活动 |
| 计数与刷新 | 左灰色数量、右刷新图标及文字 | 数量与当前筛选一致；加载时不显示误导性的 0 项，刷新有进行中反馈 |
| 活动卡片 | 左日期牌、中标题与元信息、右上状态 | 标题允许换行，状态独立占位；时间、来源、地点各有线性图标 |
| 卡片底部 | 分隔线，查看详情 / 编辑 / 更多 | 三个独立按钮；“更多”收纳取消或恢复，不添加后端尚不支持的删除功能 |
| 页尾 | 灰色轻提示 | 保留“仅展示已录入活动。”；存在接口截断时另提示加载范围 |

## 3. 视觉规格与响应式

以下为根据截图估算的初始值，实施时以浏览器对照为准。参考图是高像素图片，不能将其中尺寸直接当作 CSS px。

| 项目 | 建议初始规格 |
| --- | --- |
| 背景 | 暖白约 `#F7F6F2`，卡片 `#FFFFFF` |
| 文字 | 主文字约 `#172534`，次文字约 `#686D70` |
| 主色 | 校园绿约 `#587A50`；选中导航文字可加深以保证对比度 |
| 状态 | 即将开始用浅绿底深绿字；进行中、已结束、已取消各有明确文字和配色，不能只靠颜色区分 |
| 分割与警示 | 边框约 `#DEDEDA`；核查提示使用深琥珀色文字与图标 |
| 字体 | 沿用系统中文字体；模块标题 24–28px，卡片标题 16–18px，元信息 13–14px |
| 间距 | 手机左右留白 16–20px，卡片内边距 12–16px，卡片间距 10–12px |
| 圆角 | 卡片与搜索框 10–14px，状态筛选胶囊圆角 |
| 日期牌 | 约 44–52px 宽，上段绿色月份，下段暖白日期；与正文之间竖分隔线 |
| 图标 | 统一线性 SVG，约 18–22px；不使用 emoji 替代 |

目标视口：390×844 为主验收尺寸，320×740 检查极窄屏，430×932 检查大手机，1440×900 检查桌面现有居中手机画布。不将此方案扩展为桌面侧栏后台。

- 窄屏状态栏允许横向滚动，高级筛选入口保持可发现；不强行压缩五个标签与筛选按钮。
- 卡片标题、状态在窄屏可分行；时间、来源改为纵向排列，完整信息可换行，避免固定卡片高度。
- 顶栏与分类导航保持可访问，搜索及列表随内容滚动；不要将整段工具区固定后挤占手机列表空间。
- 按钮有效触控区域至少 44px；键盘焦点可见，图标按钮提供可读名称，弹层支持焦点管理与关闭后返回触发按钮。
- 延续 Shell 规则：正式网页不绘制截图中的模拟系统时间、电量栏；原生端使用系统状态栏及安全区。
- 背景首版使用纯色与轻描边，不需要把截图的纸张纹理制作成图片背景。

## 4. 现有能力与缺口

已核对 `AdminScreen.tsx`、`admin.css`、API 客户端和 `server/src/timemap.ts`。

| 能力 | 当前情况 | 实施要求 |
| --- | --- | --- |
| 管理分类 | 已有六项，截图显示五项 | 保留操作记录，调整导航样式 |
| 活动列表、新建、取消、恢复 | 已有 | 复用数据和写入流程，操作后重新读取列表 |
| 状态标签 | API 返回 `effectiveStatus` | 映射为中文展示；不把 upcoming/ongoing/ended 当成可人工写入状态 |
| 编辑活动 | PATCH API 已有，当前活动卡片没有编辑入口 | 新建/编辑共用表单；编辑回填字段并调用更新接口，保留未修改数据 |
| 查看详情 | 已有学生侧活动详情页 | 首版复用详情路由；管理卡片内动作独立，不做整卡按钮嵌套 |
| 搜索、高级筛选 | 当前管理活动面板没有 | 加入关键字、状态、地点、日期范围；高级筛选使用可重置的抽屉或弹层 |
| 来源信息 | 已有 `source` 与 `externalLink` | 展示真实来源；有合法外链时再提供来源链接，不编造官网名称 |
| 总数与分页 | 管理接口只返回有限 `items`，按开始时间倒序 | 若仅前端过滤，数量必须写“当前已加载 X 项”；完整管理建议补服务端搜索、筛选、总数和分页 |

时间与日期牌统一按 Asia/Shanghai 展示。跨年列表需要显示年份，日期牌不能让管理员误认活动年份。排序首版沿用现有开始时间倒序；如增加排序选项，应由分页查询统一处理。

高级日期筛选建议明确为“开始日期范围”，按北京时间自然日计算边界，避免与“活动持续时间与区间重叠”的另一种口径混淆。地点候选加载失败时单独显示重试，不冒充“无地点”。

## 5. 截图中的业务差异

### 时间、地点待补充

当前正式活动创建要求标题、已启用地点和合法开始时间。截图同时显示具体日期与“时间待确认”，并存在“地点待补充”，不能通过把必填校验删除来复刻。

首版保持正式活动规则：展示真实日期、时间和地点。仅结束时间缺失时显示已有开始时间，不标成整个时间未知。如果业务确需保存不完整活动，另行设计草稿/待补全状态、允许缺失的字段、列表筛选及发布校验；草稿不得自动成为学生端正式活动。这属于业务扩展，不纳入纯 UI 复刻。

### 非校内范围提醒

当前活动返回字段没有明确的校内/校外核查结论。首版不根据标题中“威海”等词语判断校外，也不固定显示截图的警告。若后续增加提醒，应先确定校区边界及坐标判定，或引入人工核查标记，并在界面说明其依据。未知坐标不能直接认定为校外。

### 数量与示例活动

不固定“3 项活动”、日期或三条示例标题。视觉验收可用隔离的本地样例覆盖长标题、取消态和异常信息，正式列表始终使用接口数据。

## 6. 交互与状态验收

| 状态/操作 | 触发条件 | 可见反馈及后续动作 |
| --- | --- | --- |
| 加载 | 首次进入、切换查询 | 卡片骨架或明确加载提示，结构稳定，避免旧请求覆盖新查询 |
| 空列表 | 没有已录入活动 | 提示“暂无活动”，提供新建活动 |
| 无搜索结果 | 查询无匹配 | 保留查询条件，提示无匹配，提供清除条件 |
| 请求失败 | 列表/保存请求失败 | 显示明确错误与重试；保存失败保留表单草稿 |
| 部分可用 | 地点候选失败、封面失败、来源链接缺失 | 保留活动列表，局部提示；缺失链接仅显示文字；不阻断无关操作 |
| 保存成功 | 新建或编辑完成 | 明确成功提示，关闭表单并重新拉取，维持合理的筛选状态 |
| 取消/恢复 | 更多菜单选择 | 显示活动名称及影响后确认；提交期间防重复，失败保持原状态 |
| 无权限 | 非管理员进入或会话失效 | 延续非管理员不发管理请求的规则；服务端逐接口校验仍保留；会话失效给出重新登录入口 |
| 筛选 | 输入搜索词、切换状态、应用高级筛选 | 条件取交集；服务端查询时防抖并防止过期响应，分页回到第一页 |
| 刷新 | 点击刷新 | 保留当前查询条件，显示刷新中反馈，结果和数量同步 |

表单沿用封面上传与字段校验，编辑时正确处理北京时间回填、可空字段清除和未改变的封面。新建/编辑弹层内容超长时可滚动，底部提交按钮可操作。

## 7. 文件与实施顺序

| 文件 | 计划改动 |
| --- | --- |
| `app/src/screens/AdminScreen.tsx` | 公共标题、导航；活动面板结构与筛选；编辑、详情和更多操作 |
| `app/src/screens/admin.css` | 管理端作用域的配色、导航、工具栏、日期牌、卡片和响应式 |
| 可新增 `app/src/components/admin/` | 随复杂度拆分 ActivityDateBadge、AdminActivityCard、ActivityEditor、ActivityFilters；不为简单结构过度拆分 |
| `app/src/components/icons.tsx` | 复用或补齐搜索、盾牌、筛选、编辑、刷新、更多等线性图标 |
| `app/src/api/client.ts` | 完整查询版本补管理列表参数和分页返回类型；复用现有创建/更新接口 |
| `server/src/timemap.ts` | 完整查询版本补管理员关键字、状态、地点、日期范围、总数与分页，保留权限校验 |
| `docs/test/` | 实施后记录目标尺寸截图、功能验证与未覆盖状态 |

建议分三步实施（按一名熟悉项目的开发者估算，不含新增草稿业务）：

1. 公共头部与导航、活动卡片、日期牌、状态映射和响应式：约 0.5–1 人日。
2. 搜索/筛选、编辑表单、详情与更多菜单、服务端完整查询：约 1–2 人日。
3. 多尺寸视觉对照、权限与失败态回归、文档和证据整理：约 0.5–1 人日。

整体约 2–4 人日。若只做视觉与已加载数据的本地筛选，可先用约 1–2 人日交付首版，但必须清楚标注已加载数量与搜索范围。

## 8. 完成标准与当前边界

- 四个目标视口检查长中文标题、英文标题、跨年日期、长来源和各状态，无横向溢出或按钮遮挡。
- 所有可见操作可用，编辑真实保存，取消/恢复结果以服务端为准；无匹配与无数据分别呈现。
- 检查六个管理面板，避免共享 `.adm__card` 等样式使举报处理、审核表单和操作记录布局退化。活动专有样式使用独立作用域。
- 检查键盘、焦点、读屏标签、触控范围、对比度及减少动画偏好。
- 对查询和保存行为做必要验证，运行前端构建与 lint；新增后端查询时补充有意义的过滤、分页和权限验证。
- 实施后保存浏览器截图和真实状态验证记录，再作视觉完成判断；本方案没有运行页面，未声称通过渲染验收。
