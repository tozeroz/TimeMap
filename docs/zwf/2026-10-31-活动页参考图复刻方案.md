# 活动页参考图复刻方案

日期：2026-10-31。参考：《校园活动精选.png》。范围：活动列表 UI 与交互方案，尚未修改页面或后端。

## 结论

以现有活动列表为基础，重做标题、三行筛选和左海报右信息的列表即可接近参考图，不需要更换框架。难度低于地图页。现有海报、时间、地点、来源、展示状态、收藏字段已经具备；真正需要确定的是“全部”的口径、自然日/自然周筛选，以及单地点与多地点活动的范围。

## 现有能力

- `ActivitiesScreen.tsx`：时间、状态、地点筛选，刷新，加载/失败/空状态，收藏及进入详情。
- `ApiActivity`：`coverImageId`、`title`、`startsAt`、`endsAt`、`source`、`effectiveStatus`、`favoritedByMe` 等字段已提供。
- 管理页已可上传活动封面，详情页已经通过 `mediaUrl(coverImageId)` 显示海报，列表尚未展示它。
- 活动当前关联一个 `place`，包含地点 id、名称、经纬度和启用状态。
- 地图已支持 `#/map?placeId=...` 定位地点；活动详情当前提供的是进入地点详情，列表需要另加直接地图入口。

## 视觉与布局方案

| 部分 | 实施方式 | 难度 |
| --- | --- | --- |
| 标题与副标题 | 改为“校园活动”“发现校园里的新鲜事”，右侧刷新按钮保留 | 低 |
| 时间行 | 全部/今天/本周，选中为深橙文字和短下划线，保持点击区域 | 低 |
| 状态行 | 状态单选，选中浅橙胶囊；窄屏可横向滚动或用真实展开按钮，避免将右箭头画成无效装饰 | 低 |
| 地点行 | 图钉、全部地点/已选地点、右箭头，复用地点筛选面板和清除逻辑 | 低 |
| 列表标题 | “近期活动”配已加载数量；查看历史或全部时相应改为“活动列表”等准确标题 | 低 |
| 活动行 | 左侧海报，右侧标题、状态、时间、地点、来源；星标独立放在右上，底部为地图查看 | 中低 |
| 海报 | 首选约 4:5 竖图，宽度占行的约 34%–38%；统一圆角，图片失败或缺失用中性占位，不编造正式海报 | 中低 |
| 信息密度 | 中文标题允许 2–3 行，来源可换行；320px 窄屏需缩短日期格式，避免星标挤占正文 | 中低 |
| 底部导航 | 保持现有路由；如按图统一为地图/广场/活动/我的，需要检查全部主页面 | 低 |

不把日期、状态、海报中的示例活动固定写进正式页面。截图中的三张精美海报属于内容素材，UI 布局不能替代海报制作；已有活动有封面就直接展示，没有封面时后续可通过管理员上传。

列表项不能把收藏、地图查看按钮嵌套在另一个按钮中。建议使用 `article` 或列表行作容器，海报/标题作为详情入口，星标和地图查看作为独立按钮，保证点击收藏不会误入详情。

## 需要修正或明确的行为

### 1. 状态“全部”

当前 UI 的首项是“默认”，只展示即将开始与进行中的活动。接口已支持 `status=all`。复刻参考图时，显示“全部”就应真实传入 `all`，包含已结束和已取消，不能只替换标签。

这会改变首次进入的默认内容，需要在实现中明确采用参考图的全部口径。数据多时应考虑排序；当前后端 `all` 按开始时间倒序，而不是固定将截图中的进行中、即将开始、已结束排成三行。

### 2. 今天/本周

当前后端实际查询为 `starts_at < now() + 1 day` 和 `starts_at < now() + 7 day`，不是自然日与自然周，也缺少与下界共同构成的窗口。因此配合 `status=all` 时，旧历史活动也可能通过时间条件。

建议按校园业务统一为北京时间：今天为自然日，本周为周一到下周一；筛选与该时间范围有交集的活动。活动状态继续由服务端 `effectiveStatus` 提供，不能由前端按截图固定颜色和文案。

无结束时间的活动需明确定义为按开始时间落入范围，还是按现有业务规则持续进行，不能只在界面上猜测。列表的日期显示也应与筛选采用一致时区。

### 3. 地图查看与多个地点

首版建议支持现有单地点模型：有效坐标时跳转地图并定位 `place.id`；地点无坐标或停用时禁用地图入口并说明原因，仍允许查看活动详情。

参考图第一条“校园内·多个地点”不能只改显示文字。真正支持需要活动与地点的多对多关系、管理员多地点录入、地点筛选匹配规则，以及地图展示多个点并调整视野。该部分应作为独立扩展，首轮不为复刻文字引入假数据。

### 4. 数量与列表状态

现有接口返回有限列表，没有独立总数字段。若显示 `items.length`，应明确是已加载数量；需要“符合条件的总项数”时补充服务端总数/分页。筛选变化后应防止较早请求覆盖较新结果，刷新/收藏期间提供防重复反馈。

收藏状态继续以接口返回值为准；未登录走登录引导，失败不把星标改成假成功。海报失败、地点候选读取失败和活动列表失败分别处理；地点候选读取失败不能冒充“没有可选地点”。

多地点扩展还涉及数据库迁移、管理页和地图视野接口，另行估算。

## 实施顺序与工作量

以一名熟悉项目的开发者估算：

1. 标题、筛选、左海报右信息、星标和地图入口：约 1–2 人日。
2. 补齐时间筛选、状态全部口径、错误反馈与多尺寸回归：整体约 2–3 人日。
3. 如需真正多地点活动，额外约 2–4 人日；海报设计与素材准备另算。

建议第一轮采用现有单地点数据结构，先实现可操作的参考图布局和正确筛选。验收覆盖：长标题、无海报、海报失败、全部状态、跨天/跨周活动、未登录收藏、地点缺坐标、快速切换筛选，以及 320px 手机到桌面居中布局。

本轮仅检查本地代码并记录方案，未调用活动写入接口、修改页面或部署线上。
