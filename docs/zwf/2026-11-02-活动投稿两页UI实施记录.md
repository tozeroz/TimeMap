# 活动投稿两页 UI 实施记录

日期：2026-11-02。范围：按两张参考图实现用户端界面，保留既有主页功能；未实施数据库、后端或管理员审核页面。

## 已实现

- 活动页加号进入 `#/activity-submit`；表单不显示主导航，提供返回和「我的提交」。
- 米白背景、深蓝文字、橙色提示、三组编号字段、左右列布局、简介计数、封面选择与预览、底部提交按钮。
- 新表单为空；三个必填字段、60/300 Unicode 码点计数、时间先后、HTTP/HTTPS 链接校验。所有时间按北京时间解释，转换为带时区 ISO。
- 权威地点查询、加载/失败/空态、失效地点提示；上传进度、失败重试和移除。封面使用私有用途，不退回公开 activity 上传。
- 未提交内容按账号及投稿保存在 sessionStorage；主动离开确认、刷新提示、失败保留；普通用户登录成功返回表单。
- 个人主页增加三标签、左右/Home/End 键切换、四状态筛选、三种状态条目、空态/加载/错误/分页/刷新。
- `#/activity-submission?id=…` 显示完整内容与审核历史；未通过可修改重提；公开详情仅在接口明确提供公开状态和活动 ID 时开放。
- 沿用已有个人资料、发布/收藏、活动收藏、滚动位置与底部导航。图片失效使用占位；私有封面用带凭据 fetch 获取 blob，不将 token 放入 URL。

主要文件：`app/src/screens/ActivitySubmitScreen.tsx`、`activitysubmit.css`、`MyActivitySubmissions.tsx`、`activitysubmissions.css`；衔接 `MeScreen.tsx`、`me.css`、`App.tsx`、`LoginScreen.tsx`、`api/client.ts`。

## 队友需要接通的契约

以下为前端采用的拟定契约，**不是已上线接口**。接口未实现时会显示错误，不会生成本地投稿或假成功。

| 接口 | 请求／响应 |
| --- | --- |
| `POST /api/activity-submissions` | 活动字段与 clientRequestId → ActivitySubmission，须有 id 和 pending 状态 |
| `GET /api/me/activity-submissions?status=&cursor=&limit=20` | `{ items: ActivitySubmission[], nextCursor?: string \| null }`，status 省略表示全部 |
| `GET /api/me/activity-submissions/:id` | 当前完整 ActivitySubmission |
| `POST /api/me/activity-submissions/:id/resubmit` | 活动字段、clientRequestId、expectedRevision → 当前 ActivitySubmission |
| `POST /api/media` | multipart，新增 purpose=`activity-submission`，沿用 uploadRequestId 与 file；必须由服务端实现私有用途 |

类型见 `api/client.ts` 的 ActivitySubmissionFields / ActivitySubmission。状态为 pending/approved/rejected；publicationStatus 为 public/cancelled/unavailable，缺省按不可确认公开处理。审核历史字段为 revision/decision/reason/reviewedAt。地点名字段为 placeName。

媒体尚未扩展该用途，当前后端预计拒绝上传；不会转用公开上传。前端暂定接收 10 MB 内 JPEG/PNG/WebP，需与后端最终限制统一。主办方、来源和类型的长度限制等待后端契约明确。重试相同表单沿用同一请求标识，但服务端仍必须实施幂等、所有权与版本检查。管理员及短信登录服务未做真实联调。生产发布、后端审核及三角色端到端流程均未完成。
