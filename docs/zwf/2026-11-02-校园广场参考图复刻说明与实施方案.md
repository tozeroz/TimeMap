# 校园广场参考图复刻说明与实施方案

日期：2026-11-02  
对应路由：`#/campus`  
参考图：`E:/code/BJTUTimeMap/时光坐标校园广场界面.png`

本文是基于参考图与当前代码的复刻方案。本次只编写文档，尚未修改校园广场 UI，也未部署线上。

## 1. 复刻目标

保留校园广场的浏览、排序、筛选、点赞与发布能力，将视觉调整为参考图中的米白背景、深蓝文字、橙色选中态和双列内容卡片。

页面主要层级：

1. 顶部「校园广场」标题、学校选择入口和消息按钮。
2. 「热门 / 最新」排序与右侧地点筛选。
3. 两列错落卡片：照片、主体贴纸、纯文字内容。
4. 右下角橙色发布按钮。
5. 底部地图、广场、活动、我的导航，广场选中为橙色。

参考图里的照片、头像、昵称、正文和点赞数仅作为排版参考。最终使用实际接口内容，数量和卡片顺序由数据决定。

## 3. 建议视觉参数

以下为适配手机的初始 CSS 参数，需要在实际渲染后微调，不直接使用参考图的原始像素。

| 项目 | 建议 |
| --- | --- |
| 页面背景 / 卡片 | `--c-bg` 米白 / `--c-surface` 白色 |
| 正文 / 辅助信息 | 沿用 `--c-text`、`--c-text-2` |
| 选中与装饰 | 品牌橙 `--c-brand`；小字操作与白字按钮沿用可读性更高的 `--c-primary` |
| 标题 | 24px，较粗；学校名称 14px |
| 内容区左右边距 | 12px 起；页头 20px |
| 两列间隔 / 卡片竖向间隔 | 8px / 8px |
| 卡片圆角 | 12px；图片位于卡片上部，顶部圆角随容器裁剪 |
| 正文预览 | 14–15px，最多 2–3 行，全文在详情页阅读 |
| 地点 / 作者 | 12–13px；头像 24px，圆形 |
| 图片 | 按真实宽高比预留空间，限制极端比例；避免所有图片强制裁成竖图 |
| 交互区域 | 点赞、消息、筛选等触摸区域至少 44×44px，图标可小于点击区域 |
| 发布按钮 | 约 52px，避开底栏、系统安全区与卡片底部内容 |

保留已有系统字体，不全站引入手写字体。纯文字卡片如果采用手写风格，先做局部样式与系统回退；精确手写字体属于可选素材工作，不阻塞主要复刻。

## 4. 三种卡片如何实现

### 照片卡片

结构建议为「首图 → 正文预览 → 地点 → 作者与点赞」。图片有可靠尺寸时提前计算比例，减少加载后的布局跳动。多图帖子先显示首图，是否显示数量角标可在实现时统一约定。

参考图中的卡片标题可直接使用现有 `body` 的正文预览，不为视觉复刻强行增加数据库标题字段。没有正文的图片帖不补造标题。

点击图片或正文进入帖子详情；作者按钮进入用户主页；点赞独立操作。使用可聚焦的真实链接/按钮组织点击区域，避免把按钮嵌在另一个按钮内，也避免整张卡片只能用鼠标点击。

### 主体贴纸卡片

只在接口 `imageMode === 'sticker'` 时显示「主体贴纸」角标。`ApiPost` 已包含该字段，但 `toFeedPost()` 尚未传递到 `FeedPost`，需要同时调整类型与转换。

必须先核实帖子媒体与地图媒体的含义：`images` 是帖子配图，`mapMediaId` 是地图展示媒体。不能看到 `mapMediaId` 就直接替换广场首图；应确认贴纸成品的实际保存位置。需要时为透明主体设置浅鼠尾草绿底和 `object-fit: contain`，照片继续采用照片展示策略。

已有贴纸素材可以直接展示。把普通照片自动抠成猫咪贴纸、加白边和涂鸦属于图片编辑/生成能力，不是 CSS 卡片样式的一部分，不应在浏览列表时自动触发生成请求。

### 纯文字卡片

使用真实正文在浅杏色区域内排版，CSS/SVG 可以提供少量纸纹、线条和叶片装饰。正文保留为可访问文本，不用截图替代文字。

长正文截断并通过详情页阅读；短文字适当留白。预览区设置合理的最小/最大高度，避免一句话撑成大块空白或长文无限拉高。缺少地点时不补造地点。

## 5. 数据与交互注意事项

### 学校与父地标

北京交通大学作为地图父地标，与学校/校区选择是相关但不同的数据语义。不能通过帖子地点名称直接推导学校归属。

第一阶段可以将页面定位为当前学校的校园广场，并根据有来源的学校配置展示校名；如果仍使用全局帖子接口，就需要如实说明当前内容范围，不能把改校名包装成已经完成学校筛选。

学校切换只有在用户选择状态、帖子归属字段和服务端查询条件都接通后才算完成。当前 `listPosts({ sort, placeIds })` 没有传学校筛选；已有学校/校区面板不等于帖子已按学校隔离。暂缺权威上下文时使用中性副标题。

地点筛选候选应按显式层级区分父地标与具体地点。若保留父地标筛选，需要后端明确支持后代地点范围；当前 `placeIds` 精确查询不能被当成自动包含所有子地点。第一阶段建议保留具体地点筛选，父地标聚合单独实施。

### 图片和头像

- `toFeedPost()` 目前只把图片转成 URL，未保留首图宽高；需要传递比例或媒体尺寸。
- 当前头像由 `avatarFor(author)` 生成，不是接口返回的用户真实头像。视觉占位可继续使用现有方案；如果需要参考图中的真实头像效果，必须由接口提供用户头像资料，不能随机使用第三方人像。
- 图片失败时保留正文、地点和互动区域，给出中性的图片不可用占位，不能把整条帖子隐藏。

### 排序、点赞与列表状态

- 复用热门/最新服务端排序；快速切换排序或地点时加入请求版本控制，防止旧响应覆盖当前条件。
- 点赞沿用真实接口返回的计数和状态，增加单帖请求锁、失败提示；未登录继续走现有登录入口。
- 保留离线快照说明、加载、失败重试、筛选为空等状态。热门无结果时不能直接宣称整个校园没有帖子，提供切换最新的入口。
- 当前列表有服务端条数限制，页面却显示「已加载全部」。需先核实当前接口返回是否有 `total`、`hasMore` 或游标；没有可靠依据时改为「已加载 N 条」，不能承诺已取全。完整分页可作为独立接口改造。
- 多列 CSS 不保证按排序从左到右交错阅读。建议按接口顺序分成两列，优先保持视觉顺序可理解；若采用按高度分配的瀑布流，应同时验证键盘和辅助技术的阅读顺序。

## 7. 实施顺序与难度

| 阶段 | 内容 | 估计工作量 |
| --- | --- | --- |
| 第一阶段 | 页头、工具栏、照片卡片、纯文字卡片、发布与底栏选中态；沿用现有接口 | 1–2 个开发日 |
| 第二阶段 | 贴纸模式与尺寸传递、图片失败、长文、窄屏、键盘交互、排序和点赞竞态、公共列表回归 | 约 1 个开发日 |
| 可选后续 | 真正的学校内容隔离、真实头像、全量分页、父地标聚合 | 需核实接口与数据后单独估算 |

前两阶段合计约 2–3 个开发日，属于中等难度。主要风险是共享卡片和数据字段的适配。参考图照片、贴纸和手写效果的素材质量会影响视觉接近程度；只改 CSS 无法改变实际帖子内容。

## 8. 验收建议

- 在 320px、390px、430px 手机宽度及桌面居中容器检查两列、长地名和长昵称，无横向溢出。
- 照片、透明贴纸、纯文字、有图无正文、图片失败均能正确展示。
- 切换排序与地点后，列表与当前选中条件一致；从地点详情「查看全部」进入时保留筛选。
- 点赞不触发帖子详情；作者入口不触发点赞；快速点击不产生重复请求。
- 检查键盘焦点、按钮名称、选中态、文字对比度及安全区；悬浮按钮不能挡住用户无法滚动露出的内容。
- 验证加载、错误重试、离线快照、热门空窗口、筛选无结果和未登录状态，不插入演示帖子掩盖缺数据。
- 回归活动页、地图页、我的发布、用户主页和帖子列表，确认公共导航和样式没有被误改。
- 构建与 lint 通过后记录实际修改文件、截图及与参考图的有意差异，再考虑部署。
